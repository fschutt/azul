# Hello World [Swift]

In order to use `libazul` from Swift (5.10+ on Linux / macOS, 6+ on Windows), you need 
the native library and the generated API bindings.

## Installation

Download the release bundle, which contains the Swift bindings (`Azul/`), the C 
interop map (`module.modulemap`), and the example script (`hello-world.swift`).

```sh
# macOS
curl -O https://azul.rs/ui/release/$VERSION/libazul.dylib
# Linux
curl -O https://azul.rs/ui/release/$VERSION/libazul.so
# Windows
curl -O https://azul.rs/ui/release/$VERSION/azul.dll
curl -O https://azul.rs/ui/release/$VERSION/azul.dll.lib

curl -LO https://azul.rs/ui/release/$VERSION/azul-swift-$VERSION.tar.gz
tar xzf azul-swift-$VERSION.tar.gz
```

### Building from source

Only needed if you want to track `master` or patch the library locally:

```sh
# git clone https://github.com/fschutt/azul
# cd myfolder/azul
cargo run -p azul-doc --release -- codegen all
cargo build -p azul-dll --release --features build-dll
```

The DLL lands in `target/release/libazul.{so,dylib}` (or `azul.dll`), 
the bindings end up in `target/codegen/swift/` (generated by 
`azul-doc codegen all`).

## Simple "Counter" Example

```swift
import Azul

final class Counter {
    var count = 5
}

func onClick(_ counter: Counter, _ info: CallbackInfo) -> Update {
    counter.count += 1
    return .refreshDom
}

func layout(_ counter: Counter, _ info: LayoutCallbackInfo) -> Dom {
    let label = Dom.pWithText(String(counter.count))
        .withCss("font-size: 32px; margin: 0;")

    let button = Button("Increase counter")
        .withButtonType(.primary)
        .withOnClick(counter, onClick: onClick)

    return Dom.body()
        .withChild(label)
        .withChild(button.dom())
}

let window = WindowCreateOptions(layout)
window.windowState.title = "Hello World"
window.windowState.size.dimensions.width = 400
window.windowState.size.dimensions.height = 300

let app = App(Counter(), AppConfig())
app.run(window)
```

## Binding Internals

Callbacks mutate the model in place, the binding retains the object 
automatically for as long as the framework references it. Callbacks
are plain functions, they take the specific model type (`Counter`) 
directly. The framework handles type-erasure and downcasting behind the scenes. 

Enums use leading-dot syntax (`.primary`, `.refreshDom`) and Swift `String`s 
converts natively.

## Missing values and errors in callbacks

Every optional value of the API is a Swift optional: a parameter takes `nil`, a 
field or a return value is a `T?`, and a failure is a thrown error. A callback 
may `throw`: its error is logged and the callback does nothing, so `try` works 
inside it the way `?` does in Rust.

A folder picker. Before, the downcast was spelled `downcast_` and an error 
inside a callback needed its own `do` / `catch`:

```swift
func onPickFolder(_ model: Model, _ info: CallbackInfo, _ result: RefAny) -> Update {
    guard let picked = FileOpenResult.downcast_(result), let path = picked.path else {
        return .doNothing
    }
    do {
        model.link = try Url.parse(path.inner).toString()
    } catch {
        return .doNothing
    }
    return .refreshDom
}
```

Now:

```swift
func onChooseFolder(_ model: Model, _ info: CallbackInfo) -> Update {
    _ = FileDialog.openDirectory("Choose a folder", defaultPath: nil, data: model, onResult: onPickFolder)
    return .doNothing
}

func onPickFolder(_ model: Model, _ info: CallbackInfo, _ result: RefAny) -> Update {
    guard let path = FileOpenResult.downcast(result)?.path else {
        return .doNothing // not a folder pick, or cancelled
    }
    model.folder = path.inner
    return .refreshDom
}

func onOpenLink(_ model: Model, _ info: CallbackInfo) throws -> Update {
    let url = try Url.parse(model.link) // an error is logged, the callback does nothing
    model.link = url.toString()
    return .refreshDom
}
```

## Build and run

Compile the `Azul` module first, then compile your application against it. 

Note: The module library is named `AzulSwift` to prevent filename 
collisions with `libazul.so/dylib` on case-insensitive filesystems.

Linux:

```sh
# compile
swiftc -emit-library \
       -emit-module \ 
       -module-name Azul \
       -parse-as-library -j8 \
       -I. Azul/*.swift \
       -L. -lazul \
       -o libAzulSwift.so

# link
swiftc -I. hello-world.swift \
       -L. -lAzulSwift -lazul \
       -o hello-world

# run
LD_LIBRARY_PATH=. ./hello-world
```

macOS:

```sh
# compile framework
swiftc -emit-library \
       -emit-module  \
       -module-name Azul \
       -parse-as-library -j8 \
       -I. Azul/*.swift  \
       -L. -lazul \
       -o libAzulSwift.dylib

# link
swiftc -I. hello-world.swift -L. \
       -lAzulSwift -lazul \
       -framework Foundation \
       -framework AppKit \
       -framework OpenGL \
       -framework CoreGraphics \
       -framework CoreText \
       -o hello-world

# run
DYLD_LIBRARY_PATH=. ./hello-world
```

Windows (use the Git Bash, ideally):

```sh
# compile
swiftc -emit-library \
       -emit-module \
       -module-name Azul \
       -parse-as-library -j8 \
       -I. Azul/*.swift azul.dll.lib \
       -o AzulSwift.dll

# link
swiftc -I. hello-world.swift \
           AzulSwift.lib azul.dll.lib \
       -o hello-world.exe

./hello-world.exe
```

You should see the window pictured on the [hello-world landing page](../hello-world.md). 
Click the button: the counter should increment, the layout callback then re-runs, and the new value renders.

1. `app.run(...)` opens a native window and runs the layout callback once with your data model.
2. The returned DOM is styled, laid out, and rendered.
3. The framework then continuously queries whether anything matches the event filter set up in the DOM. 
   On receiving a click event, the framework borrows your data model mutably, runs the click callback, 
   observes the `.refreshDom` return, and re-invokes the layout callback.
4. The framework determines the diff between the previous frame's DOM and the current one, 
   and only re-updates and re-paints the counter, not the entire window.

Congratulations! Once you've got the hello-world example running, you've already mastered 80% of 
the framework. As you might have guessed, more complex UI and styling are only composing more Dom 
objects together and working with the various event filters. 

You can now start reading about the [architecture patterns](../architecture.md) or explore 
what [methods the `Dom` has to offer](../dom.md).
