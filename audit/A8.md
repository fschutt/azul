### A8-01 `dilate_disk` O(ink x pi r^2) per halo
- file: `layout/src/cpurender/raster.rs` `dilate_disk` (base 5841)
- class: quadratic (in r), waste
- evidence: every ink pixel walked every tap of the disk, 4 channels, plus a source copy and a u32 x 4 accumulator.
  Runs for every halo the kept-halo cache does not hold: every label at a settle repaint (the key holds
  `font_size_px`, which a zoom changes; 1,567 labels Tuebingen). Editor radius 1.2 px at scale 6 (9 taps), 2.4 at
  DPI 2 (21-37), 4-8 zoomed in (69-225 taps). The dense "sliding max over every pixel" would be SLOWER at these
  radii (~23 vs 2.7 ops a buffer pixel at r = 1.2). So: sparse scatter, runs of equal pixels merged.
- fix: disk by rows; a run of equal pixels in one source row writes its row span `L + 2 b` once per disk row
  (`grow_run`), u16 accumulator, no source copy, `first` channel parameter. Solid 64 x 16 block r = 2 -> 8: 5,376
  -> 20,736 writes (old 21,504 -> 230,400).
- test: `raster::audit_a8_dilate_tests::{a_disk_grown_by_runs_is_the_disk_grown_by_pixels,
  growing_the_alpha_alone_grows_the_alpha_the_whole_pixels_grow, the_dilation_work_grows_with_the_radius_not_with_
  the_disk_area}`; existing `dilate_disk_tests` (vs the original gather) stay. Pure-python model: 348 random cases
  equal (scratchpad `a8py/dilate_equiv.py`).
- severity: high
- status: fixed 34f151893

### A8-26 a runtime face's bytes are copied once more into the registry (A9 round 2 S4)
- file: `text3/fontreg.rs` `register_font`, `CallbackInfo::register_font`
- class: memory (transient), waste
- evidence: `register_font(&str, &[u8])` copies a new face into the registry's `Arc<[u8]>`; the editor calls
