   failure, but drop it when that work lands).
2. **autofix Vec rule (F17).** `doc/src/autofix/module_map.rs`: ONE `is_vec_family()` (vec,
   vecdestructor, vecdestructortype, vecref, vecrefmut) used by `determine_module`,
   `widget_module_for` and `get_correct_module_with_path`; `*VecSlice` is no longer "structural",
   so a widget slice is placed by the widget rule and every other slice keeps its element-based
   module (the path / keyword steps give the old verdicts for them). RED unit tests
   `a_widget_vec_slice_is_placed_by_the_widget_rule_not_by_its_name`,
   `the_three_vec_rules_agree_and_a_vec_slice_is_not_a_vec`.
3. **Theme helpers (F4, F3).**
   - `CoreCallbackData::create(event, refany, callback: impl Into<CoreCallback>)`
     (core/src/callbacks.rs; `Dom::add_callback` builds through it). The private `hook()` of
     shortcut_recorder, cell_grid, timeline, thumbnail_strip, shells/{navigation_pane,
     command_palette, mobile_shell, settings_layout} are deleted, tile.rs's variant delegates.
   - `widgets::themes::decl` gained the one-property base helpers (`simple`, `display_flex`,
     `flex_direction`, `grow`, `no_shrink`, `position`, `overflow_x_hidden`,
     `overflow_y_hidden`, `nowrap`, `px_width/height/min_width/left/top/bottom`); timeline.rs,
     cell_grid.rs, dialog_kit.rs, shells/mod.rs import them, their private copies are gone.
   - `style_kit`'s builders merged into `decl` - one module, one name per meaning:

     | was (`style_kit::` / `kit::`) | now (`decl::`) |
     |---|---|
     | `bg`, `themed_bg`, `hover_bg`, `active_bg` | `fill`, `themed_fill`, `hover_fill`, `active_fill` (a background paint) |
     | `fill()` (width/height 100%) | `fill_box()` |
     | `border(edges, w, light, dark)` | `themed_border(..)` (`decl::border(w)` stays the colourless one) |
     | `drop_shadow` | `themed_shadow` |
     | `inset_shadow` | `themed_inset_shadow` |
     | `focus_halo` (left slot) | `focus_halo_stacked` |
     | `focus_shadow_ring` (left slot) | `focus_halo_inset_stacked` |
     | `hover_border` | `hover_border_color` |
     | `layers ink padding radius radius_corners font_size weight themed_layers themed_ink Edges ring_slot focus_ring hover_layers active_layers hover_ink face push` | same names |

     `focus_ring` / `hover_border_color` are one `const [_; 8]` each with every dark twin right
     after its light value (kit's put all four lights first); `themed_ink` / `hover_ink` are
     `const`; every shadow helper builds through one private `box_shadow`. Every caller moved:
     flat.rs (79 call sites), flora.rs (378) with their per-fn `use` lines, the theme_blocks /
     titlebar / combobox tests. `style_kit.rs` keeps only the theme marker (`FLAT_CLASS`,
     `FLORA_CLASS`, `marker`, `theme_of_classes`).
4. **One encoder, one decoder (F5, F31).** `azul_core::xml::html::{encode_text,
   encode_attribute}` next to `decode_character_references`: text escapes `& < >`, an attribute
   also `" '` (`&quot;` / `&apos;`); both leave out what XML 1.0 cannot carry (C0 controls but
   tab / LF / CR, U+FFFE, U+FFFF); whatever they write decodes back in every `CharRefMode`.
   RED tests first (core/src/xml_html_test.rs). Callers moved, each naming its context:
   cell_grid `html_escape`, selection.rs inline chain (+ its test `unescape` -> the decoder),
   e2e/builder.rs `escape_xml`, notification.rs `xml_escape`, xml/mod.rs test `escape`,
   dll/src/web/html_render.rs `html_escape` / `html_escape_attr`. Three test expectations that
   pinned `&quot;` inside element TEXT (cell_grid clipboard table, the e2e builder's mount XML,
   the toast XML) and the NUL row of selection's unicode test were restated in RED commits
   first. Decoder: `prepare_string` reads through `decode_character_references(.., Xml)` with
   `&nbsp;` protected (written as `&amp;nbsp;`, which the one pass turns back into `&nbsp;`);
   xml.rs's `decode_entities`, `decode_numeric_entity`, `html_named_entity` and their seven tests
   are gone (restated on the one decoder first, d0f71856d).
   Found on the way and fixed (RED + fix): `ClipboardContent::to_html` wrote the font family
   into `style="..."` unescaped - a `"` in it ended the attribute.
5. **micromail (F26).** layout depends on micromail 0.2 (`default-features = false`,
   `features = ["tls-rustcrypto"]` - the rustls provider layout's `http` already brings; crash-mail
   implies http through telemetry). crash_mail.rs's calls are unchanged in 0.2. This is the GREEN
   of the RED wire tests 9a4af9d55 (`MIME-Version`, dot-stuffing, CRLF, STARTTLS handshake);
   their docs now say what 0.1 did. Cargo.lock: the 0.1.0 package removed, both dependents name
   `micromail`; supply-chain/config.toml: the 0.1.0 exemption removed.
