## The two engine changes (for the reviewers of other packages)

- **XML (bf8123486)**: attribute names from the strict loaders now carry their prefix as written (`xlink:href`,
  `xml:lang`, `epub:type`, `xmlns:x`). I checked the consumers: nothing in the engine looked up a stripped name.
  The azul_core attribute table has no `lang` / `space` entry, SVG files only use `parse_xml_string` to validate,
  and `scan_external_resources` reads HTML names. AzReader matches by local name. Behaviour change: an
  `xlink:href` in an XML DOM document stays `xlink:href` (before, it read as `href`).
- **Rich text (f83a2688c)**: the engine test `normalize_clamps_orphan_indents_and_keeps_one_block` stated the
  clamp, and it was WRONG for the shared model, so I changed it. It is now
  `normalize_keeps_one_block_and_every_list_items_level` (the empty-document part is unchanged). The writers
  already handle kept levels: the HTML writer opens holder items for skipped levels, and the Markdown writer
  puts an item with no shallower item before it at the top level, because CommonMark can only nest under an
  item. AzNotes no longer promotes the children when a parent item becomes a paragraph. They keep their level
  in the session and read back at level 0 from Markdown.
- **Overlap with R3-WIDGETS**: `a_rich_text_editors_list_indent_scales_with_its_text` ("a level-1 item at 14 px
  is indented 26 px, not 50") has the same root cause. Its "Two" is a Bullet(1) after a paragraph, so the
  clamp drew it at level 0. f83a2688c should turn it green. If R3-WIDGETS also edits `normalize` /
  `indent` in doc.rs, keep this version (or the same rule). My edits there are the normalize loop, the
  `indent` bound and the two tests.
