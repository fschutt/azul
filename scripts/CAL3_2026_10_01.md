# CAL3: AzCalendar on the Office scaffold, like Outlook 2010's calendar (2026-10-01 / 02)

Branch `wt/cal3` from `16d19442c`. Nothing was compiled or run here (house rule; no prebuilt
AzCalendar with this code exists). Every Rust file passed `rustfmt --edition 2021` as a parse check;
every azul call was checked against a copy of the generated bindings
(`target/codegen/dll_api_external.rs` / `reexports.rs` of 2026-10-01 03:29) by name and module; the
Python / JS scripts pass `py_compile` / `node --check`.

## What was built

### The window (examples/azul-calendar)

`OfficeShell` (the scaffold AzMail uses) inside a `ShellThemeScope`, `WindowDecorations::NoTitle` +
the app-drawn `Titlebar`:

- **Ribbon** (`chrome.rs`):
  - FILE opens the backstage.
  - HOME: New Appointment, New Meeting (an AzMeet link ticked), Go To Today / Next 7 Days, Arrange
    Day / Work Week / Week / Month / Schedule View (the shown one pressed in), Manage Calendars
    (Open Calendar = Open & Export, Calendars), Share Calendar (a notice: later).
  - VIEW: Current View (Calendar / List), Arrange, Layout (Navigation Pane, To-Do Bar), Look
    (Flat, Flora, Light, Dark).
- **Backstage**: Info (counts, data folder, meeting server, Sync now), Open & Export (.ics import:
  path field + Browse + target calendar or "a new calendar named after the file"; export: path +
  Browse + one calendar or all), Print (an empty state: later), Calendars (rename on Enter,
  recolour, remove - its events move to the default calendar - and add), Options (on
  `ShellSettingsLayout`: the meeting server with Save / Sync now, CAL2's settings sheet moved here;
  theme / mode buttons; To-Do bar and navigation pane), About (keys).
- **Navigation pane** (`ShellNavigationPane`, a 252 px rail, 56 px folded):
  - the header holds the inline `DatePicker` (today ringed, the shown days LIT - a new engine
    feature below; its arrows turn the navigator without moving the view) and "My calendars"
    (a `CheckBox` per calendar, its colour swatch, its name);
  - the module switcher Mail / Calendar / Contacts / Tasks: Mail starts AzMail next to AzCalendar
    (`AZMAIL_BIN`), the other two say they are not built yet.
- **Views** (`views.rs` model, `timegrid.rs` / `views_ui.rs` UI):
  - Day / Work Week / Week: CAL2's week generalised to the view's days, with all its behaviour
    (whole day scrolling, zoom around the pointer, click / drag draft with the popover, now line).
    New: an all-day row, events in their calendar's colour, a selection ring, and "More options"
    in the popover (hands the draft to the editor window).
  - Month: six weeks of cells. A day shows what fits; a full day shows "+N more" (opens that day).
    The day number opens the day; a double click makes an appointment there.
  - Schedule View: the day's hours across, a row per calendar shown.
  - List: the coming 7 days, grouped by day.
  - Every event box is a keyboard stop named "title, time": click selects, double click or Enter
    opens it in the editor.
  - Over the view: a header (Back, Forward, title, Today), the reminder bar, the empty-calendar bar
    (Import...), the notice.
- **To-Do bar** (`ToDoBar`): the next 8 appointments of the coming week (one opens in the editor),
  and tasks (`tasks.rs`: `tasks/default/<uuid>.json`, add / tick).
- **Status bar**: "Items: N", the range, and the meeting links' state as the sync segment (a click
  sends them now).
- **Keys**:
  - Ctrl/Cmd+Alt+1..6 the views;
  - Ctrl/Cmd+N new appointment, Ctrl/Cmd+Shift+Q new meeting, Ctrl/Cmd+T today;
  - Alt+Left/Right back / forward;
  - F6 / Shift+F6 the panes (the shell's);
  - Ctrl/Cmd+S saves in the editor.
- **Reminders**: a 20 s timer finds due reminders (`views::due_reminders`) and shows the first as an
  `InfoBar` (Dismiss); `AZCAL_REMINDER <title>` on stdout.
- **Command line** (`args.rs`):
  - `--screen day|work-week|week|month|schedule|agenda|editor|backstage-<page>`;
  - `--theme flat|flora` (`AppConfig::with_theme`), `--mode light|dark` (`with_mode`);
  - `--sample` (`sample.rs`: a Work calendar and a week of repeating, located, reminded and all-day
    events, written only into an empty calendar);
  - `--date YYYY-MM-DD`, `--data DIR`.
- **Settings** kept in `settings.txt`: view, hidden calendars, To-Do bar, navigation pane folded
  (generic `settings::value / line / flag`).

### The event editor window (`editor_ui.rs`, model `editor.rs`)

- A second window, made by `CallbackInfo::create_window` from any "open" (ribbon, menu, keys, the
  popover's More options, a double click or Enter on an event, the To-Do bar).
- `window_id` `azcalendar-editor`; the main window is `azcalendar`.
- The same scaffold: title row, a ribbon (APPOINTMENT / MEETING: Save & Close, Delete, Delete This
  Occurrence, Add AzMeet Link, Close), the form as the main pane.
- Fields:
  - subject, location, attendees (`Name <a@b>`, commas / semicolons / lines; checked);
  - start date + time, all day, end (time, or end date when all day);
  - repeat: `Segmented` rows Does not repeat / Daily / Weekly / Monthly / Yearly (+ Custom), with a
    second row for Weekly (on its weekday / every weekday) and Monthly (day N / the nth or last
    weekday), Every N, Ends never / after N / on a date;
  - reminder and calendar (`DropDown`s), "Add AzMeet link", notes (`TextArea`).
- Save writes the event and closes the window; the main window rebuilds
  (`Update::RefreshDomAllWindows`) and moves to the event when it is out of view. A new AzMeet link
  is made offline (CAL2's code); the main window's sync timer registers it.
- One editor at a time (the layout callback cannot tell two editor windows apart); a second open
  says so in the main window.

### The model (pure Rust, unit-tested)

- `rrule.rs`: the RRULE subset.
  - FREQ DAILY / WEEKLY / MONTHLY / YEARLY, INTERVAL, COUNT, UNTIL (date or date-time), BYDAY with
    nth / last, BYMONTHDAY ±, BYMONTH, WKST.
  - Days a month lacks are skipped; COUNT counts DTSTART and is applied before EXDATE.
  - Periods before a view are stepped over; there is a 200 000 period cap.
  - Parse / write round trip; unsupported parts are named; `describe()` gives a sentence.
- `ics.rs`: iCalendar import / export.
  - Unfold, and fold at 75 octets (never inside a character); TEXT escaping; quoted parameters;
    DURATION.
  - TZID resolved through the file's own VTIMEZONE (the latest STANDARD / DAYLIGHT onset, made by
    its RRULE); UTC and floating times; VALUE=DATE all-day events.
  - RRULE, EXDATE; RECURRENCE-ID moved / cancelled occurrences; VALARM reminders; ATTENDEE
    mailto; AzMeet links (`X-AZCAL-MEETING`).
  - Notes for what changed (an unsupported rule, an unknown zone, past midnight).
  - The writer uses floating times, CRLF, folded lines.
- `event.rs` version 3: all day + last day, location, notes, attendees, reminder, calendar, repeat,
  except, uid.
  - Every field is left out while empty, so a plain event is still the version 2 file byte for
    byte (CAL2's format and `events/<uuid>.json` layout unchanged).
  - `Event::check`, `starts_between`, `remove`.
- `calendars.rs`:
  - `calendars/<uuid>.json`; the default calendar `calendars/default.json` once changed;
  - eight colours with dark twins;
  - hidden calendars as a setting.
- `views.rs`:
  - days, ranges, titles and steps of the six views;
  - occurrences (repeating and several-day events);
  - month "+N more", the list's days, due reminders.

### Engine: DatePicker lights a range (RED `7af90d031`, GREEN `ff96d1b81`)

The brief asks for the navigator's "visible range highlighted"; the DatePicker could only ring
today and mark the pick.

- `DatePicker.range_start` / `range_end` (`set_range` / `with_range`): each day of the range the
  displayed month has gets a wash (`DatePickerLook::day_in_range`, an accent wash with its dark
  twin) and the class `__azul-native-date-picker-in-range`.
- `restyle_grid` keeps the wash on a pick's repaint (the pick wears the picked face; today's ring
  stays on top).
- `build_grid_with` takes `DayMarks` (today + the lit days) instead of `today`.
- The manifest's "date_picker (inline)" fixture now lights a week, so the theme lints
  (`theme_contrast`, `theme_pairs`, label convention) read the wash in both themes and modes.

### Light / dark, flat / flora

- The chrome is the shells' and widgets' (all in the `theme_contrast` lint).
- The app's own surfaces are `system:` colours or tints with dark twins (the `mode_tests` in lib.rs
  hold every constant to that).
- New guard `every_calendar_colour_reads_with_the_desktops_ink_in_light_and_dark`: on every
  calendar tint in both modes, the main ink is at 4.5:1 or better and the secondary at 3:1 (event
  text, and the "Join meeting" button that sits on a tint). Swatches are at 3:1 against the window.
- The E2E's `contrast` stage reads every painted text of the real app against the rectangles
  painted under it (the display list), in flat / flora x light / dark, for Week, Month, List and the
  backstage, and saves screenshots.

## api.json (never edited by hand; for `azul-doc autofix add`)

Only the DatePicker grew; everything else the app uses already exists in the base's api.json.

- `DatePicker`: new fields `range_start: OptionDatePickerState`, `range_end: OptionDatePickerState`,
  right after `today`.
  - Both are alignment 4, like `today`, and come before `mode`, `theme`, `inline`, so there is no
    padding.
  - Doc: "The first day of a range the grid lights - the days an app shows (a calendar's week, work
    week or month) - with range_end its last: each day of it the displayed month has wears a wash
    under its face's ring. None lights nothing." / "The last day of the lit range."
- `DatePicker` fns (both `DatePickerState` args by value):
  - `set_range(refmut, start: DatePickerState, end: DatePickerState)`: "Light the days from start
    to end, both included, where the displayed month has them: a calendar's date navigator showing
    which days the calendar shows."
  - `with_range(value, start: DatePickerState, end: DatePickerState) -> DatePicker`.
- Rust-only: `DatePickerLook::day_in_range`, `CellFaces::in_range`, `DayMarks`.

AzCalendar calls `DatePicker::with_range(..)`, so it compiles only after the bindings are regenerated
with these.

## What is left

- **The editor window in a headless run**: depends on MAIL2's engine change (child windows laid out
  and pumped, a debug timer per runtime window, routing by `window_id` without the
  wrong-window-consumes-the-request problem of the spmc queue). Until then the E2E reaches the
  editor only on a desktop backend.
- **Storage**: still CAL2's direct, atomic file writes from callbacks; the brief kept "event files as
  they are". Moving events, calendars and tasks onto `azul-storage`'s `Drive` (`LocalDrive`) on a
  `Thread` is the next step toward S3.
- **One editor window at a time**. Several would need the layout callback to know its window
  (`LayoutCallbackInfo` has no window id).
- **Editing a single occurrence**: only "Delete This Occurrence" (an EXDATE) exists; editing one
  occurrence of a series, or the series from one day on, is not built. Imports turn
  RECURRENCE-IDs into exceptions plus separate events.
- **Time zones**: events are wall-clock (floating), as CAL2's. Imported TZID / UTC times are
  converted once, to the reader's zone. A timed event past midnight is cut at 23:59, with a note.
- **Not built**: moving or resizing events by dragging; printing (an empty state says later);
  sharing (a notice).
- **Reminders** show as an info bar, not as an OS notification.
- **The navigator** shows the 1st picked when it is turned to a month the view is not in (the
  DatePicker always has a picked day). The To-Do bar's own calendar does not light the range: the
  `ToDoBar` API has no range.
- **Twins**: the backstage pages and the editor had a text-field and a drop-down wrapper each; they
  are one `crate::text_field` / `crate::drop_down` now (as `crate::picked` / `crate::typed` for the
  callbacks). `week_interactions.py` and `offline_links.py` already share one client.
