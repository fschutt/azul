# MAIL6 report (wave 6, 2026-10-03) - AzMail like Outlook 2010

Branch `wt/mail6` from `25d78e309`. Brief: `scripts/waves/wave6/MAIL6.md`. Progress: `scripts/MAIL6.PROGRESS.md`.
Nothing was compiled (house rules). Every edited Rust file was parse-checked with `rustfmt --check`, every
Python file with `py_compile`. The run was interrupted once by a power loss and resumed from the progress
file (commits up to `61e803731` are the first run's, the rest the resumed run's).

## 1. What was built

AzMail already had the Outlook 2010 frame from MAIL1/MAIL2/MAILVIEW (PimShell with the ribbon File / Home /
Send-Receive / Folder / View and its groups, navigation pane with Favorites, per-account trees with unread
counts and the module buttons, message list with search, "Arrange By: Date" and grouped rows, reading pane
with the pictures info bar, Sent/To and the people footer, To-Do bar, status bar). Wave 6 made it work and
finished it against the app checklist:

- **The window fills** (`13bbb49d1`): every window's body is `height: 100%` (`lib.rs WINDOW_BODY_CSS`); the
  LOOK showed the content stopping at ~490 of 860 px, the module buttons cut off.
- **Close via the event** (`7b777cfcb`, DEDUP_OFFICE A16): the compose window's
  `WindowEventFilter::CloseRequested` handler reads the compose as it is NOW, vetoes with
  `info.prevent_window_close()` and asks "Do you want to save changes?" in the standard `MessageBox` in a
  `Modal` (Save / Don't Save / Cancel). The hand-cleared `close_requested` flag is gone. Not the
  `CloseGuard` widget: at the time its `dirty` was the last build's snapshot; INFRA6 (`33d685fb7`) now judges
  it by the latest DOM, so AzMail could switch to it later.
- **Data root** (`bbe5e3533` / `c9aeb24dc`): the AzMail folder is `<Azlin data root>/mail` (accounts inside
  as before); an older `<user data>/AzMail` folder is moved there once (INFRA6's migration does not know
  AzMail's folder name); `AZMAIL_DATA` still overrides it (scripts, tests).
- **azul-appkit** (`aee6084b5`, DEDUP_EDITORS B10/B11; `a4fb8803f`): `args.rs` is SPEC / ABOUT / SHORTCUTS /
  `Screen::of` on the kit; `start()` builds the kit (`create_kit`, `app_config`, `window_options`, `--shot`
  in `on_window_created`). File > Options is the kit's settings page (theme, mode, data, shortcuts; the View
  tab's own theme/mode buttons are gone), File > About the standard `AboutDialog` in a `Modal`, the view
  toggles (reading pane, To-Do bar, navigation collapsed, plain text, newest first) are remembered in the
  kit's settings.json; Mod+E (never wired) is out of the shortcut table.
- **To-Do bar on the shared task store** (`a90f4016d` / `85fdf8cec` / `df7697b1d`, DEDUP_EDITORS B12):
  `todo.rs` reads `azul_pim`'s task store once at start (before the window), a typed task is a new task file
  `tasks/<list>/<uuid>.json` (id from `Uuid::from_seed(azul_storage::ids::random_seed())`), ticking one off
  completes it (a repeating task rolls on); every write is an appkit file job on a Thread.
- **`__azmail_` prefixes** (`61e803731`): `ids.rs` holds every DOM id / class AzMail names, each a
  `const AzString = AzString::from_const_str("__azmail_...")` defined once (account wizard, compose window,
  the paper and the mail body); the E2E scripts use them.
- **Sanitizer: the mail's classes behind a per-message prefix** (`8ab5e1ed2` / `62eb61a93`, user ruling):
  each class name a selector can name without an escape stays as `m<8 hex of a hash of the mail>_<name>`
  (the same with pictures on or off, `Sanitized::class_prefix`), and every class the sheet's selectors name
  (outside attribute selectors and their quotes; `:not(.x)` included) is renamed to match - so Outlook's
  `p.MsoNormal` and a newsletter's `.button` apply, and a mail can never reach `__azmail_` classes (even
  `class="__azmail_paper"` becomes the mail's own `m...___azmail_paper`). The paper's class is `ids::PAPER`.
- **One encoder** (`1f5b490f1` / `2cd4e4c30`, HYGIENE F5): `html.rs`'s `escape_into` is gone; text and
  attribute values go through `Xml::encode_text` / `Xml::encode_attribute` (needs the two api.json functions
  in section 4). The other two items of the brief were already done: the third character-reference decoder
  went with `Xml::create_from_html` (MAILHTML), `compose.rs`'s `escape_html` with the RichTextDoc serializer.
- **Status bar zoom** (`710335921` / `45cd36ca3` / `00edadf34`): Outlook's zoom at the status bar's right end
  (`StatusBarZoom` over 50..200 %, - / + by ten, the slider over the buttons' range), remembered as the
  settings value `zoom`. A plain-text mail's paper scales its font and line height; an HTML mail gets the
  zoom as an `em` of the pane's font, so what the mail leaves to the paper scales (its own px sizes stay -
  azul has no CSS `zoom`, section 7).
- **A wide mail stays on its paper; the mail's `<body>` is its own element** (`a3fae19d3` / `1cd185655` /
  `5fa5cb752` / `2f111c6bb`, LOOK item 5). Measured first on the prebuilt engine with the debug server's
  `mount` op (500 px pane, the newsletter's 600 px table): the paper as `display: inline-block; min-width:
  100%` with the 12 px margin as the padding of an element INSIDE it is 624 px for the table, 500 px for a
  short mail, and long text wraps at 476 px - Chrome's numbers. So: `.__azmail_paper { display:
  inline-block; min-width: 100%; box-sizing: border-box; colours }`, and the new mail-body element
  `ids::MAIL_BODY` (`__azmail_mail_body`, padding 12 px) IS the mail's `<body>`: its classes, `dir` and
  `style` are on it, the sheet's `body` rules apply to it (`html` / `:root` to the paper), and its `bgcolor`
  / `text` are a rule BEFORE the mail's own rules, which win over it as an author rule beats a presentational
  hint in Chrome (the "black frame around a white table" was the hint, as an inline style on a nested div,
  beating the newsletter's dark-mode `body { background: #000 }`). The reading pane holds the HTML body in an
  `overflow-x: auto` box. Found on the way: `bgcolor="red; position: fixed"` put a declaration on the mail -
  `safe_style_value` now refuses `;`, `{`, `}` (a colour is one value).
- **One date formatter** (`d78f1070a` / `9dcaa3553`, DEDUP_EDITORS B4): `message::rfc3339_utc` writes through
  `azul_storage::time::iso8601` (empty before 1970 and past 9999).
- **E2E** (`scripts/azmail_e2e.py`): a new `--phase sample` (`62cf7cd60`, extended since) walks `--sample`
  with no servers: the window fills, prefixed ids, a To-Do bar task becomes a task-store file, New E-mail
  opens a compose window that fills, closing it edited asks "save changes?", the newsletter keeps the list
  and pane widths and its 600 px table on the paper, the status bar's + zooms to 110 %, and after a restart
  the task and the zoom are there again. `--phase account` is the old wizard / IMAP / SMTP run. Fixed in the
  driver (`7423954a9`, `8181e9e4f`, `c33fd5102`): with `--runner` the app's `AZMAIL_*` markers are in the
  runner's `--log`, not in `azmail.out` (every marker wait timed out); stopping the runner left the headless
  app running (now its own session, killed as a group); a wait for one feature has its own limit, so a
  missing feature fails its check instead of every later one.
- **RED engine test** (`cc7040ae5`, no wave-6 owner): `layout/tests/typing_stays_with_its_field_when_another_page_replaces_it.rs`
  (LOOK item 9, section 7).
