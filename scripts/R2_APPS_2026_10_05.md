## Seen broken (not in my files) - for the coordinator
1. **ENGINE: a callback in a Modal's (transient) window does not rebuild the owner window.**
   - Headless, prebuilt FIX9 build. A button callback inside a `Modal` returns `Update::RefreshDom`
     and changes the app state, but the window that declares the Modal is not regenerated. Its
     tree, and so the Modal (which replays the owner's extracted subtree), stays stale until
     something else rebuilds it (`redraw` op, Escape).
   - Pointer: dll/src/desktop/shell2/common/transient.rs. The popup's layout callback returns the
     parent's extracted subtree, so a RefreshDom inside the popup must also wake the parent
     (`request_regeneration_all_windows`, as the mailbox writers do).
   - Not checked: whether a desktop backend shows the same.
   - Blocks azerp_e2e steps 3, 4 and 4b. Every app whose Modal buttons change state should be
     affected (appkit ui.rs, AzClock, AzMail, AzMonitor, AzNotes, AzReader, AzSetup use Modal).
