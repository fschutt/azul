## What was built

1. **CloseGuard asks the app at close time.** New `dirty_check`: a callback the guard calls when
   `CloseRequested` arrives; it answers `CloseGuardDocumentState::{Saved, Unsaved}` and decides instead of
   the `dirty` flag the DOM was built with. An answered close (Save / Don't Save) still passes. `with_dirty`
   stays for static cases. A repr(C) enum, not `bool`: `bool` has no `HostOut` impl (core), and the enum
   reads as the answer it is; a host that does not answer = `Saved` (the window can always close).
   Module docs and `doc/guide/en/system/windowing.md` say when to use which.
2. **TextInput (and every) placeholder in its own ink - fixed in the cascade.** Root cause in
   `core/src/prop_cache.rs` `get_property_slow`: the `::placeholder` tier admitted every inline declaration
   whose non-pseudo conditions held, so a declaration conditioned only on the mode or the app theme matched
   the pseudo-ELEMENT's tier. A widget that follows the app theme has ALL its declarations in
   `@theme(flat)` / `@theme(flora)` blocks, so its resting ink (declared after the prompt grey) won by source
   order: every app-themed TextInput / TextArea prompt painted in the full ink. Now the placeholder tier
   admits only declarations naming `::placeholder` (the rule the tier's own comment states); the host's
   declarations reach the prompt through the Normal tier. The other tiers keep their loose match (the
   widgets' "states appended last" convention relies on it). flat's `FIELD_PLACEHOLDER_DARK` doc updated.
3. **The flat backstage page in the dark mode.** `Backstage`'s flat look painted the palette's
   `content_bg` (Office white) with no dark half; the root, right side and pane now take `flat::DARK_PG` at
   night (one `page_bg` pair through `decl::themed_fill`; the rule flat's chrome states give a page-neutral
   surface). Flora's look already had its pair.
4. **A DatePicker's calendar is never wider than its pane.** The panel (`CONTAINER_STYLE`, both looks build
   on it) gets `box-sizing: border-box; max-width: 100%`: it still hugs its 32 px columns where there is
   room; in a narrower pane it takes the pane's width and the columns (32 px flex bases that shrink) give
   way. The month grid shares the panel.
5. **ToDoBar week start.** `ToDoBar.week_start` (`DatePickerWeekStart`, default Sunday like the
   DatePicker), `set_week_start` / `with_week_start`, passed to its calendar.
6. **Zoom slider + check box colour.**
   - The slider looks (flat / flora) appended their dark rail fill and their thumb paint after a
     `track_style` / `thumb_style` the CALLER set - against the field docs (`Some` is an answer). The status
     bar injects a transparent hit area over its own rail, so the zoom slider became a black (flora) or grey
     (flat) box at night. The looks now paint only the slider's own parts (a guard each, inside the two
     existing functions of the shared theme files; nothing reordered).
   - `system:` colours travel as a reserved transparent token; the CSS printers wrote its hex. New
     crate-only `ColorU::to_css_value` (the `system:<name>` keyword for a token, else `to_hash`); the
     printers of every bare-`ColorU` property (color, border colours, caret-color, selection colours,
     scrollbar-color, box-shadow, flood(), column-rule-color) use it; all their parsers read the keyword
     back. `to_hash` (api.json) is unchanged.

   - F20 MessageList -> SummaryList: done as a mechanical TYPE / module / class rename in one script,
