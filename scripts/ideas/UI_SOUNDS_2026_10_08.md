# UI sounds: system sound APIs first, CC0 samples as the fallback (2026-10-08)

User request: *"can you also research good CC0 UI sounds online? like clicks and so on. Or ideally
system sound APIs"*.

This is research only. No code was changed. Every API fact below was checked against the linked
source: vendor docs, SDK headers or upstream source code. The pack numbers (file counts, durations,
peaks, encoded sizes) were measured on copies downloaded to `/tmp`. No audio was added to the repo.

---

## 0. Summary

**Recommendation: use the system APIs first and the bundled CC0 samples second. Hand the bundled
samples to each OS's *system-sound channel*, not to azul's `AudioSink`.**

- Every OS has two things:
  1. A small set of **alert and event sounds the user picks**: the macOS alert sound, the Windows
     sound scheme, the freedesktop sound theme, Android's key-click effects.
  2. A **system-sound channel** that plays short files supplied by the app. It plays them under the
     user's sound-effects device, volume and on/off switches. The channels are macOS/iOS System Sound
     Services, Windows `PlaySound(SND_SYSTEM)`, libcanberra with `media.role=event`, and Android
     `playSoundEffect` / `USAGE_ASSISTANCE_SONIFICATION`.
- No OS ships sounds for most UI meanings: toggle, menu open, send, success and so on. Those need
  samples. Playing the samples *through the OS channel* still honours the OS settings for free, and
  the app never holds an audio device open.
- Why azul's own stream is the wrong default:
  - A 2026 macOS measurement compared NSSound (an app-owned stream) with System Sound Services:
    - `play()` blocked for 50–84 ms with NSSound, 0.3 ms with System Sound Services.
    - After the device had been idle, output started 50–870 ms after the call with NSSound, 16–18 ms
      with System Sound Services.
    - With NSSound the app owned the audio IO; with System Sound Services `systemsoundserverd` owned
      it. [M-PR]
  - On iOS, azul's AVAudioEngine sink runs under the default `soloAmbient` session. That category
    "will interrupt any other audio sessions which are also nonmixable", so a click would stop the
    user's music. [A-solo] While a media session is active, `media_keys/apple.rs` sets `.playback`
    instead, and that category ignores the Silent switch, which is just as wrong for UI sounds.
    Sounds played with System Sound Services "are not subject to configuration using your audio
    session". [A-MPG]
- **Default: widget sounds off** (`WidgetSounds::Native`). Sounds play only where the platform's own
  toolkit makes them: Android when "Touch sounds" is on, and GTK-style desktops when
  `input-feedback-sounds=true` (GNOME's default is `false`).
  - Microsoft says: "Consider not assigning sounds to frequently occurring events by default."
    [W-UX]
  - Apple, Windows and iOS buttons do not click.
- **Three best CC0 packs:**
  1. Kenney *Interface Sounds* (100 sounds)
  2. Kenney *UI Audio* (51 sounds)
  3. Robin Lamb *UI Sound Effects* (12 sounds, built from CC0 sample libraries)

  Gaps (camera shutter, whoosh, crumpling paper) are covered by single CC0 sounds from freesound
  (section 3).
- **Bundled format: IMA-ADPCM mono WAV.**
  - Measured on 16 trimmed sounds: **74.5 KB at 48 kHz**, 43.5 KB at 24 kHz.
  - Opus would be 12.2 KB, but azul only decodes Opus on Apple.
  - Ogg Vorbis spends about 4.2 KB of setup header per file.

### 2.2 Windows

**`PlaySoundW(psz, hmod, flags)`** (winmm.dll) [W-PS]. The flags that matter:

| Flag | Doc text | Use |
|---|---|---|
| `SND_ALIAS` | "a system-event alias in the registry or the WIN.INI file" | System events |
| `SND_ALIAS_ID` | Predefined IDs: `SND_ALIAS_SYSTEMASTERISK`, `…DEFAULT`, `…EXCLAMATION`, `…EXIT`, `…HAND`, `…QUESTION`, `…START`, `…WELCOME` | — |
| `SND_APPLICATION` | "an application-specific alias in the registry", combined with `SND_ALIAS` | App-registered events |
| `SND_ASYNC` | Return immediately | Always |
| `SND_MEMORY` | "points to a sound loaded in memory"; with `SND_ASYNC` the buffer "must remain valid until the sound has completed playing" | Bundled samples; `'static` bytes satisfy this |
| `SND_NODEFAULT` | "If the sound cannot be found, PlaySound returns silently without playing the default sound" | Always |
| `SND_SYSTEM` | "assigned to the audio session for system notification sounds … puts the sound under the control of that volume slider" | Always |
| `SND_SENTRY` | Triggers SoundSentry, the accessibility visual cue, "If the user did not enable SoundSentry, the visual cue is not displayed" | Event class |
| `SND_NOSTOP` | Without this flag PlaySound "attempts to stop any sound that is currently playing in the same process" | One UI sound at a time per process; fine for UI |

**`MessageBeep(uType)`** (user32) [W-MB]:

- `MB_OK` plays "Default Beep".
- `MB_ICONINFORMATION`/`ASTERISK` (0x40) plays "Asterisk".
- `MB_ICONWARNING`/`EXCLAMATION` (0x30) plays "Exclamation".
- `MB_ICONERROR`/`HAND`/`STOP` (0x10) plays "Critical Stop".
- `MB_ICONQUESTION` (0x20) plays "Question".
- `0xFFFFFFFF` plays a simple beep.
- It is asynchronous: "After queuing the sound, the MessageBeep function returns control … and plays the sound asynchronously."
- Fallback chain: the default sound, then `Beep`.
- Caveat: on Windows Server 2022 the `SystemSoundsService` task is disabled.

**The registry scheme.**

- Each event's file is the default value of
  `HKCU\AppEvents\Schemes\Apps\<app>\<event>\.Current`, with a `.Default` key next to it.
  - `<app>` is `.Default` for Windows and `Explorer` for File Explorer.
  - Display names live in `HKCU\AppEvents\EventLabels\<event>`.
- Events every Win32 implementation defines: SystemAsterisk, SystemExclamation, SystemExit,
  SystemHand, SystemQuestion, SystemStart. [W-PSsys]
- Modern Windows adds others, for example:
  - `.Default`
  - `Notification.Default`, the toast sound, also `ms-winsoundevent:Notification.Default`
    [W-toast]
  - `Explorer\EmptyRecycleBin`
  - `Explorer\Navigating`, the "Start Navigation" click
- Win11 files in `C:\Windows\Media` include `Focus0-4/Invoke/Show/Hide/MoveNext/MovePrevious/GoBack_48000Hz.raw`.
  [W-media] Their names match WinUI's `ElementSoundKind`.

**What the "No Sounds" scheme does:**

- It sets `HKCU\AppEvents\Schemes` (Default) = `.None`.
- Playback actually follows each event's `.Current` value. Clearing a `.Current` value silences that
  event. Setting only `.None` via the registry still showed "No Sounds (modified)" and kept playing.
  [W-none]
- `SND_ALIAS` + `SND_NODEFAULT` therefore honours the scheme automatically.
- `SND_MEMORY` samples bypass the scheme. Azul must check the gate itself: scheme `.None`, or
  "event sounds off".
- `SPI_GETBEEP` "Determines whether the warning beeper is on" [W-SPI]. That is not the scheme.
- Related a11y switch: `SPI_GETSHOWSOUNDS`/`SM_SHOWSOUNDS` means "the user requires an application
  to present information visually" [W-SPI].

**Registering your own events** (lets users re-map or silence them in the Sound control panel):

1. Write `HKCU\AppEvents\EventLabels\<Event>` = display name.
2. Write `HKCU\AppEvents\Schemes\Apps\<exe-name>` = app display name.
3. Write `HKCU\AppEvents\Schemes\Apps\<exe-name>\<Event>\.Current` (and `.Default`) = WAV path.
4. Play with `SND_ALIAS | SND_APPLICATION`.

Microsoft's UX guide: "Register your program's custom sound events… Don't hardwire the sounds…"
[W-UX] The app key is the .exe name. That rule comes from ReactOS (`GetModuleFileNameW(NULL)`)
[W-ReactOS], not from Microsoft's docs, so test it on real Windows.

**WinUI's vocabulary**, for reference only: XAML-only, not callable from Win32.
`ElementSoundPlayer.Play(ElementSoundKind.{Invoke, Show, Hide, MovePrevious, MoveNext, GoBack, Focus})`.
State `Auto` means "The platform determines whether or not sounds are played"; Focus cycles through 4
variants. [W-WinUI][W-ESPS]

**Microsoft's UX rules** (worth adopting as the design constraints) [W-UX]:

- "When in doubt, don't use sound."
- Sounds should be "short (less than one second)", "600 Hertz [Hz] to 2 kilohertz [kHz]", "soft or
  moderate in volume".
- "Don't repeat a sound more than two times consecutively."
- "sound … should never be the only method of communication."
- "Don't have volume or mute controls in your program."

**Rust:** `windows-sys` `Win32::Media::Audio::PlaySoundW` [rs-WS], or (azul's style) `DynamicLibrary::load("winmm.dll")`.

### 2.3 Linux (freedesktop)

**Specs.** Sound Theme spec and Sound Naming spec, both from 2008 [L-theme][L-naming].

- **Theme location:** `$XDG_DATA_DIRS/sounds/<theme>/<profile>/<name>.{disabled,oga,ogg,wav}`.
- **Lookup order** [L-lookup]:
  1. The current theme, then its parents, then `freedesktop`.
  2. Output profile: the requested one, then `stereo`, then none.
  3. Locale.
  4. Name truncation at the last `-`: `message-new-instant` → `message-new` → `message`.
- **`.disabled`** files stop the lookup.
- **Formats:** "WAV/PCM 8-48kHz, 8/16bits, and OGG/Vorbis I".
- **App-specific names** use `x-<binary>-…`.

**Event ids for UI** (exact spellings from the spec):

| Context | Ids |
|---|---|
| Input feedback | `button-pressed`, `button-released`, `button-toggle-on`, `button-toggle-off`, `menu-click`, `menu-popup`, `menu-popdown`, `menu-replace`, `tooltip-popup`, `tooltip-popdown`, `item-selected`, `expander-toggle-on/off`, `notebook-tab-changed`, `dialog-ok`, `dialog-cancel`, `drag-start`, `drag-accept`, `drag-fail`, `link-pressed/released`, `scroll-{up,down,left,right}[-end]`, `window-{close,minimized,maximized,…}` |
| Notifications | `message-new-instant`, `message-new-email`, `complete-download`, `complete-copy`, `dialog-information`, `dialog-warning`, `dialog-question`, `window-attention-active/inactive`, `device-added/removed`, `alarm-clock-elapsed` |
| Alerts | `dialog-error`, `battery-low`, `network-connectivity-lost`, … |
| Actions | `message-sent-instant/email`, `bell-terminal`, `bell-window-system`, `trash-empty`, `item-deleted`, `file-trash`, `camera-shutter`, `camera-focus`, `screen-capture`, `count-down`, `completion-sucess` *(sic)*, `completion-fail`, `completion-partial`, `audio-volume-change` |

**The `freedesktop` fallback theme (0.8)** ships exactly these files [L-fdlist]:

- alarm-clock-elapsed, audio-channel-\*, audio-test-signal, audio-volume-change
- **bell**, **camera-shutter**, **complete**, device-added/removed
- **dialog-error/information/warning**
- **message-new-instant**, **message**
- network-connectivity-established/lost, phone-\*, power-plug/unplug
- **screen-capture**, service-login/logout, suspend-error
- **trash-empty**, window-attention, window-question

It has **no input-feedback sounds**, so `button-pressed` and similar find nothing unless the theme
has them. KDE's *Ocean* theme has `button-pressed`. Licence of the freedesktop theme: "CC-BY-3.0 and
CC-BY-SA-3.0 and GPL-2 and GPL-2+" [L-fdcopy]. Playing it from the system is fine; bundling it is not
(and not needed).

**libcanberra** (LGPL-2.1+, last release 0.30, 25 Sep 2012 [L-cahome]; GNOME calls it "unmaintained
… for about 10 years" [L-gd]).

- It is still the de-facto API:
  - GNOME's compositor mutter links it: `meta-sound-player.c` calls `ca_context_play_full` with
    `cache-control "permanent"` for an allow-list. [L-mutter]
  - KDE's KF6 KNotifications uses it. [L-knotif]
- **No variadic calls needed:** `ca_context_create`, `ca_proplist_create`/`ca_proplist_sets`,
  `ca_context_play_full(c, id, props, cb, ud)`, `ca_context_cache_full`, `ca_context_cancel`,
  `ca_strerror`.
- **Properties** [L-cah]:
  - `event.id`
  - `event.description`
  - `media.role` ("event")
  - `media.filename`
  - `canberra.cache-control`: `permanent`, "useful for very frequently used sound events such as
    those used for input feedback"; or `volatile`; or `never`.
  - `canberra.xdg-theme.name`
  - `canberra.enable`: "0" makes play fail with `CA_ERROR_DISABLED`.
  - `canberra.volume`: a dB multiplier.
- **Fallback for free:** when `event.id` is not found (or not set), canberra plays
  `media.filename`. [L-castc] KNotifications uses exactly this to pass a fallback file.
- **Format of that fallback file:** canberra's WAV reader accepts **only PCM (0x0001) or
  WAVE_FORMAT_EXTENSIBLE**. [L-cawav] Bundled ADPCM must be written out as PCM16 WAV first.
- **Threading:** each context has a mutex, so calls are serialised and can come from any thread.
  Calls fail with `CA_ERROR_FORKED` after `fork()`. The finish callback may run "from a background
  thread" and must not call back into canberra. [L-cah]
- **Rust:** no maintained crate (crates.io search for "canberra" only finds distance-metric crates).
  dlopen `libcanberra.so.0` with libloading, which is already a Linux dependency.
- **Sample cache:**
  - The pulse backend uploads samples into the server's sample cache, so the next play is just one
    command.
  - PipeWire: "The pulse server implements a sample cache that is otherwise not available in
    PipeWire". [L-pw] It works through `pipewire-pulse`.
  - `media.role=event` puts the stream under PulseAudio's "System Sounds" volume entry.
- **Test from a shell:** `canberra-gtk-play -i button-pressed`.

**Settings.**

- **GNOME** `org.gnome.desktop.sound` [L-gschema]:
  - `event-sounds` (default `true`)
  - `input-feedback-sounds` (default `false`)
  - `theme-name` (default `'freedesktop'`)
  - The Settings alert chooser writes `bell-terminal` and `bell-window-system` symlinks into
    theme `__custom` and switches `theme-name` to it. [L-gcc] So `bell-window-system` resolves to
    the user's chosen alert sound.
  - Plain libcanberra does **not** read these settings. Only libcanberra-gtk binds
    `gtk-enable-event-sounds` → `canberra.enable` and `gtk-sound-theme-name`.
  - The GTK widget sounds came from `canberra-gtk-module`, gated by
    `gtk-enable-input-feedback-sounds`. That is GTK 2/3 only, because GTK 3.94 dropped loadable
    modules. [L-gtk394]
- **KDE:** `kdeglobals` `[Sounds] Theme=` (default `ocean`) and `Enable=` (default true), as read by
  KNotifications. [L-knotif] There is no input-feedback switch. Ocean is **CC-BY-SA-4.0** per its
  SPDX headers [L-ocean], so it is not bundleable.
- **Neither libcanberra nor the event role available:** azul can run the spec lookup itself (a
  directory stat plus the truncation rule; Vorbis decodes through Symphonia) and play through its
  ALSA `AudioSink`. That stream has no event role, no sample cache and no "System Sounds" slider,
  so it is the last resort.

### 2.5 iOS

- **`AudioServicesPlaySystemSound`** is Apple's documented route "To play user-interface sound
  effects (such as button clicks)". [A-MPG]
  - Same restrictions as on macOS: 30 s or shorter, PCM or IMA4, one at a time, no volume control.
  - Not subject to the audio session, so it never interrupts other apps' audio.
  - It honours the Ring/Silent switch. Developers report it also follows the separate "Ringer and
    Alerts" volume. [A-forum2]
- **Built-in ids** (1000–1351, e.g. 1104 keyboard "Tock") are **undocumented**.
  - Apple: "System-supplied alert sounds and system-supplied user-interface sound effects are not
    available to your iOS application." [A-alert]
  - Forum warning: an undocumented id "could disappear without notice". [A-forum]
  - Community lists: [A-tuner].
  - **Do not use.** Bundle the sample and use `AudioServicesCreateSystemSoundID` instead.
- **`UIDevice.current.playInputClick()`** plays the keyboard click "only if the user has enabled
  keyboard clicks … and only if the input view is itself enabled and visible". It also needs
  `UIInputViewAudioFeedback.enableInputClicksWhenVisible == true`. [A-click] So it only applies to
  custom input or keyboard-accessory views.
- **`UIFeedbackGenerator`:** impact, selection, notification (success/warning/error), canvas.
  [A-ufg] Already wired. On iOS the native idiom for success/warning/error is **haptics, not sound**.
- **`AVAudioSession`:** if azul's AVAudioEngine sink is ever used for UI sounds, it needs `.ambient`
  ("audio from other apps mixes with your audio… Silent switch … silence[s] your audio") [A-amb]
  instead of the default `soloAmbient`.

### 2.6 Web (azul's web backend, `dll/src/web/`)

- Browsers have no system-sound API and no way to read the OS sound settings.
- Plan: map `CallbackChange::PlaySound` to a new TLV patch kind (see the table in
  `dll/src/web/EVENT_PATCH_SCHEMA.md`). `loader.js` keeps one `AudioContext` and the decoded
  `AudioBuffer`s. The server serves the bundled samples as PCM16 WAV.
- Autoplay: starting Web Audio "outside the context of handling a user input event is subject to
  autoplay rules" [W3-autoplay]. Clicks are fine; timer-driven notifications before the first user
  gesture may be blocked.
- `navigator.vibrate()` needs sticky user activation and is "not Baseline" (not in Safari).
  [W3-vib]

### 3.4 Processing before bundling (all needed, measured)

1. **Trim the leading silence** at a −50 dB gate. UA switches have 0–124 ms; Independent.nu has up to
   124 ms.
2. **Fade out** over 5 ms.
3. **Downmix to mono.**
4. **Normalise to −6 dBFS peak**, or match the loudness of the platform sounds. The source masters
   reach +0.5…+5.7 dBFS true peak after resampling. Microsoft: "roughly the same volume as the
   typical Windows sound".
5. **Resample** to 48 kHz.
6. **Keep a provenance manifest** (`assets/sounds/SOURCES.md`): URL, quoted licence line and
   SHA-256 of each original. CC0 needs no attribution; Kenney asks for optional credit.

### 3.5 Size budget (measured)

The 16 picks above (Kenney plus Robin Lamb's Ding), trimmed and normalised: 2.83 s of audio in total.

| Encoding | Total |
|---|---|
| Opus 24 kb/s (Ogg, per file) | **12.2 KB** |
| Opus 32 kb/s | 14.7 KB |
| IMA-ADPCM 4-bit, 24 kHz | **43.5 KB** |
| IMA-ADPCM 4-bit, 48 kHz | **74.5 KB** |
| PCM16 24 kHz | 134 KB |
| PCM16 48 kHz | 267 KB |

- The three freesound picks add about 1 s, which is about +25 KB as ADPCM-48k.
- **Vorbis** spends about 4.2 KB of setup header per file (the smallest Kenney `.ogg` is 4,275 B
  for 10 ms). Sixteen separate Vorbis files carry about 68 KB of headers before any audio.

**Recommendation: IMA-ADPCM mono 48 kHz WAV, one file per sound, about 75–100 KB in total.** Use
24–32 kHz if 50 KB matters more than the top octave of the clicks.

- **The decoder is trivial:** about 100 lines, or Symphonia's `adpcm` when `audio-decode` is on.
  It needs no new dependency and adds no `cfg`-dependent code size.
- **Core Audio reads MS-IMA WAV:** checked here with `afconvert`. System Sound Services *documents*
  only linear PCM and IMA4, so the safe route writes PCM16 WAV to the cache directory.
- **Why not Opus:** it saves about 60 KB but needs a decoder on Linux, Windows and Android. Azul
  decodes Opus only through AudioToolbox; Symphonia 0.6 has no Opus decoder
  [rs-sylibopus]. The pure-Rust decoders (`opus-decoder`, `opus-pure`, …) were all first released in
  2026 [rs-opus] and would add more code than the asset saving.
- **Optional:** synthesise Click and Tick procedurally (a 3–20 ms decaying sine or noise burst):
  0 bytes, and CC0 by construction.

## 4. Proposed azul API (design only; nothing implemented)

### 4.1 Vocabulary (semantic, like `HapticPattern`)

```rust
// core/src/sound.rs  (mirrors core/src/haptics.rs)
#[repr(C)]
pub enum SystemSound {
    // input feedback: gated by an OS "input feedback" switch where one exists
    Click, Tick, ToggleOn, ToggleOff, MenuOpen, MenuClose, Expand, Collapse,
    TabChange, Back, DragStart, DropAccept, DropReject,
    // events / actions: gated by the OS "event sounds" switch
    Notification, Success, Info, Question, Warning, Error, Bell,
    Delete, TrashEmpty, Send, CameraShutter, ScreenCapture,
}
impl SystemSound {
    pub const fn class(self) -> SoundClass;                // InputFeedback | Event
    pub const fn freedesktop_id(self) -> Option<&'static str>;
    pub const fn fallback(self) -> Option<SystemSound>;    // Expand→MenuOpen, TrashEmpty→Delete,
                                                           // ScreenCapture→CameraShutter, Question→Info,
                                                           // DropAccept→Click, DropReject→Error
    pub const fn haptic(self) -> Option<HapticPattern>;    // Toggle*/Tick→Selection, Success/Warning/Error→same
}
#[repr(C)] pub struct SoundRequest { pub sound: SystemSound, pub volume: f32 } // volume: bundled route only
#[repr(C)] pub enum WidgetSounds { Native, On, Off }
#[repr(C)] pub struct SoundConfig { pub enabled: bool, pub widget_sounds: WidgetSounds, pub volume: f32 }
//   AppConfig.sounds: SoundConfig { enabled: true, widget_sounds: Native, volume: 1.0 }
```

### 4.2 API surface (the same queue as haptics)

- **`CallbackInfo` methods:**
  - `play_system_sound(SystemSound)` and `play_system_sound_request(SoundRequest)` push
    `CallbackChange::PlaySound { request }`. The variant is appended and deferred, like `PlayHaptic`.
  - `set_sounds_muted(bool)`: a runtime mute at app level.
- **`SoundManager`** (in `LayoutWindow`, next to `haptic_manager`):
  - Adjacent-dedup coalescing.
  - A minimum interval per sound: Tick about 40 ms, everything else about 100 ms.
  - At most 2 identical sounds in a row (Microsoft UX rule).
- **Drain:** at depth 0 in `shell2/common/event.rs`, next to `play_haptic_native`, call
  `play_sound_native(&req, &system_style.audio, &app.sounds)`. The routing and gating decision is a
  **pure function** `route(req, &AudioMetrics, &SoundConfig, Platform) -> Route`, unit-testable on
  every host.
- **`AudioMetrics` extensions:**
  - `ui_sound_effects_enabled`: macOS `com.apple.sound.uiaudio.enabled`.
  - `show_sounds`: Windows `SM_SHOWSOUNDS`; macOS `com.apple.sound.beep.flash`.
  - `sound_theme`: GNOME `theme-name`; KDE `[Sounds] Theme`.
  - Fill macOS, KDE and Android (`SOUND_EFFECTS_ENABLED`).
  - Replace `SPI_GETBEEP` with scheme ≠ `.None`.
- **Escape hatch, not portable:** `play_platform_sound(&str)`. It maps to `NSSound(named:)`, a
  `PlaySound` alias, a freedesktop `event.id` or an Android `FX_*` name.

**B (bundled sample) means, per OS:**

| OS | How a bundled sample is played |
|---|---|
| macOS / iOS | Decode once to PCM16 WAV in `Caches/azul-sounds/<hash>/`, then `AudioServicesCreateSystemSoundID` once (keep the id for the app's lifetime). `IsUISound`=1. |
| Windows | Build a PCM16 RIFF image in memory once, then `PlaySoundW(ptr, NULL, SND_MEMORY\|SND_ASYNC\|SND_SYSTEM\|SND_NODEFAULT)`; add `SND_SENTRY` for the event class. |
| Linux | Write PCM16 WAV to `$XDG_CACHE_HOME/azul/sounds/`, used as canberra's `media.filename` with `media.role=event`. `cache-control` is `permanent` for the input class, `volatile` for events. Theme = GNOME `theme-name` or KDE `Theme`. |
| Android | Through azul's AAudio sink with `AAUDIO_USAGE_ASSISTANCE_SONIFICATION`. |
| Web | Web Audio. |

**Rules:**

- Only when the system channel is missing (Linux without libcanberra; Android below API 28) does a
  bundled sound fall back to `AudioSink`, opened lazily and closed after about 3 s idle.
- **Never** let the app-level mute suppress `CameraShutter` on Android when
  `mustPlayShutterSound()` is true.

### 4.4 Gating (in order)

1. **App switches:** `SoundConfig.enabled` and the runtime mute. Note Microsoft's "Don't have
   volume or mute controls in your program" [W-UX]. So the app mute is for kiosks and tests; the
   default is on and the OS is in charge.
2. **OS switch for the sound's class** (table 2.7). Routes that apply it themselves are not
   double-gated: `IsUISound`, `SND_ALIAS`, `AudioManager.playSoundEffect(int)`.
3. **Widget sounds:** `WidgetSounds` for sounds that widgets emit implicitly. `Native` means:
   - Android: `FX_KEY_CLICK` for clickables (the system "Touch sounds" switch still decides).
   - Linux: input sounds only if `input-feedback-sounds=true`.
   - macOS, Windows, KDE, iOS: silent.
   `On` plays them subject to steps 1–2. `Off` never plays them.
4. **Accessibility:** if `show_sounds` is set, Error and Warning also get a visual cue. Sound is
   never the only cue.

### 4.5 Widgets (opt-in hooks; only the existing default callbacks change)

| Widgets | Sound |
|---|---|
| `button` | Click |
| `check_box` / `switch` / `radio_group` | ToggleOn / ToggleOff |
| `slider` / `stepper` | Tick, on detents |
| `tabs` / `segmented` | TabChange |
| `drop_down` / `menubar` / `popover` | MenuOpen / MenuClose |
| `modal` / `dialog` / `alert` / `info_bar` | Info / Warning / Error, by style |
| `toast` | Notification |
| `tree_view` / `accordion` | Expand / Collapse |
| `camera` | CameraShutter |
| `screencap` | ScreenCapture |

Haptics pair through `SystemSound::haptic()`, but only when the app asks for both.

### 4.6 Headless / E2E

- **Recording:** on `AZ_BACKEND=headless` and in the e2e runner, the drain never calls an OS API.
  `SoundManager` appends to a bounded recording:
  `{sound, class, route ("system:freedesktop:button-pressed" | "bundled:click" | "alert"), suppressed_by (None | "app-muted" | "os:input-feedback-sounds=false" | …), frame}`.
- **`assert_sound` op:** `sound`, `count?`, `played?`, `route?`; plus `assert_no_sound`. It mirrors
  `assert_notification` (`layout/src/e2e/full.rs` ~L6080, recorded in
  `layout/src/managers/notification.rs`).
- **`AZ_SOUNDS` env var:** `AZ_SOUNDS=off` records but never plays, even with a real window (screen
  recordings, CI with a display). `AZ_SOUNDS=log` prints one stderr line per sound. The debug server
  can list the recording.
- **Unit tests** (pure, no device): `route()`, the gating table, coalescing, and the IMA decoder
  against an ffmpeg-made golden file.

### 4.7 Suggested order

1. Core types, `CallbackInfo`, manager, headless recording, `assert_sound`. No OS code yet;
   testable everywhere.
2. macOS: AudioToolbox dlsym, `NSBeep`, bundled assets plus cache writer. Fix macOS
   `AudioMetrics`.
3. Windows: winmm `PlaySoundW`, the scheme check through the existing `registry.rs`.
4. Linux: libcanberra dlopen, GNOME and KDE settings, `AudioSink` last resort.
5. Android (`AudioManager` FX, `MediaActionSound`, AAudio usage) and iOS (System Sound Services,
   haptic idiom).
6. Widget hooks.
7. Web patch kind.

### 4.8 Open questions for you

1. Is the default `WidgetSounds::Native` right? It is silent except on Android and on GTK desktops
   with input-feedback on.
2. Ship about 75 KB of samples always, or behind a cargo feature (`ui-sounds`, default on)?
3. Use the undocumented macOS Finder/Dock sounds for Delete, TrashEmpty, Shutter and Send (native
   feel, exists-check), or always the bundled set?
4. Windows: register app events under `HKCU\AppEvents` on first run, so users can re-map them in
   the Sound control panel? It writes to the registry.
