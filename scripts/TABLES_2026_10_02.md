## 1. Item 1 - DEDUP_WIDGETS_API F23: the 220px prose table (`f120ecc14`)

`prose_cells_wrap_inside_a_220px_table` asserts per cell again: each cell on exactly two baselines, both
cells on the same two, every pen inside its own cell, and the column widths equal to the CSS Tables 3
3.9.3 split `min + (214 - sum(min)) * (max - min) / sum(max - min)` within 1.5px, with every min/max
measured in the same page from one-cell tables (`width: 1px` is floored at the cell's min-content,
`auto` is its max-content). The cells hold two words each: "exactly two lines" then holds for any face
(a column between a cell's min- and max-content puts one word per line) - the five-word prose wrapped
onto two lines at Times and three at DejaVu Serif (Linux CI).

**Engine: already right.** Probe at the base: columns 131.8 / 82.2 (Chrome 131.5 / 82.5, Times; Arial
129.1 / 84.9 in both), one word per line. The test now uses the shared `table_markup` fixture (its own
copies of `laid_out` / `runs` / `node` are gone).

## 2. Item 2 - DEDUP_WIDGETS_API F24: E-INLINE (`e4a6554a5`, `d4dc39299`)

**Root cause, bisected (it is neither the table nor the inline intrinsic sizing):**

| page (the only text in it in brackets) | azul | Chrome |
|---|---|---|
| `width: 1px` table, `<i ib 100/> <i ib 100/> <i ib 100/>` | 306 | 106 |
| the same with `<span>` boxes | 106 | 106 |
| `<span style="font-style: italic">` boxes | 306 | 106 |
| `<i style="font-style: normal">` boxes | 106 | 106 |
| `<i>` boxes + a regular `<p>x</p>` anywhere | 106 | 106 |
| `<i>` boxes + a bold or italic `<p>x</p>` | 306 | 106 |
| `<p><b>bold</b> tail</p>` | "bold" | "bold tail" |
| `<p><span>plain</span> tail</p>` | both | both |

A text run (the spaces, " tail") beside an element of another `font-style` / `font-weight` is dropped -
not shaped, no display-list item, no width, no break opportunity - unless some other text in the
document needs its regular face. `words()` built its boxes from `<i>`, which the UA makes italic. The
cause is in the font chains resolved for the document (`getters::collect_font_stacks_from_styled_dom` /
`resolve_font_chains_fast`) or in the run's chain lookup at shaping (`text3::cache`); the code reads
right in both places and I could not pin the mechanism without a run.

- RED (ignored, OPEN, for the text/font owner): `layout/tests/text_beside_an_italic_or_bold_box_keeps_a_font.rs`
  (a table's minimum is one italic box; the spaces between italic boxes take their width; the text
  after `<b>` paints).
- The two TABLE_A width-cap tests are back on fixed-size boxes (their original intent:
  `words(10, 100)` / `words(10, 50)`); `table_markup::words` builds `<span>` boxes (non-italic). With
  them the prebuilt engine lays both pages out as Chrome does (600 / 300 wide).

## 3. Item 3 - newsletters end to end

Each fault: RED test (Chrome's numbers, RED on the base), then the fix in the engine where it lives.

### 3.1 Anonymous table objects (`c6530d7e4` RED, `b05d55558`, `03ba7769c`)

**mailgun x 3 (80 of the 625 mismatches are "no box in azul"):** the templates center their body with
`<td class="container" style="display: block; width: 600px; margin: 0 auto">` between two empty cells.
The layout's tree is the reconciler's (`cache::reconcile_recursive`), which built no anonymous table
objects (CSS 2.2 17.2.1): the block `td` was a direct child of the row, `fc::analyze_table_row` skipped
it as no cell, and the whole mail body had no box.

- `cache::reconcile_table_children` (new; `TableParent` = table / row group / row): the children a
  parent takes stay; a run of the others goes into an anonymous `table-row` (under a table or row
  group) and, inside a row, each run of non-cells into an anonymous `table-cell`
  (`FormattingContext::TableCell`), a block container whose inline runs sit in anonymous inline
  wrappers. `cache::reconcile_child_under` reconciles one child under a given layout parent.
- `LayoutTreeBuilder` agrees (its anonymous cell was `FormattingContext::Block`, which the grid skips;
  an anonymous row now wraps its non-cells in a cell): `process_anonymous_table_box_children`.
- `fc::layout_cell_for_height` takes a DOM-less (anonymous) cell (it failed the table with
  `InvalidTree`).
- Rule 1 (whitespace): only whitespace whose nearest siblings on both sides are table-internal boxes or
  captions is irrelevant; beside inline content it is a space in the anonymous cell
  (`layout_tree::table_relevant_children`, one rule for both builders). Tests:
  `a_rows_stray_child_sits_in_an_anonymous_cell` (3), `a_space_between_a_tables_inline_children_is_kept`
  (2). WPT out of the expectations: css-tables `whitespace-001`, `anonymous-table-ws-001` (medium).

### 3.2 Atomic inline contributions (`1624bc60d` RED, `8502418d9`)

**cerberus hybrid / responsive (a 680px table 1081px wide), the 01_newsletter CTA (157 vs 205),
leemunroe's button table (121 vs 164):** three faults in the intrinsic sizes an IFC gets from an
inline-block (sizing.rs):

1. `max-width` never reached the stored intrinsic sizes (`calculate_intrinsic_recursive` wrote `width`
   and `min-width` in, not `max-width`); now a length max-width caps both (content-box converted), before
   the min-width floor; not for tables and cells (the column algorithm's).
2. An atomic inline went into the IFC measurement at its CONTENT max-content - no padding, border or
   margin: `atomic_inline_width_contributions` gives margin-box min/max contributions.
3. The min-content scan saw every atomic inline at its max-content: `process_layout_children` records
   the differing min contributions, `calculate_ifc_root_intrinsic_sizes` scans the content once more
   with them.

Test: `an_inline_block_contributes_its_clamped_padded_width` (6).

### 3.3 Cell vertical-align and the last bottom margin (`bd750b08b` RED, `2db332ee0`)

**postmark invoice/receipt (`<h3 style="margin-top: 0">` 8px low), 04_receipt (the item table 8px
low):** a cell is a BFC root; its last child's bottom margin is part of its content (the row height
counted it), but `position_table_cells` aligned block content by the children's border edges. Test:
`a_cells_vertical_align_counts_its_last_childs_bottom_margin` (3).

### 3.4 Inline-blocks in a cell of inline content (`73195eff6` RED, `963ba093c`)

**postmark receipt/welcome: the button's green box centered, its label at the cell's left edge.**
`layout_cell_for_height` laid such a cell out with `layout_ifc` and dropped the positions it reports for
the atomic inlines: the box (hit-testing, `get_node_position`, the debug server, its own content) sat at
the cell's origin while its line painted it in place. Now published (`publish_interior_positions`), and
moved with the line by the vertical-align shift. Test: `an_inline_block_in_a_cell_sits_where_its_line_puts_it` (2).
This also moves every inline-block in a table cell that mail_boxes reported at the cell's origin
(cerberus hybrid's second / third columns).

### 3.5 `<br>` in the intrinsic measurement (`303d81844` RED, `22661a53e`)

**04_receipt: the item column 439 of 554px (Chrome 366):** the intrinsic collection treated `<br>` as an
empty inline, so "item<br/>note" measured as one line. It now emits the hard break the layout emits.
Test: `a_line_break_ends_a_line_in_the_max_content` (3).

### 3.6 Inline-table baseline, caption-side (`5e81932cd` RED, `66af7e730`)

- A first row with no baseline-aligned cell (the HTML default) has its baseline at the bottom content
  edge of its lowest cell (CSS 2.2 17.5.3); it was the row's top and an inline-table hung below its line.
- `caption-side` is read from the caption (inherited; the table's value is the fallback).

Tests: `an_inline_tables_baseline_is_its_first_rows` (2), `a_captions_own_caption_side_places_it` (2).

### 3.7 Spanning cell percentage (`bd6869d05` RED, `0629c73e3`)

`<td colspan="2" style="width: 50%">` in a 400px table: Chrome 100 / 100 / 200, azul three columns of
133.3. `table_width::distribute_spanning_cell` (the one span rule of the layout and the intrinsic sizes)
now hands a spanning cell's percentage to its columns (CSS Tables 3 3.8). Test:
`a_spanning_cells_percentage_is_shared_by_its_columns`.

### 3.8 Right-to-left tables (`aaf51a70c` RED, `5f2ed28c3`)

**cerberus responsive / hybrid: a row reversed with `<td dir="rtl">` (x +-387).** CSS 2.2 17.5: the
table's `direction` orders its columns. `TableLayoutContext::rtl` (from the table's inherited
direction, in `analyze_table_structure`); `position_table_cells` mirrors the columns in the grid's
width and places a cell at the lowest x of its columns; `place_table_grid_boxes` takes the leftmost
column for the grid / a group; the painter (`table_grid_lines`, column backgrounds, collapsed
horizontal strips) reads the lines by position. Test: `a_right_to_left_tables_columns_run_from_the_right` (2).
Not done: the collapsing border model resolves a cell's LEFT border as its start edge (right in ltr;
in rtl the physical sides swap) - no corpus table has visible borders in an rtl table.

### 3.9 Checked and already at Chrome parity (probe, widths/positions; heights differ only by the strut)

colspan + rowspan grid, percent + fixed + auto columns, `table-layout: fixed`, border-collapse widths,
caption top wider than the table, empty cells, `width` / `cellpadding` / `cellspacing` / `border`
attributes, `width="25%"` on a cell, `<table height>`, `align="right"`, `nowrap`, thead/tbody/tfoot
order, `max-width` on a 100% table, nested 100% tables in auto cells, vertical-align bottom in a text
cell, a rowspan taller than its rows.

## 6. Least sure to compile (read these first)

1. `cache.rs reconcile_table_children` / `reconcile_child_under`: the `display_of` closure (captures
   `styled_dom`) alive across calls that take `new_tree_builder: &mut`, `recon: &mut`,
   `debug_messages: &mut` (implicit reborrows of the `&mut` parameters, passed on repeatedly).
2. `cache.rs reconcile_recursive`: `TableParent::of(..).filter(|parent| ..parent.takes(..))` (the
   closure gets `&TableParent`; `takes(self)` on a `Copy` type through auto-deref), then
   `children_are_different = true` / `&mut new_child_hashes` (its element type inferred as `u64` from
   the new fn's `&mut Vec<u64>`).
3. `layout_tree.rs table_relevant_children`: `before.is_none_or(internal_or_caption)` twice with the
   same closure (it captures only `&StyledDom`, so it is `Copy`).
4. `layout_tree.rs process_anonymous_table_box_children`: recursive `&mut self` method; returns
   `self.flush_inline_run(..)` as its tail expression.
5. `sizing.rs calculate_ifc_root_intrinsic_sizes`: `min_content.get_mut(index)` matched as
   `Some(InlineContent::Shape(shape))`, then `if let ShapeDefinition::Rectangle { size, .. } = &mut
   shape.shape_def`; the second `self.text_cache.measure_intrinsic_widths(.., self.ctx.debug_messages)`
   (same reborrow as the first call).
6. `sizing.rs process_layout_children`: the removed local `use azul_css::props::layout::{LayoutHeight,
   LayoutWidth}` (both are imported at the top of the module); the `<br>` arm builds
   `crate::text3::cache::InlineBreak { break_type, clear, content_index }` by full path.
7. `fc.rs position_table_cells`: `.and_then(|w| w.relative_position.as_mut())` on
   `tree.warm_mut(..)`; `n.box_props.unpack().margin.main_end(writing_mode)`.
9. `fc.rs position_table_cells`: `col_positions.get(cell_info.column..span_end).and_then(|spanned|
   spanned.iter().copied().reduce(f32::min))`; `analyze_table_structure` keeps `table_node` (a shared
   borrow of `tree`) alive while it reads the direction.
8. `fc.rs layout_table_fc`: the caption-side chain (`table_ctx.caption_index.and_then(|i| tree.get(..))
   .and_then(|c| specified_caption_side(ctx, c)).unwrap_or_else(|| ..)`) with `ctx: &mut`; the
   `row0_cells: Vec<&TableCellInfo>` iterator chains (`filter` over `&&TableCellInfo`).

  These are most of the remaining y deltas in the corpus.

  reproduced deterministically; restart the app per case for clean probes.
