### 1. MoneyInput (`money_input.rs`) - an amount in a currency, integer minor units, never floats
- The field IS a `TextInput` (as NumberInput's is - no twin of the field); the money input decides which edits it
  accepts: a text that is an amount or can still become one (`-`, `12,` in en) is accepted (amount `None` while
  incomplete); garbage, a digit past the currency's minor digits (non-zero), a `-` where negatives are off and an
  i64 overflow are REFUSED (`TextInputValid::No`); `min` / `max` are reported (`BelowMin` / `AboveMax`), never
  refused (typing `1` on the way to `150` must work). On blur the text is rewritten canonical through
  `TextInput::set_text_in` (`1234,5` -> `1.234,50`) and `on_commit` reports; every state change reports `on_change`.
- Locale: `MoneyLocale { decimal_separator, group_separator (u32 code points, 0 = none), symbol_position,
  symbol_spaced }`; `en_us / de_de / fr_fr (U+202F) / de_ch (U+2019)`, `from_tag` (a table: de/it/es/da/... comma
  decimal; fr/nb/sv/fi/cs/pl/ru... NBSP grouping; nl/pt-BR currency before; *-CH Swiss; es-MX/US English),
  `from_sample` (separators read off a number the app's localizer formatted, e.g. ICU `format_decimal(123456789, 2)`,
  so the platform decides). Parsing tolerates: grouping optional, groups of three only, a typed space for a
  space-like separator and `'` for the Swiss apostrophe, the currency code / symbol before or after, `-` before or
  after, U+2212, accounting parentheses, and the KEYPAD DECIMAL (a lone `.` / `,` followed by 1..=minor digits - it
  cannot be grouping - is the decimal point, in every locale).
- Currency: `MoneyCurrency { code, symbol, minor_digits }`, `from_code` (ISO 4217 minor digits and symbols for the
  common codes: JPY/KRW/VND/CLP/ISK 0, KWD/BHD/OMR/JOD/TND/LYD/IQD 3, CLF 4, others 2). The code shows in an addon
  beside the field, on the locale's side. `MoneyInput::format_amount` / `parse_amount` for tables and imports.
- Skins: flat = the input-group addon (strip face, default border, 4 px radius, secondary ink); flora = a raised
  paper tab (rT -> rB face, bd2 hairline, soft1 ink, semibold, tracked). The field is the TextInput's own look.

### 2. Gauge (`gauge.rs`) - one value in a range as a dial, a ring or a bar
- `GaugeKind::{Arc (270 degrees, open at the bottom), Ring (full circle from twelve), Linear}`; `GaugeBand { from, to,
  kind: GaugeBandKind::{Ok, Warn, Bad, Neutral}, color: OptionChartColor }`; the value wears the colour of the LAST
  band holding it, the accent outside every band; bands are washed over the track (`show_bands`).
- Drawn with the chart's vector path - no second renderer: the dial is one SVG user space (`SvgNodeData::ViewBox`),
  the track, every band and the value's arc are one node each with an `SvgNodeData::Path` FILL of
  `chart::wedge_ring` (a ring segment between two angles). The bar is plain boxes. Value + label in the middle.
- A11y: role `Indicator` (= accesskit `Meter`) via `MeterAriaInfo`, named by the accessibility name or the label,
  value = `Gauge::summary()` ("73% (warning)") - the colour is never the only signal. Not a Tab stop (a meter).
- Robust maths: values clamp to the range, an inverted range reads the right way round, NaN / an empty range draw
  nothing, inf holds at the end.
- Skins: flat = Bootstrap semantic colours (success green, a deepened amber - #ffc107 vanishes on white - danger red,
  grey) with lighter dark steps, the slider groove as track; flora = the semantic stones (leaf / amber / clay /
  slate, stone by day, glow at night).

### 3. DateRangePicker (`date_range_picker.rs`) - two months side by side, presets
- First click ANCHORS, the pointer (or the keyboard focus) PREVIEWS the span in place (ends in the picked face, the
  days between washed, today ringed), the second click PICKS (either way round), Escape drops the anchor. Presets
  (Today, Yesterday, Last 7 / 30 days, This / Last week (week start), This / Last month, This / Last year;
  default six) pick at once and turn the months so the span shows.
- App-owned state: `DateRangePickerView { range, anchor, year, month }`; every action is a `DateRangePickerEvent
  { view (the NEXT view), kind: Anchored / Picked / Preset / Navigated / Cancelled, preset }`. Anchor, pick and the
  preview repaint both grids in place (no rebuild needed); turning months (header arrows, Page Up / Down, an arrow
  past either month, a preset elsewhere) is the app's rebuild - like DatePicker's month navigation.
- Keyboard: the days of BOTH months are one Tab stop; arrows move across the two months, Home / End the week's
  ends, Enter / Space pick (the activation click). A summary line ("4 Mar 2026 - 10 Mar 2026", a live region) and
  the root group's value say the range.
- NO TWIN of the date picker: refactors - `themes::{flat,flora}::date_picker_look()` (the look, split out of
  `date_picker`), `date_picker::day_grid` (the month grid frame, a closure per day; DatePicker's own grid uses it),
  and pub(crate) helpers (month_name, day_accessibility_name, build_weekday_row_from, header_nav_button,
  shifted_date, cell_faces, the header classes / arrows). Unpinned, the two looks are merged PER PART
  (`calendar_look`, theme_blocks::part_of) so the DOM is built once; state parts stack with `stack_parts`.

### 4. ReferencePicker (`reference_picker.rs`) - type to find one record of a large list
- BUILT ON ComboBox (field, popup list, active option, keys, a11y are the combobox's). Records
  `ReferencePickerItem { label, detail, id: u64 }`; `ReferencePickerFilter::Local` (the picker filters all records:
  label or detail contains the query, case-insensitive) or `App` (the records ARE the app's - possibly async -
  search results; `loading` says "Searching..."); at most `max_rows` (default 50) listed with a status line
  "N more - type to narrow" / "No matches"; a "Create <label> "<query>"" row unless a record is called exactly the
  query. Events `ReferencePickerEvent { text, id, kind: Query / Pick / Create }`; Query is DEBOUNCED through an
  azul timer (`debounce_ms`, default 150; 0 = every keystroke; a pick drops a pending query).
- ComboBox EXTENDED (in place, existing behaviour unchanged):
  - root-cause fix: the field click asks the ENGINE whether the list is open (`is_transient_window_open`, whose latch
    survives a rebuild) instead of only its payload flag - a combobox the app rebuilds on every keystroke used to
    need two clicks to close its list;
  - `item_details` (a quieter second line per option), `status` (a line after the options that is no option - no
    click, no active state, a live region), `open_on_type` (typing opens the closed list).

### 5. Shared helper
- `theme_blocks::{skins_of, structure_skin, part_of}`: the skin merge of a skin-built widget, written once (the chart
  had it inside `ChartLook`; `ChartLook::part` now delegates). Gauge, MoneyInput and DateRangePicker use it.
- `chart::over_plot` is pub(crate) (the gauge's arcs sit over its dial the same way).
