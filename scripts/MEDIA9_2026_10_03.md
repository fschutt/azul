## 1. The engine: audio files decoded and played

### Decision: Symphonia 0.6.1

Evaluated against the planning's list (`symphonia`, + `rubato`, `lofty`): **symphonia 0.6.1**
(2026-08; the current line, 0.6.0 since 2026-05; MPL-2.0, which `deny.toml` allows; pure Rust,
edition 2024 - the pinned toolchain 1.91 builds it). It demuxes MP4 / M4A, Ogg, MKV / WebM, WAV,
AIFF, CAF and decodes MP3, AAC-LC, ALAC, FLAC, Vorbis, PCM / ADPCM, and reads ID3v1 / ID3v2 / APE /
Vorbis comment / MP4 / RIFF tags and cover pictures - so `lofty` is not needed for reading tags
(writing tags is not a feature yet). 0.5.5 was the alternative (the API most code knows); 0.6 was
chosen because it is the maintained line and its API could be verified from its own sources.
`opt-simd` is OFF (it would pull `rustfft`). Opus inside Ogg / MKV / MP4 is demuxed by Symphonia
(it has no Opus decoder) and decoded by azul's own `AudioDecoder` (AudioToolbox on Apple; the
OpusHead pre-skip dropped); elsewhere an Opus file says "no Opus decoder here".
`rubato` was not added: a linear resampler (`playback::LinearResampler`) covers a device that
refuses the file's rate and a gapless next track at another rate; rubato is the quality step.

**New dependency** (dll only, `dll/Cargo.toml`): `symphonia = { version = "0.6.1",
default-features = false, optional = true, features = ["mp3", "aac", "alac", "flac", "vorbis",
"pcm", "adpcm", "wav", "aiff", "isomp4", "ogg", "mkv", "caf", "id3v1", "id3v2", "ape"] }` behind a
new feature `audio-decode = ["dep:symphonia"]`, added to `build-dll`. It brings (cargo-vet
exemptions needed): symphonia, symphonia-core, -metadata, -common, -bundle-flac, -bundle-mp3,
-codec-aac, -codec-adpcm, -codec-alac, -codec-pcm, -codec-vorbis, -format-riff, -format-isomp4,
-format-ogg, -format-mkv, -format-caf (all 0.6.1), `extended` 0.1.0, `num-complex` 0.4, and
`regex-lite`, `lazy_static`, `bytemuck`, `smallvec`, `bitflags`, `log` (most already in the tree).

### What was built (`dll/src/desktop/extra/audio/`)

- `playback.rs` (pure, every target): `Rechunker`, `LinearResampler` (streaming; a stream cut into
  packets resamples exactly as whole), `remix`, `apply_gain` (ramped), `chunk_peaks` +
  `LevelHistory` (the level of what is HEARD, not written), `TrackClock` (which track and media
  time the listener hears from the output's frame count - gapless boundaries, seeks),
  `RealTimeClock` (the headless synthetic sink plays in real time).
- `AudioSink` (mod.rs) grows `try_play` (says whether the output took the frame), `queued_frames`,
  `samples_played` (a media clock), `pause` / `resume` (in place), `clear` (drops the queue; the
  played count does not jump), `config`. The `OutputDevice` seam gets `queued_frames` /
  `set_paused` / `clear` with defaults; AVAudioEngine (frames in the scheduled buffers, the
  player node's pause / play, stop+play with a generation counter so the stopped buffers'
  completions count nothing), cpal / WASAPI (the queue, a paused flag, clear) and ALSA
  (`snd_pcm_delay` / `snd_pcm_pause` / `snd_pcm_drop`+`snd_pcm_prepare`, each optional) implement
  it; AAudio keeps the defaults. The synthetic headless sink now plays what it takes in real time
  (`AZ_SYNTHETIC_DEVICES=audio_sink`), so a headless player's position moves.
- `decode.rs`: `AudioFileDecoder` (a decoded FILE; named apart from `AudioDecoder`, the Opus PACKET
  decoder) - `open(path)` / `create(bytes, extension)`, `info()` -> `AudioFileInfo` (title,
  artist, album, album artist, genre, date, lyrics, codec, container, cover + its media type,
  length, rate, track / total / disc, channels; every metadata revision, later over earlier; the
  front cover), `next_frame()` (interleaved f32 at the file's rate), `seek(s)` (sample-accurate:
  the demuxer's packet seek plus dropping the frames before the target; at / past the end the file
  ends), `position_s`, `waveform(buckets)` (10 ms peaks resampled), honest closed handles that say
  why. `FileSource` (Rust-only) is the part the player shares.
- `player.rs`: `AudioPlayer` - a thread per player owning `PlayerCore` and the `AudioSink`
  (opened with the first file at its rate x 2 channels; 48 kHz with resampling when the device
  refuses the rate; no output -> `has_output` false and the reason). `load_file` / `load_bytes` ->
  a track id, `queue_file` / `queue_bytes` (GAPLESS: the next file's first sample follows the
  last one's in the same stream), `clear_queue`, `play`, `pause`, `toggle`, `stop`, `seek`,
  `skip`, `set_volume` (ramped), `get_state` -> `AudioPlayerState` (what is HEARD: track,
  position, length, peaks for a meter, queued count, playing / finished / has_output, a failed
  track's id), `error_message`. `PlayerCore` is a pure step function over a `PcmOutput` seam (the
  tests drive it with a fake output); the lead kept in the device is 250 ms, so a pause or a seek
  is heard at once.
- `AudioFileInfo` and `AudioPlayerState` live in `core/src/audio.rs` (plain repr(C) data, shared
  by the wasm build and the apps); wasm stubs of both handles in `dll/src/unified/audio.rs`.

## 2. The widgets (`layout/src/widgets/`; looks APPENDED to `themes/flat.rs` and `themes/flora.rs`)

Each: a `XxxLook` per theme (`// ==== <widget> ====` banners at the end of both theme files),
unpinned it follows the app theme (`theme_blocks::follow_app_theme`), light / dark twins via
`decl::themed_*`, in the widget manifest (`label_convention::every_widget_dom`) and in the
`theme_contrast` INPUTS group, tests named as sentences, RED commits before GREEN.

- **LevelMeter** (`level_meter.rs`) - AzMeet's meter moved here (no twin left): the dB scale
  (-60 dB empty, 0 dB full: `db_percent`, `rms_percent` = AzMeet's formula, `peak_percent`), a
  trough of three segments (green, amber past 70 % = -18 dB, red past 90 % = -6 dB), horizontal
  or vertical, a `ProgressBar` a11y role with "42%"; `LevelMeter::update_level(info, node, level)`
  resizes the segments in place (no rebuild); `LevelMeterThrottle` = AzMeet's `meter_change` rule
  (at most every interval, by half a percent or more); `level_of(frame)`, `peak_level(peak)`.
  AzMeet now uses it (`examples/azul-meet/src/{lib.rs, ui.rs}`: `mic_level_percent`,
  `METER_FLOOR_DB`, `meter_moved_ms` gone; the bar is a LevelMeter named "Microphone level").
- **SeekBar** (`seek_bar.rs`) - time played | trough (buffered, played, chapter ticks, a thumb) |
  length; press seeks and starts a scrub (reported with `dragging` set), moves follow, the release
  (or leaving the trough) reports `dragging` cleared - a player seeks once on release; keys 5 s /
  30 s with Ctrl, Home / End; the merge callback keeps a scrub across rebuilds (the slider's rule);
  a `Slider` a11y role reading "1:12 of 9:22"; `SeekBar::update_position(info, node, s)` moves
  the played part, the thumb, the label and the value in place (skipped mid-scrub);
  `media_time` / `SeekBar::media_time` is the one media-clock format ("m:ss", "h:mm:ss", "--:--").
- **MediaControls** (`media_controls.rs`) - a Toolbar row of icon Buttons named by what they do
  now ("Play" / "Pause", "Shuffle on", "Repeat one", "Back 15 seconds", ...): [shuffle] previous
  [back 15 s] play [forward 30 s] next [repeat] and a Volume Slider; one `on_action` hook with a
  `MediaControlsEvent { value, action }`; `MediaRepeat::next` (off -> all -> one).
- **Waveform** (`waveform.rs`) - a bar per peak (height = peak), the played bars in the accent, a
  playhead; it is a seek SURFACE exactly like the seek bar's trough: the same dataset
  (`SeekBarWrapper` + `SeekSurface`), the same pointer / touch / key callbacks (`seek_callbacks`,
  extracted so both share them), the same merge callback, the same hook type (`SeekBarOnSeek` /
  `SeekBarState`) and the same in-place move (`move_surface`; `Waveform::update_position`). The
  peaks: `WaveformPeaks` (streaming) + `resample_peaks` - the one helper pair, which
  `AudioFileDecoder::waveform` uses too.

Not built as variants (noted, see "Left"): MediaControls' compact / large / overlay sizes (one size
today; an app styles the row), SeekBar's hover-time tooltip and thumbnail preview.

## 3. AzMusic (`examples/azul-music`)

On the S7 **MediaShell** (music.md's shell; the plan named RecordsShell, which is S6 - decision in
the progress file): the sidebar (Songs, Albums, Artists, the playlists, "New playlist from the
queue"), the content (the songs in azul's virtualized **DataTable** with its filter row - Enter /
double-click plays from that row in the table's order; albums and artists as lists with Play -
`TODO(WIDGETS9A): IconGrid` of covers; a playlist; the empty state with "Scan the music folder" and
"Use the sample library"), the now-playing bar always under both (title / artist, MediaControls
with shuffle / repeat / volume, SeekBar, LevelMeter, a status line). Settings: the kit's page plus a
Library section (the music folder: Choose... (`FileDialog::open_directory`), "Scan the music
folder"). About, shortcuts, `--screen songs|albums|artists|settings`, `--theme`, `--mode`,
`--sample`, `--data-dir`.

- Model (plain Rust, tested): `library.rs` (Track, Album, Library: albums by filed artist,
  artists, search by every word, the JSON file, a rescan keeps known files' ids), `queue.rs`
  (PlayQueue: order, shuffle from a seed keeping the current track, repeat off / all / one,
  previous restarts after 3 s, play next, enqueue, `upcoming` for gapless), `playlists.rs` (one
  file per playlist), `scan.rs` (the audio files under the folder, hidden skipped, ~/Music),
  `sample.rs` (six generated tones in two albums).
- Data (the S3 split): `music/library.json`, `music/playlists/<uuid>.json`, the sample tones in
  `music/sample/<album>/<nn> <title>.wav` - all through the azul-storage Drive on a Thread
  (`kit::spawn_file_jobs`); the music itself is read where it is.
- The scan runs on a Thread: `AudioFileDecoder::open(path).info()` per file.
- Playback: one `AudioPlayer`; the app loads the queue's current track and hands over the NEXT one
  (`queue_file`) while it plays - gapless; a 250 ms timer reads `get_state`: when the handed-over
  track is heard the queue moves on and the one after it is handed over; the SeekBar and the
  LevelMeter move in place (markers); the window is rebuilt only when the track or the play state
  changes; the desktop is told (`set_now_playing`; `expose_system_media_controls = true`); media
  keys (PlayPause, NextTrack, PrevTrack, MediaStop), Space (not while the filter row is edited),
  Mod+Left / Right / Up / Down, Mod+R rescan; the desktop's seek / volume requests
  (`ApplicationEventFilter::MediaControl` + `get_media_control_request`).
- `scripts/azmusic_e2e.py`: --sample (AZMUSIC_LIBRARY 6 2), double-click plays "First Light", End
  on the seek bar goes on to "Harbour Walk" with no stop between (gapless), Space pauses / plays,
  Albums, Mod+, settings, dark.

## 4. AzPlayer (`examples/azul-player`)

On the MediaShell's player variant: the stage (black; azul's **VideoWidget** filling it with
`VideoSource::File`, the OSD and a note over it; a double-click is fullscreen) or the library
("Open a video...", "Continue watching" with a progress bar and "Resume at 31:50"), and the
controls bar (title, MediaControls with the skips and the volume, SeekBar, fullscreen, back to the
library), hidden two seconds after the pointer rests while the video plays; no title row in
fullscreen.

- The sound: an `AudioPlayer` playing the same file's audio track (AAC via Symphonia's isomp4),
  sought to the same resume point. The picture leads (moving it costs a decode from a keyframe):
  on every status report of the VideoWidget (about four a second) the sound is moved to the
  picture when they are more than 0.15 s apart (`sync::audio_correction`), plays / pauses with
  it. Play, pause and seeks reach both (the widget through `config.paused` / `config.timestamp`
  on rebuild; a repeated seek to the same time is nudged a millisecond so it is a change).
- Fullscreen: F, F11, a double-click (Escape leaves), `WindowFrame::Fullscreen` +
  `prevent_system_sleep`. Keys: Space, Left / Right 10 s (Shift: a minute), Up / Down volume with
  an OSD, M mute, Mod+O open.
- `player/history.json` (recent files, newest first, 20 kept; resume unless < 5 s or (nearly)
  finished; written every 10 s of playback and at the end), through the Drive on a Thread.
- `scripts/azplayer_e2e.py`: makes a 6 s H.264 + AAC MP4 with ffmpeg (skipped without it), plays
  it (or sees the "does not play here" note where nothing decodes H.264), Space, M (the OSD), F /
  Escape, then a second run sees the file in the library from the history.
