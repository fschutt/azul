# MEETDRIVE6 - AzMeet and AzDrive (report, wave 6, 2026-10-03)

Branch `wt/meetdrive6` from `25d78e309`. Nothing was compiled (house rule): every touched `.rs`
parses (`rustfmt --emit stdout`), the Python scripts byte-compile. Unlike the earlier reports the
look was SEEN this time: both apps ran headless from the prebuilt binaries (aa59b2d84) under
`scripts/waves/tools/run_capped.sh`, one at a time, and their screenshots were read (flat + flora,
light + dark). The run was interrupted twice (a power loss, a DNS outage) and resumed from
`scripts/MEETDRIVE6.PROGRESS.md`.

## 1. What was built

### AzDrive (examples/azul-drive)
- **Prefix ruling**: `src/ids.rs` - every id and class once, `__azdrive_<snake_case>`, as
  `const AzString` (`AzString::from_const_str`); the content pane, panes, dialogs and Options take
  their names from it. `scripts/azdrive_e2e.py` and `examples/azul-drive/scripts/browse.py` ask
  for the prefixed names (and detect an older build's names).
- **On azul-appkit**: the command line is `AppArgs` + AzDrive's `--layout` (DEDUP D2); the keyboard
  shortcuts are an appkit `Shortcut` table checked against the key rule (`keys::SHORTCUTS`); the
  data root, the saved theme / mode, FILE > Options = appkit's settings page (View / Navigation /
  Drives + the kit's pages), About = azul's `AboutDialog`; the view settings live in
  `drive/view.json` in the data tree; a built-in "Azlin" drive shows the data tree itself.
- **Drives that are not the data tree** (Home, the upload source, the download folder) are opened
  with INFRA6's `LocalDrive::without_manifest` (args.rs `write_sample`, actions.rs upload /
  download), so no `.azlin/cache` lands in the user's home.
- **Standard dialogs** (DEDUP D12): "delete for good" and "remove the drive" are azul's
  `MessageBox`; a transfer running 2 s opens azul's `ProgressDialog` once (`Queue::
  wants_progress_dialog`, RED-tested).
- **Dedup**: dead browse helpers gone (N6), `now_secs` -> `azul_storage::time` (D23), counts in the
  singular (`browse::counted`: "1 drive", "1 item"), one rule for a drive's metadata rows
  (`browse::metadata_rows`: no repeated Location, `Created` as a date) shared by the details pane
  and Properties (the latter had its own copy).
- **LOOK fixes**: F2 renames to the text the widget holds (deletions were lost: "notes.txt", End,
  nine Backspaces, "todo.txt" -> "todo.txtn"); text outside the shell (the inline sheet) took the
  default serif face - the body now names `system:ui`; the sheet gets a z-index.
- **E2E** (`scripts/azdrive_e2e.py`): screenshots wait until no animation / exit / transition runs
  (`settle`, the details pane animates its rows in); steps 5/7/9/10 run Select all / Undo / Copy /
  Paste from the ribbon, a new step 16 checks Cmd+A / Cmd+C with the content pane focused (see 7).
  A local copy that skips steps 7 and 16 (both need this branch's code) PASSES against the
  prebuilt binary.

### AzMeet (examples/azul-meet)
- **Prefix ruling**: `src/ids.rs` (`__azmeet_*`, tiles `__azmeet_tile_<who>_<camera|screen>`);
  the scripts find either naming (`App.id`).
- **Initials** are `azul_pim::initials` (DEDUP_EDITORS B24) - and of the NAME: the views carried
  the label "Ada (you)" as the name, so the avatar read "A(". `TileView` / `PersonView` now carry
  the plain name and `me`; `ui::shown_name` adds "(you)"; this side's shared screen is "Your
  screen".
- **On azul-appkit** (without its `azul` feature: the android / ios builds link statically):
  `AppArgs` + AzMeet's `--name` (D2); the data root; `meet/settings.json` read once at start (theme,
  mode, meeting server, name, video quality - `store::Prefs`) and written from the settings, the
  lobby's name field and a meeting server that answers; About = azul's `AboutDialog` with the facts
  as an appkit `AboutInfo` (+ where the files are); a Keyboard settings page lists `keys::SHORTCUTS`,
  the table `keys::command_for` (the window's key rule) is tested against.
- **Meeting data = files in a per-meeting folder** (user ruling): `meet/<room id>/meeting.json`
  (link, server, when this side joined, who was there) and `meet/<room id>/chat.jsonl` (one JSON
  object per message). Every write goes through `flush_files` -> `store::save`: queued, ONE save
  Thread at a time (a file queued again keeps only its newer bytes, so an older chat.jsonl never
  lands over a newer one), through azul-storage's `LocalDrive`; stdout `AZMEET_SAVED <key>`. The
  old `<config>/AzMeet/settings.txt` written with `std::fs` inside the health callback is gone
  (not migrated - pre-release, the next server that answers is saved again). A headless run keeps
  files only when given a data root (`--data-dir` / `AZLIN_DATA`); in the demo only Ada's window
  keeps them (one meeting, one machine).
- The demo's meeting code comes from `azul_storage::ids::random_seed` (it names a folder).
- **Chat**: Send empties the field for real (`TextInput::set_text_in`, see engine below - the
  re-render with `with_text("")` left the typed text on screen); the Send button takes the draft
  from the field's focus-lost hook (deletions included).
- **E2E** (`scripts/azmeet_e2e.py`): one `AZLIN_DATA` per side, and after the chat both sides'
  `chat.jsonl` must hold both messages and `meeting.json` must list the other person (a build
  without the files - no `AZMEET_SAVED` - skips that check and says so); a tile that is not there
  yet is waited for (it failed at its first poll). Run under ONE outer `run_capped.sh` (it holds a
  machine-wide lock). It PASSES against the prebuilt binary (H.264 both ways, chat both ways).

### Engine (unowned areas, RED first)
- **cpurender** (`layout/src/cpurender/raster.rs`): text inside an opacity / filter / transform
  layer (transparent clear) was drawn with LCD subpixel AA, which blends each stripe against the
  destination and stamps the pixel opaque - every glyph edge blended against transparent black:
  every dimmed (disabled) control's label was smeared and heavy in LIGHT mode (AzDrive's ribbon).
  `backdrop_is_opaque` probes the run's ink box; one transparent pixel and the run is drawn
  grayscale (as browsers do in a layer without an opaque background). Opaque backdrops keep LCD,
  so flat renders are byte-identical. Test: `layout/tests/text_inside_an_opacity_group_keeps_its_colour.rs`.
- **TextInput** (`layout/src/widgets/text_input.rs`): (a) the widget's mirror inserted at the
  engine caret's cluster START, dropping its affinity - after End (trailing on the last cluster)
  every typed character was mirrored one place early, so `on_text_input` hooks saw a different
  text than the field showed (`caret_byte`); (b) `TextInput::set_text_in(info, container, text)`
  (NEW public API): an app sets a field's text from a callback - the same one write the widget
  uses for a search field's Escape (`replace_engine_line`); a password gets its mask.
