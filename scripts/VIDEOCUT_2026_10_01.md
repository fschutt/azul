# VIDEOCUT: AzVideoCut, the first cut of the Premiere clone (2026-10-01)

Branch `wt/videocut` from `16d19442c`. Nothing was compiled or run (house rules): every Rust
file parses (`rustfmt --emit stdout`, scratchpad `vc_parse.sh`), the E2E script
byte-compiles. The suites, the api.json generation, the app build and the E2E are the
parent's (commands below).

## What was built

### 1. azul: MP4 container I/O for apps (`dll/src/desktop/extra/video_codec/container.rs`)

An editor SEEKS: it needs an MP4's H.264 track as access units by index; an export needs an
encoder's packets in a file. azul had only `DecodedVideo::decode_mp4_h264` (a whole clip,
decoded eagerly) and no muxer. Now (always-present C-ABI handles; the `mp4` crate behind them
is `video-native`'s, already in Cargo.lock and in `build-dll`):

- **`Mp4Demuxer`**: `create(bytes)` (through the existing `demux::demux_mp4_h264`), `is_open`,
  `error`, `width`, `height`, `fps` (from the presentation times, not the crate's integer
  rate), `duration_ms`, `chunk_count`, `chunk(i) -> OptionVideoChunk` (Annex-B, keyframes with
  their SPS/PPS in front), `frame_at(ms)` (the unit SHOWN at a time: by presentation time, so
  B-frame streams map right), `keyframe_before(i)`.
- **`Mp4Muxer`**: `create(width, height, fps)`, `write_annexb(packet)` (the first unit must be
  a keyframe with its parameter sets; they go to the avcC box, AUDs are dropped, every other
  NAL is length-prefixed; 90 kHz track timescale, constant rate), `samples_written`,
  `finish() -> U8Vec` (the file, in memory), `error`.
- **`VideoChunk`** / `OptionVideoChunk` in `azul_core::video` beside `VideoFrame`.
- wasm stubs in `dll/src/unified/video_codec.rs`; without `video-native` the demuxer reports
  why and the muxer does not open.
- **Root-cause fix, `VideoEncoder::encode_at(frame, timestamp_us, force_keyframe)`**:
  `VtEncoder::encode` stamped every frame with the WALL CLOCK; an export renders far faster
  than real time, so the rate control saw a fraction of a second of video and gave the file a
  fraction of its bitrate. `encode` is now `encode_at` with the wall clock (a live call is
  unchanged).
- **Twins unified (NO DUPLICATION)**: VideoToolbox's private `annexb_nals` and demux.rs's
  `append_avcc_as_annexb` (plus a copy of the same AVCC loop inline in the VideoToolbox encoder
  callback) are one helper each in `container.rs`; `demux.rs` and `videotoolbox.rs` import
  them.

### 2. azul: the `Timeline` widget (`layout/src/widgets/timeline.rs`)

Tracks of clips under a time ruler with a playhead; reusable by AzCalendar (day lanes), AzShow
(animation pane), audio apps (`TimelineTrackKind::Generic`).

- Structure: ruler row (corner timecode | ruler with labelled ticks, minor ticks, the
  playhead's head) over the body (track headers: name + mute/show and lock toggles as link
  `Button`s named "Hide V1" / "Lock V1" | lanes: a lane per track, clips placed at their time,
  the playhead line) over a scroll bar (thumb = the view's share).
- **Virtualised horizontally**: the app hands over every clip (data is cheap); only the clips
  and ticks inside `visible_window(view_start, view_width, pps)` (the view plus a quarter on
  each side) become DOM nodes (a thousand clips -> about sixteen nodes).
- **Controlled**: the app owns tracks, clips (with selection), playhead, `view_start`,
  `pixels_per_second`, snapping; ONE hook `on_event(TimelineEvent)`: Seek, Scroll, Zoom,
  ZoomToFit, Select (shift/ctrl, the pointer's time), Open (double-click), Move (target
  track in `value`), Trim (edge), LaneClick, Delete (shift = ripple), ToggleMute,
  ToggleLock.
- Pointer: ruler press/drag scrubs (pointer capture); scroll bar press/drag scrolls; a clip
  press selects, a drag moves it (also to another track) or, within `EDGE_PX` of an edge, trims
  it; the clip follows live (`set_css_property` left/width/top), snaps to the playhead, 0 and
  every other clip edge within `SNAP_PX`, and the release reports ONE Move/Trim. The drag
  survives the app's rebuild between press and release (the shared state is the lanes'
  dataset with `merge_timeline_state`, the split pane's rule). Locked tracks take no presses.
- Keyboard: the lanes are the one Tab stop (`Slider` named "Timeline", valued by the
  playhead's timecode): Left/Right a frame (Shift: a second), Home/End, Up/Down edit points,
  `+`/`-` zoom about the playhead, `\` zoom to fit, Delete/Backspace (Shift: ripple); letters
  and Space are left to the app. No `Scroll` handler (the `wheel_ownership` lint): an app that
  wants wheel scrolling / Ctrl+wheel zoom listens on its own container (AzVideoCut does).
- Looks: flat (Premiere on Windows 7: strip ruler, desk lanes, tinted clips, gold selection
  ring, red playhead, field-ring focus) and flora (strip, leaf headers with `.fl-label`, earthy
  tints, brass ring, clay playhead, accent/glow focus) appended under `// ==== timeline ====`;
  every colour a light/dark pair; structure in `TIMELINE_*_BASE` statics; follows the app
  theme when unpinned. In the lint manifest and the CHROME contrast group.
- `Timeline::format_timecode(seconds, fps)` (HH:MM:SS:FF) is the one timecode formatter (the
  app uses it for its monitors).

### 3. The app: `examples/azul-videocut` (package `AzVideoCut`, lib `azvideocut`, bin `AzVideoCut`)

On S3 `TimelineShell` (+ `office_shell().with_status_bar(..)`), `Titlebar` under
`WindowDecorations::NoTitle`, `ShellThemeScope` (slate accent):

- **Media bin**: thumbnail (frame 0), name, "duration - w x h - codec"; click selects,
  double-click (or "Open in source") opens it in the source monitor; Import (FileDialog
  `open_multiple_files`, mp4/m4v/mov) probes each file on a worker (`decode::probe`: size,
  rate, length, first frame) and references it by path.
- **Source monitor**: the media at its position (a `Slider`), Mark In / Out (I / O when the
  source monitor is active), Insert (,) / Overwrite (.) the marked range on V1 at the playhead.
- **Program monitor**: the sequence at the playhead through ONE image node updated in place
  (`change_node_image` by marker); timecode; |< < Play/Pause > >|, In / Out; Space, J / K / L
  shuttle (1x, 2x, 4x either way), arrows, Home / End, Up / Down edit points.
- **Timeline**: the widget over V1..V3 / A1..A3; tools Select (V), Razor (C; Shift = all
  tracks; Ctrl/Cmd+K = razor all at the playhead), Ripple (B: ripple trims), Slip (Y: a drag
  slips the source), Hand (H: selects, no extra behaviour yet), Zoom (Z: click zooms in, Shift
  out); snapping toggle (S); wheel scrolls, Ctrl/Cmd+wheel zooms; clip thumbnails; transition
  names as the clip's second line.
- **Effect controls**: Position X/Y, Scale %, Opacity %, Crop L/R/T/B % (`NumberInput`s), the
  head transition (None / Cross dissolve / Dip to black + frames), Enable/Disable, Reset.
- **Audio meters**: the rail is there, it says "no audio decoder" - **gap**: azul decodes no
  audio (`AudioSink` plays PCM; no AAC/Opus decoder), so A tracks hold clips that play silent.
- **Export dialog**: H.264 MP4 (the encoder named), size 1280x720 / 854x480 / 640x360,
  bitrate 8 / 4 / 1.5 Mbit/s, range Sequence / In to Out / First second, "Export now", a
  `ProgressBar`, Cancel; the file goes to `videocut/<uuid>/exports/<name>.mp4` on the Drive.
- **Settings** (`ShellSettingsLayout` in a `Dialog`: Playback, Export, Storage, About) and
  **About**; `--screen editor|export|settings|about --theme flat|flora --mode light|dark
  --size WxH --project <uuid> --sample`; theme and mode buttons in the toolbar.

Model (`model.rs`, unit-tested): project -> media items -> sequence -> tracks -> clips (`start`,
`source_in`, `length` in sequence frames, `Effects`, head `Transition`, `enabled`). Edits are
`Edit` commands through `Project::edit` (insert with a split at the insert point, overwrite,
razor one track / all unlocked, lift, ripple delete, move (overwrite at the destination, never
onto the other kind of track), trim (within the media and the neighbours, never under a
frame), ripple trim, slip, effects, transition, enable, track hide / lock); undo / redo keep the
sequence before each edit (command + memento, 200 deep); a locked track refuses edits; JSON
round trip without the history.

Pictures (`render.rs`, `decode.rs`): CPU compositor - V1 up, top wins, each clip a premultiplied
layer through crop -> fit -> scale -> position -> opacity; cross dissolve mixes the outgoing
(playing on into its handle) and incoming layers, dip to black darkens out / in. Files are read
by `ClipReader` (`Mp4Demuxer` + `VideoDecoder`, RGBA8 at the monitor's size - VideoToolbox
scales): the keyframe at or before the frame, then forward; on from where the decoder is when
the frame lies ahead in the same GOP (`feed_plan`); the last six frames cached; file bytes shared
by every job (`MediaFiles`).

Threads and idle CPU: every picture is a SHORT-LIVED job (an azul `Thread` that ends): a scrub
asks for one frame at a time and keeps only the newest request (`Coalesce`). Play starts a
decode-ahead job (six frames ahead, waiting on a `Condvar`) and a `Timer` at the MONITOR's frame
interval (its highest refresh rate) that shows the frame due at each tick and rebuilds the DOM
four times a second (timeline playhead, timecode); pause ends both. An idle editor has no
thread and no timer, so the shell's thread-poll timer (which runs at the frame rate while any
thread exists) stops too.

Export (`export.rs`): frames rendered at the export size on a worker, `VideoEncoder::encode_at`
(own timestamps, a keyframe every two seconds), `Mp4Muxer` -> MP4; no H.264 encoder -> Y4M
(uncompressed I420, BT.601 video range); a muxer that does not open -> raw `.h264`. Progress +
cancel through `ExportShared`; a 200 ms timer shows it while it runs.

Files (`store.rs`): `videocut/<uuid>/project.json`, `media/`, `exports/` on azul-storage's
`Drive` (a `LocalDrive` on `$AZVIDEOCUT_DATA` or `<data dir>/azul`), written by jobs (never in a
callback), saved after every edit. `--sample` (`sample.rs`): two coloured sweeps cut with a
cross dissolve, colour bars, a title matte as a picture in picture on V2; where the machine has
an H.264 encoder the two sweeps are ENCODED to `media/*.mp4` through the export path itself
(encode -> mux -> demux -> decode round trip), else they stay generated.

stdout for scripts: `AZVIDEOCUT_PROJECT <id> <clips> <frames>`, `AZVIDEOCUT_SAMPLE
encoded|generated`, `AZVIDEOCUT_EDIT <edit> <clips> <frames>`, `AZVIDEOCUT_PLAYHEAD <f>`,
`AZVIDEOCUT_FRAME <f>`, `AZVIDEOCUT_SAVED <id>`, `AZVIDEOCUT_EXPORT <done> <total>`,
`AZVIDEOCUT_EXPORTED <key> <bytes> <mp4|y4m|h264>`, `AZVIDEOCUT_ERROR <msg>`.

`scripts/azvideocut_e2e.py`: sample project (4 clips, 200 frames) and its first frame; the S3
slots inside the window, not overlapping; 4 timeline clips, playhead, ruler, lanes; Shift+Right
twice (frame 50); Ctrl+K (razor all: 6 clips); razor tool + click (7); select + Shift+Delete
(ripple delete: 6 clips, shorter); Ctrl+Z (7, 200); Home, Right; Ctrl+E, "First second",
"Export now", the file on disk (`ftyp` for MP4 / `YUV4MPEG2` for Y4M); flora + dark
screenshot.

Registered: root `Cargo.toml` member, `scripts/workspace_test_members.txt` (tested), the
`dll_tests` step "Run AzVideoCut tests" in `.github/workflows/rust.yml`.

## What is left / gaps

- **Graphite**: the plan's per-frame compositor is not wired; the CPU compositor stands in
  (the same `compose(project, frame, w, h, source)` seam a Graphite renderer would replace).
- **Audio**: azul has no audio decoder, so A tracks hold clips that play silent; the meters say
  so. (`symphonia` -> `AudioSink`, master clock from `frames_played`, per the plan.)
- **B-frames**: seeking assumes a decoder that hands frames out in DECODE order, one per access
  unit (VideoToolbox's synchronous decode). `frame_at` finds the unit by presentation time, but
  feeding `keyframe..=i` and keeping the last frame shows unit `i` only for such a decoder; a
  reordering decoder (Vulkan Video) needs a pts per frame (`VideoFrame` has none).
- **Readers per job**: decoder sessions are not moved between threads, so each scrub / playback
  job opens its readers (and demuxes the cached bytes) again; fine for the sample, slow for big
  files. A persistent decode worker needs a thread poll that does not tick at the frame rate
  while the worker idles (engine: the shell polls threads every frame while any exists).
- **Export in memory**: `Mp4Muxer::finish` hands the file back as bytes (and the Drive takes
  bytes); a long 1080p export holds the whole file in RAM. A file-backed muxer (`create_file`)
  or a streaming Drive put is the fix.
