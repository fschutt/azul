## What was built

**`examples/azul-mail/src/dkim.rs` (new)** - client-side DKIM:
- `generate_key()`: RSA 2048 through micromail's `generate_rsa_key_pem` (micromail feature `signing`;
  micromail itself untouched), the private half as a `Secret` (no Display, zeroed on drop), the public half
  as base64 **SubjectPublicKeyInfo** (`public_key_of`, PKCS#1 or PKCS#8 PEM in).
- `record_name` (`<selector>._domainkey.<domain>`), `record_value` (`v=DKIM1; k=rsa; p=...`),
  `zone_line` (split into 255-character strings), `default_selector` (`azmail<yyyymm>`), `is_selector`,
  `can_sign_for` (refuses provider domains: gmail.com, outlook.com, icloud.com, gmx, web.de, ...),
  `dmarc_record`, `setup_notes` (DMARC `p=none` + rua, SPF `~all` not `-all`, reverse DNS / PTR, port 25).
- `check_published` / `dns_report` / `txt_records` / `match_record` / `report_lines`: a TXT lookup through
  the UDP resolver micromail's MX lookup uses (`microdns`), a TXT answer reader (compression, NXDOMAIN,
  truncation), the match of the published key, DMARC and SPF records, one line each for the page.

**`send.rs`** - direct delivery:
- The outbox keeps the message UNSIGNED; every attempt signs it with the key in memory. An account that
  signs but whose key has not come from the keyring yet WAITS (queued, the attempt not counted, due again
  at once) - never sent unsigned. Sent keeps the message as it went out (signed).
- A signed mail is tried directly even where only a SHIPPED default asks for a relay (gmail.com,
  googlemail.com, yahoo.com - those defaults were about unsigned mail from home); a learned refusal still
  holds it back (`PolicyList::holds_back(domain, signed)`).
- Refusals are learned WITH THEIR CAUSE (`RefusalCause` in `send_policy.json`: `home_address` - Spamhaus
  PBL and other home-address lists, Microsoft S3150 / 5.7.606, Yahoo [BL21]; `no_reverse_dns` - Gmail
  5.7.25, Postfix "cannot find your reverse hostname"; `not_authenticated` - 5.7.26 / SPF / DKIM / DMARC)
  and explained in words on the recipient ("example.net refuses mail sent straight from a home Internet
  connection (its answer names a list of home addresses such as Spamhaus PBL): it needs a relay (...)").
- PORT 25: when no exchanger of a domain can even be connected to (no SMTP reply at all), AzMail probes
  big providers' exchangers on port 25 (`gmail-smtp-in.l.google.com:25`,
  `outlook-com.olc.protection.outlook.com:25`, first IPv4 + first IPv6 address, 6 s each). All found in
  DNS and none connectable = this connection blocks port 25: recorded as `port25: {open: false, checked,
  detail}` in `send_policy.json`; every direct mail then waits ("this Internet connection blocks outgoing
  mail on port 25 (many home providers do): the mail waits in the Outbox until it can go through a
  relay") and the probe is repeated after an hour (a laptop on another network). Any server's answer
  records port 25 as open. This is exactly the list the later relay fallback reads.

**`sending.rs`** - the form: `SendingForm::{dkim, dkim_domain, dkim_selector}`, `apply_dkim` (domain
typed or the address's, selector typed / saved / this month's, the new or saved public key or a key file,
else "Create a key first"), `describe()` adds ", DKIM-signed (<domain>)".

**`lib.rs`** - one keyring QUEUE (`KeyringCall`, `keyring_call` / `keyring_next`; azul keeps only the
last keyring answer, so calls go one at a time); `KeyringOp::StoreDkim / GetDkim`; `MailApp::dkim_keys`
(read once per run; `None` = the keyring has none); Send / Receive reads the DKIM key after the password
and the Outbox retry signs with it; `IoJob::DkimKey` (key generation on a Thread) and `IoJob::DkimCheck`
(DNS on a Thread).

**`ui_account.rs`** - the Sending page (wizard step and Account Settings) gets a DKIM section: "Sign my
mail with DKIM", domain + selector, **Create a key**, the TXT record to publish (name `#__azmail_dkim_name`,
value `#__azmail_dkim_value`, zone-file line), **Check DNS** (results per record), the four notes. Save puts
a new key into the keyring (`AzMail/<account>/dkim`) and memory. **`ui_compose.rs`**: Send hands the key over.

**`bin/azmail_send.rs`**: `--dkim-generate <pem>` (a key as the page makes it; prints `AZMAIL_DKIM_NAME` /
`AZMAIL_DKIM_VALUE`; the file 0600), `--port25-probe host:port`.

**`scripts/azmail_send_test.py`**: an INDEPENDENT DKIM verifier (RFC 6376 relaxed canonicalization written
in python, RSA-SHA256 checked by the `openssl` command, dkimpy as a second opinion when installed); cases
`dkim` (now the full signature), `dkim-generated` (AzMail's own key + record: `p=` equals OpenSSL's SPKI
of the key file, the mail verifies against the printed record), `port25`.

## How the user tries it with a real account (direct + DKIM)

Requirements: an address at a domain of your OWN (you can edit its DNS), an IMAP mailbox for it (any
hoster), and a connection whose outgoing port 25 is open (AzMail tells you if not).
1. Build: `cargo build --release -p AzMail` (and `--bin azmail-send` for the CLI). Start `target/release/AzMail`.
2. File > Add Account: name, address, the IMAP password (or app password). Incoming: the hoster's IMAP
   server (filled in for known providers). Sending: **Directly**, tick **Sign my mail with DKIM**, keep the
   domain (your address's) and selector (`azmail<yyyymm>`), click **Create a key**. The page shows the record.
3. At your DNS provider add a TXT record: name `<selector>._domainkey` (some providers want the full
   `<selector>._domainkey.<domain>`), value `v=DKIM1; k=rsa; p=...` exactly as shown (zone files: the
   quoted-strings line). Add `_dmarc.<domain>` TXT `v=DMARC1; p=none; rua=mailto:<you>` if there is none.
   Keep SPF ending in `~all`.
4. Finish / Save (the key goes into the system keyring), wait a few minutes, Account Settings > Sending >
   **Check DNS** until it says "published, with this key".
5. Send / Receive once (F9) after each start - it reads the password and the DKIM key from the keyring.
   Then New E-mail, send to a Gmail or Outlook address you can read.
6. Check: Gmail "Show original" must say `DKIM: 'PASS' with domain <your domain>` and `DMARC: 'PASS'`;
   or send to `check-auth@verifier.port25.com` (an automatic report comes back). If the mail stays in the
   Outbox, its reason says why (port 25 blocked, a home-address list, no PTR) and `send_policy.json` in
   the account folder records it - that is the list the relay fallback will use.
CLI alternative: `azmail-send --data <AzMail folder> --account <id> --from you@yourdomain --to x@gmail.com
--direct --dkim-generate /tmp/k.pem` prints the record to publish (a CLI-made key lives in that file).

The secondary route (sign in to a provider's SMTP server: Gmail app password at
myaccount.google.com/apppasswords, iCloud app-specific password at account.apple.com, Fastmail app
passwords) is NOT built yet.

## Engine gaps seen (not fixed here)

- FONTREG: no runtime "register a font under a family name": `FontManager::register_named_font` exists,
  but nothing in `CallbackInfo` reaches it, and the DLL swaps the fc_cache on every regenerate_layout
  (`replace_fc_cache` -> `drop_dangling_memory_faces`), which would drop such a face; a runtime list
  re-registered after each swap (like `register_builtin_mock_fonts`) is needed.
- `HttpRequestConfig::download_bytes` / `http_get` run synchronously inside the calling callback on
  desktop (`download_bytes_blocking` then `request::complete`): an app that downloads from a callback
  blocks its UI. Calling them from an azul Thread works (the request queue is a global Mutex).

## micromail notes (micromail untouched)

- `format_dkim_dns_record` publishes `p=` as PKCS#1 RSAPublicKey (what RFC 6376's text says) - OpenDKIM's
  verifier (`d2i_PUBKEY`) reads only SubjectPublicKeyInfo, which is what every provider publishes; AzMail
  writes its own record (SPKI).
- Connection failures come back as `Deferred { reply: None, reason: "could not connect to <host> port
  <port>" }`; a structured "unreachable" status would let a caller tell DNS failures from refused / timed
  out connections without a probe.
