# DRIVE2 - AzDrive works like Windows 10 File Explorer with the Ribbon (2026-10-01)

Branch `wt/drive2` from `39092feee`. Nothing was compiled (house rule): every Rust file passed
`rustfmt --check` as a parse check, the Python scripts `py_compile`, and two read-only review
agents checked the app against the generated bindings (`target/codegen/dll_api_external.rs`) and
the regenerated api.json (`16d19442c`). The unit tests, the widget lints, the AzDrive build and
the E2E are for the parent (commands in section 6). The run survived a network outage (resumed
from `scripts/DRIVE2.PROGRESS.md`); after the outage rule every unit was committed on its own.

## 1. What AzDrive is now

`examples/azul-drive` is rebuilt as Explorer on the S5 `BrowserShell` (title row, Ribbon over the
address bar, navigation pane | content | preview pane, the details pane under the row, the status
bar), inside a `ShellThemeScope`, flat and flora, light and dark (it follows the app theme and the
OS mode; `--theme` / `--mode` pin them).

- **Ribbon** (`ui_ribbon.rs`). FILE = the backstage (Options on `ShellSettingsLayout`, About,
  Close). HOME: Clipboard (Pin to Quick access [toggled when pinned], Copy, Paste, Cut, Copy path,
  Paste shortcut*), Organize (Move to v, Copy to v [pins, drives, "Choose location..."], Delete v
  [Recycle / Permanently delete / Show delete confirmation], Rename, Undo <what>), New (New folder,
  New item v [Folder, Text Document, Empty file], Easy access v [Pin, Add a folder as a drive]),
  Open (Properties, Open v, Edit, History*), Select (Select all, Select none, Invert selection).
  SHARE: Share (the items' addresses on the clipboard), Email (mailto with the addresses), Zip
  (azul's `Zip` into "<name>.zip" in the folder), Download, Upload (the OS's multi-file dialog),
  Burn to disc*, Print*, Fax*, Advanced security*. VIEW: Panes (Navigation / Preview / Details
  pane toggles), Layout (the 8-cell gallery), Current view (Sort by v with Ascending /
  Descending, Group by v, Add columns v, Size all columns to fit), Show/hide (Item check boxes,
  File name extensions, Hidden items as check boxes, Hide selected items*, Options). DRIVE: Add S3
  drive, Add folder as drive, Remove drive, Drive properties, Refresh. Every button runs its
  `Action`, or - `actions::why_not` - is greyed with the reason as its tooltip ("Select one or more
  items first.", "Nothing to paste: copy or cut something first.", "The Home drive stays.");
  the starred ones are always greyed with why AzDrive cannot do them.
- **Layouts** (`ui_view.rs`): Extra large / Large / Medium / Small icons, List, Details, Tiles
  (the `Tile` widget), Content; Ctrl+Shift+1..8 as in Explorer; the status bar's Details / Large
  icons switch. Details: a header of the visible columns (Name, Date modified, Type, Size; Add
  columns: Folder path, ETag), a click sorts, again reverses (an arrow marks it), each header has
  an edge to drag (the width follows the mouse, saved) or double-click (fit). Group by Name /
  Type / Size / Date modified in Explorer's groups ("A - H", "Tiny (0 - 16 KB)", "Earlier this
  week", folders first), collapsible (the Accordion's Groups variant). Item check boxes in every
  layout. Hidden items (dot names) only when asked; extensions hidden when asked (F2 then edits
  the stem). A cut item is drawn faded.
- **Navigation pane** (`ShellNavigationPane`): Quick access (the pins) and This PC (Home, the
  local folders and S3 drives added, their folders listed lazily, one listing per expand).
  **Address bar**: Back / Forward / Recent locations (new chevron) / Up, the breadcrumb with a
  menu per crumb, a click turns it into the typed path, Refresh, Search (filters the folder).
  **Places**: This PC (drive tiles with capacity bars in groups "Devices and drives" / "Cloud
  drives (S3)" with an empty state that adds one), Quick access (pinned folders + recent places),
  folders.
- **Keyboard** (`keys.rs`, window level, a text field keeps its keys): Enter, Alt+Enter,
  Backspace / Alt+Up, Alt+Left / Alt+Right, F2 (rename in place: the field focuses itself on
  mount; Enter or a click elsewhere commits, Escape gives up), Delete / Shift+Delete, Ctrl+C / X /
  V, Ctrl+A, Ctrl+Z, Ctrl+Shift+N, F5 / Ctrl+R, Ctrl+F / Ctrl+E / F3 (the search box gets the
  focus), arrows / Home / End / Page keys with Shift (extend) and Ctrl (move the focus only),
  Ctrl+Space, the menu key and Shift+F10, type-ahead (a prefix within a second, one letter again
  cycles). Mouse: click, Ctrl+click, Shift+click, Ctrl+Shift+click, double-click, right-click
  (the item's or the folder's context menu), a click on the empty space selects nothing.
- **File operations** (`fileops.rs`, `jobs.rs`, through `azul_storage::Drive` on an azul
  `Thread` each; LocalDrive and S3Drive alike): copy / move (within a drive one `rename`), rename
  (files and folders), delete (a local drive: into `<root>/.azdrive-trash/<stamp>/<key>`, Ctrl+Z
  restores; a cloud drive, the trash itself and Shift+Delete: a confirm dialog), new folder / new
  text document / empty file (then renamed in place), upload (OS dialog, OS file drop onto the
  window), download (into Downloads, a taken name keeps both), Zip, Undo (rename, trash, move,
  new item - a new item only while still empty). ONE transfer queue: a plan first (every file
  under a folder, every taken name at the target), the "Replace or Skip Files" dialog per conflict
  (Replace / Skip / Keep both, "Do this for the next N conflicts", Cancel), then the run with
  progress messages (at most ten a second) in the status bar ("Copying 3 items to docs - 1 of 3
  (25%), 2 waiting", a click shows the queue with Cancel). Errors land in the InfoBar over the
  content (Dismiss). Drag and drop inside the window: azul has node DnD
  (`AttributeType::Draggable`, `DragStart`, `Drop`); an item drags the selection, a folder item
  or the folder's empty space takes the drop (a move; Ctrl copies; across drives a copy).
- **Preview pane**: images (`RawImage::decode_image_bytes_any` on the thread, up to 32 MB), text
  and code (the first 64 KB, one ranged GET, binary files refused), a PDF's first page (the
  dll's `Pdf::to_svg_pages` + `ParsedSvg::render`, 560 px wide), WAV sound (read into f32
  samples in the app, Play / Stop through azul's `AudioSink`), H.264 MP4 video (the video widget;
  a cloud video is fetched first, up to 256 MB); other audio says why not (azul has no decoder).
  **Thumbnails**: Medium / Large / Extra large icons draw pictures as thumbnails (one thread per
  folder, `RawImage::thumbnail`).
  **Details pane**: the item (size, dates, type, location, ETag, a cloud file's metadata), the
  selection (counts, size), the folder, a drive (space, path / bucket / endpoint / region).
- **Properties dialog** (the modal `Dialog`, or the in-window sheet): General (type, location,
  size in bytes, a folder's size and contents counted on a thread, modified, attributes) and
  Details (name, key, ETag, the backend's metadata: a local file's location / created /
  read-only, an S3 object's Content-Type, storage class, encryption, version, x-amz-meta-*) via
  `TabHeader`; a drive's properties.
- **Settings** (FILE > Options, `ShellSettingsLayout`): View (the default layout, Hidden items,
  File name extensions, Item check boxes, Ask before deleting for good), Navigation (open in This
  PC / Quick access, the panes), Drives (every drive with Remove, Add S3 drive, Add a folder as a
  drive; keys only in the OS keyring), About. Saved as `<config dir>/azul-drive/settings.json`
  (`AZDRIVE_SETTINGS` overrides) through a `LocalDrive` on a Thread; read once at start.
- **Command line** (`args.rs`): `--screen this-pc|quick-access|home|settings`, `--theme
  flat|flora`, `--mode light|dark`, `--layout <name>`, `--sample` (sample files written into the
  Home drive through a LocalDrive, never over a file).

## 7. Gaps and what is left

- **Not run.** Nothing here was compiled or run (house rule; the prebuilt binaries were gone).
  The look is written, not seen: the E2E's screenshots (`--out`) are the first look.
- **Menus headless.** The context menus and the ribbon's drop-down menus (Move to, Copy to,
  Delete, New item, Sort by, Group by, Add columns, Recent locations, the crumb menus) are
  `open_menu_for_hit_node` / `open_menu`, which the headless backend does not show
  (`show_menu_from_callback` is a no-op there), so the E2E reaches those commands by the keyboard
  and the ribbon's plain buttons; Group by, Add columns, Move to / Copy to are only checked by
  reading.
- **The Layout gallery** is the Ribbon's strip: it shows the first cells and the rest behind its
  "More" chevron; Ctrl+Shift+1..8 and the status bar's switch reach every layout.
- **Details view in the app.** The Details layout (multi-select, resizable sortable columns,
  groups) is composed in `ui_view.rs` from plain nodes: `ListView` is single-select with fixed
  100 px columns and the table code belongs to another agent tonight. Candidate widget: a
  multi-select ListView with column widths and an edge-drag hook (the app's ColumnDrag +
  window MouseOver / MouseUp is the pattern).
- **Drop targets.** Items drop onto folder items, the folder's empty space and (new) the
  navigation pane's rows. The breadcrumb's crumbs take no drops (Breadcrumb has no drop hook);
  nothing is dragged OUT to the OS (azul has no drag-out). `accept_drop` / `set_drop_effect` are
  not read by the engine, so a drop shows no copy / move cursor.
- **Audio**: WAV plays (read in the app, played by `AudioSink`); MP3 / FLAC / OGG / M4A say why
  not (azul has no audio decoder - a decoder behind `AudioSink` is the engine's next step). Video
  is H.264 MP4 only and silent (the video widget has no audio track). A PDF previews its FIRST
  page only (through SVG; how faithful it is depends on printpdf's page_to_svg).
- **F2** opens the field with the caret at the end; Explorer selects the name's stem. A partial
  selection from the app needs the text node and cursor ids (`set_selection` with
  `GraphemeClusterId` byte offsets); not attempted.
- **Big objects.** A copy INTO a bucket from elsewhere is one PUT of the whole object in memory
  (azul-storage has no multipart upload); within one bucket it is a CopyObject (up to 5 GB, no
  multipart copy beyond); a bucket-to-disk copy streams in 8 MB ranged GETs; disk-to-disk is a
  chunked file copy. Zip packs in memory (refused above 256 MB).
- **Empty sub-folders of a LOCAL source** are not recreated by a folder copy (LocalDrive's
  recursive listing lists files; the copied folder itself and S3 folder markers are).
- **Thumbnails** only for the Medium / Large / Extra large icons, pictures up to 8 MB, the
  first 120 of a folder; Tiles and Content keep the type icon.
- **Search** filters the open folder by name; there is no recursive search.
- **History** (earlier versions), Burn, Print, Fax, Advanced security, Paste shortcut and Hide
  selected items are greyed with their reason.
- **The drives file** is still written from the UI callback through `DrivesFile::save` (as FB2
  left it; the file is shared with AzMail); the settings file goes through a LocalDrive on a
  Thread.
- **New enum variants** `AddressBarEventKind::Recent` and `ShellNavigationPaneEventKind::NodeDropped`
  break an exhaustive `match` elsewhere: AzShells got its arm here; an agent building on the
  navigation pane tonight (AzMail) may need one `| NodeDropped` arm at merge time.
- **Twin removed**: the tree drop hook (this branch's and TASKS's) - TASKS's kept (`752edbdf4`).
- **Twins across branches** (reported, not merged - other agents' apps): VIDEOCUT's
  `examples/azul-videocut/src/render.rs::fit_within` is `image_scale::fit_within` (same
  signature, same rounding); PHOTO's `view::thumbnail` scales its own tile grid (a different
  input, not a twin of `RawImage::thumbnail`). Once `RawImage::thumbnail` is in api.json, an app
  that scales a decoded RawImage should call it.
- **Twins** (reported, not merged): `browse::format_size` (app, "1.5 KB") and
  `tile::format_bytes` (widget, "324 GB") - FB2's note stands; `browse::upload_key` /
  `crumbs` / `up` are FB2's tested helpers the new UI no longer calls (`fileops::check_name` and
  `crumbs_of` / `place_up` do their work).
