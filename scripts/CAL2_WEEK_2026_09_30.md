# CAL2: AzCalendar week interactions (2026-09-30)

What the user reported (Mac, trackpad): "azcalendar doesn't let me vertically scroll the full range of the
day and zoom in / out with the trackpad (like azmaps does), so I can zoom in to a part of the day. also
clicking at a certain point to add an event at that day (with a transient window popover) doesn't work as it
does in google calendar."

Branch `wt/cal2-week-interactions`, base `8812e832c`. Nothing was compiled with cargo or rustc (house rule);
see "How sure".

## Why the whole day could not be reached

The cause is in the app, not in the engine:

1. The week only ever held 08:00 - 20:00. `week::FIRST_HOUR` / `END_HOUR` clipped every event to that
   range and counted the rest ("+N before 08:00" in the day header). The hours before and after were not
   in the DOM at all.
2. Nothing in the window scrolled. There was no `overflow-y` anywhere. The grid was 12 x 64 px under a
   window-high flex column, so on a short window the bottom hours ran off the window and were clipped.
3. The flex chain (body > main > week) had no `min-height: 0`. Even with `overflow-y: auto` on the grid,
   a flex item keeps its automatic minimum size (its content height), so it would have grown to the day's
   height instead of overflowing and scrolling.

Flex layout is taffy. A layout pin test checks the exact structure the app now uses (see "Engine"). It is
expected GREEN. If it is RED, the engine has a bug after all, and the test is the RED test for it.

## What was built

### Scroll (`lib.rs` `week_grid`)
- The week holds 00:00 - 24:00. `week::lay_out_day` places events in minutes from midnight and no longer
  clips; `DayLayout`'s `earlier` / `later` counts and the header's "+N before/after" are gone.
- The day-header row (weekday + date) sits above a scroll area, so it never scrolls. The scroll area is
  `#week-scroll`: `flex-grow: 1; flex-basis: 0; min-height: 0; overflow-y: auto; overflow-x: hidden`. It
  holds `#week-grid`, a flex row of the hour-label gutter and the seven columns `#day-0` .. `#day-6`, so
  the labels scroll with the grid. `main` and the week column have `min-height: 0` too. The "New event"
  side sheet has `overflow-y: auto`.
- Opening: an `AfterMount` callback on the scroll area scrolls it so 08:00 is at the top. On today's week
  the top is instead the whole hour an hour before now (`week::first_minute_shown`).
- Today's column has a red "now" line.
- A saved event that is out of view scrolls the week to it, with the hour before it at the top
  (`week::reveal_scroll`, `save_and_reveal`). An event from the side sheet can be at any time, and
  `mint-and-join.mjs` clicks "Join meeting" by its on-screen bounds.

### Zoom
- `CalState.hour_px`: 20 - 240 px, default 48 (`week::DEFAULT_HOUR_PX` / `MIN_HOUR_PX` / `MAX_HOUR_PX`).
  The app has no settings file, so the zoom lives in the app state only and is not persisted. If a
  settings file is added later, this value belongs in it.
- Pinch: `HoverEventFilter::PinchIn` / `PinchOut` on `#week-grid`, read with `CallbackInfo::get_pinch()`.
  These are the same inputs the map widget uses. The engine reports a pinch two ways, and
  `week::pinch_step` handles both:
  - macOS trackpad magnify (`magnify` -> `inject_native_gesture`, `duration_ms` 0): each update carries
    its own scale.
  - two touches (`detect_pinch`): the scale is measured from the start of the gesture, so a step is the
    ratio to the previous update. Same gesture means the same `initial_distance` and a clock that did not
    go back.
- Ctrl / Cmd + wheel: `HoverEventFilter::Scroll`, `get_key_modifiers()` (`ctrl || meta`),
  `get_scroll_delta()`. The factor is `2^(dy/240)`, bounded to 0.8 - 1.25 per event, with the map's sign
  (`dy > 0` zooms in). The callback calls `prevent_default()` so the week does not also scroll. Without a
  modifier the callback returns at once, and a plain two-finger scroll scrolls.
- Anchor: `week::zoom_scroll` computes the offset that keeps the time under the pointer (the pinch centre,
  or the cursor for the wheel) under it, held to the day. That offset is applied with
  `scroll_to_unclamped`. After zooming in, the offset is past the old layout's range, and the
  `RefreshDom` this returns lays out the taller day before anything draws.
  `ScrollManager::register_or_update_scroll_node` keeps an out-of-range offset through that rebuild.
  Zooming out stays within range.

### Click / drag to create (Google Calendar style)
- A left press in a day column (`LeftMouseDown`) on empty time records the press and captures the pointer
  (`capture_pointer`). A press on an existing event is left alone: `week::event_at` checks the press
  against the event's drawn block (minimum 18 px) and its lane. The event and its "Join meeting" button
  behave as before.
- `MouseMove`: after moving 4 px (`week::is_drag`), the press becomes a drag. The draft is drawn live and
  redrawn only when its quarter hours change.
- `LeftMouseUp`:
  - a click gives `week::click_range`: an hour from the quarter hour clicked, cut at 23:59;
  - a drag gives `week::drag_range`: every quarter hour touched, at least 15 minutes, in either direction,
    inside the day.
  - A y on an hour line counts as the line.
  - Events do not cross midnight and 24:00 is not a time of day, so the day ends at 23:59.
- The draft (`#draft`) is drawn in place like an event: dashed border, pale fill, "(No title)" and the
  time. Its child is the popover, a `<transient-window>` (`NodeType::TransientWindow`):
  - `TransientWindowConfig::opened()`, anchor `Right`, dismiss `Outside`, material `Transparent`;
  - the anchor is the draft block itself, a viewport rect with the scroll taken off, so it opens to the
    right of the draft; the engine flips it at the screen edge.
- The popover card (`#draft-panel`) holds:
  - the title `TextInput` (`#draft-title`). It is the first tab stop, so the engine autofocuses it and
    the user types straight away.
  - "Wednesday 30 September, 10:30 - 11:30" (`#draft-when`, `week::draft_label`).
  - "Add AzMeet link": the same part as the side sheet (`meet_toggle`), using meeting.rs.
  - Cancel (`#draft-cancel`) and Save (`#draft-save`).
- Enter in the title (`TextInput::with_on_virtual_key_down`, Return / NumpadEnter) or Save runs the side
  sheet's save path, minting included. The event file is written and the popover closes, because the
  draft leaves the DOM. As in Google Calendar, an event saved from the popover without a title is saved
  as "(No title)".
- Cancel removes the draft. Escape, a press outside, or the popover's window losing focus dismisses it;
  the engine then fires `ComponentEventFilter::Dismissed`, and `on_popover_dismissed` drops the draft.
  That callback carries the form serial, so a late event cannot drop a newer draft.
- A press on the grid while the popover is open only closes it, as in Google Calendar. Some systems report
  the popover's dismissal before the press, so a press within 250 ms of a dismissal is ignored too.
  Changing week drops a draft.
- The side sheet ("New event") and the popover are one `Form`, with `FormPlace::Sheet` / `Popover`. They
  share the save, mint, cancel, title and meet-toggle code. While the sheet is open the grid ignores
  presses.

Untouched. The toolbar and `WindowDecorations` are as they were; edits are limited to the week grid, the
popover and the app state.

### What the headless E2E cannot do, and why (engine limit, not fixed here)
The popover is a separate window.
- The headless backend creates it (`pending_window_creates` becomes a child `HeadlessWindow`), but
  `HeadlessWindow::run` Phase 4 only polls the child for Close. It never runs a pass, a layout or a timer
  for it.
- The debug server's timer lives on the root window only.
- The parent does not lay out the popup content (`LayoutWindow::layout_transient_content` uses scratch
  caches).
- A key the parent gets while a focus-taking popup is open is forwarded to that popup's mailbox and
  consumed (`forward_keys_to_popup`). The headless popup never replays it (`deliver_forwarded_keys` does
  nothing).

So **Enter and Escape cannot reach the popover headless**, and neither can a pointer inside it. Instead,
the script drives the popover's nodes where they also exist: the transient subtree is part of the app's
DOM 0. It uses `focus_node` + `text_input` on `#draft-title`, falling back to the accessibility
`set_value` action, and the accessibility `default` action (a screen reader's click) on Save / Cancel.
Enter runs exactly the Save code (`save()`), and Escape runs the same `Dismissed` path as a click outside.
Both need a real window, or the engine follow-up below.

Engine follow-up (not in scope; proposed): make headless child windows live.
1. In Phase 4, lay out a new child once.
2. Call `poll_transient_mailbox()`.
3. Run `process_window_events(0)` when `transient::has_forwarded_keys` is true, and forward
   `ShouldRegenerateDomAllWindows` to the parent.
4. Give `forward_keys_to_popup` the text that the debug `key_down` records, which is currently labelled
   `Programmatic` and so skipped.
5. Or route debug ops to a child with `window_id`.

With that, the E2E could press Enter and Escape for real.

## Engine
**No engine change and no api.json change.** Only the public API is used: `CallbackInfo::get_pinch`,
`get_scroll_delta`, `get_key_modifiers`, `prevent_default`, `get_cursor_relative_to_node`,
`get_cursor_relative_to_viewport`, `get_hit_node`, `get_hit_node_rect`, `capture_pointer`,
`get_node_id_by_id_attribute`, `get_node_rect`, `get_scroll_offset_for_node`, `scroll_to`,
`scroll_to_unclamped`, `get_current_keyboard_state`; `TransientWindowConfig::opened / with_anchor /
with_dismiss / with_material`, `NodeData::create_node(NodeType::TransientWindow(..))`,
`Dom::create_from_data`, `ComponentEventFilter::{AfterMount, Dismissed}`, `HoverEventFilter::{Scroll,
PinchIn, PinchOut, LeftMouseDown, MouseMove, LeftMouseUp}`, `TextInput::with_on_virtual_key_down`. The only
file outside the app is the new layout test and its line in `layout/tests/all.rs` (appended at the end).

## How sure (nothing compiled)
- `rustfmt --check` passes on `lib.rs` (and through it `week.rs`, `event.rs`, `meeting.rs`) and on the
  layout test.
- Every call was checked against the generated link-dynamic bindings in the main checkout:
  `target/codegen/dll_api_external.rs` and `reexports.rs`, generated today at 11:57. That covers
  signatures, `into_option()` helpers, `Copy` derives and module paths.
- The f32 round trips in the week tests were checked in Python with float32 rounding; they are exact.
- The E2E script was dry-run as described above.

Least sure, in order:
1. The import paths: `azul::css::WindowBackgroundMaterial`, `azul::misc::{TransientAnchor,
   TransientDismiss}`, `azul::window::TransientWindowConfig`, `azul::dom::{DomId, DomNodeId,
   NodeHierarchyItemId, NodeId, VirtualKeyCode}`. They are taken from `reexports.rs`; if the parent's
   codegen differs, only these `use` lines move.
2. `DomId { inner: 0 }` as a struct literal for the root DOM. The generated type has a public `inner`
   field.
3. `on_day_drag`: `press.dragging.then(|| press.range(hour_px))`, a closure borrowing a `&mut Press`
   binding immutably before the next write.
4. `zoom(&mut guard, &mut info, ..)`: deref coercion of the `downcast_mut` guard to `&mut CalState`.
5. `info.get_current_keyboard_state().current_virtual_keycode.into_option()`: a `Copy` field of a
   temporary that implements Drop.

Runtime assumptions to watch in the E2E:
1. The `pinch` debug op only injects the gesture. The script's next `mouse_move` pass is meant to deliver
   it. If another pass runs in between, the gesture is cleared and "zoom" fails; only that stage fails.
2. `text_input` into a node of the transient subtree of DOM 0: `TextInput`'s handler needs only the node
   hierarchy (`value_node`) and the recorded changeset, so `on_title` should get the text. If it does not,
   "click" / "drag" fail with the file saying "(No title)".
3. The accessibility `default` action on the popover's Save / Cancel. This is the `Click` filter on the
   Button root, which has the PushButton role.

## What is left
1. The headless popup limit and the proposed engine follow-up above, so the E2E can press Enter and
   Escape.
2. The zoom is not persisted: the app has no settings file.
3. On platforms with classic (non-overlay) scrollbars the grid's columns are narrower than the header's
   by the scrollbar width, so the header misaligns by up to that width. macOS overlay scrollbars
   reserve no space.
4. The draft block shows the typed title only after the next rebuild: `on_title` returns `DoNothing`, as
   the side sheet does, so the popover's field is not rebuilt on every keystroke.
5. Moving or resizing existing events by dragging, all-day events and overnight events are not built.
