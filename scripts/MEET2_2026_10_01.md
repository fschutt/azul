# MEET2 - AzMeet that properly works: the video leftovers, CallShell, chat, culling, CPU (report)

Branch `wt/meet2` from `39092feee`. Nothing was compiled with cargo (house rule). Every touched
`.rs` file parses (`rustfmt --emit stdout`); the PURE AzMeet modules (`chat.rs`, `speaker.rs`,
`tiles.rs`, `pace.rs`, `args.rs`, `video_wire.rs`) were type-checked on their own with
`rustc --edition 2021 --crate-type lib --test --emit=metadata` (no binary built, no target/);
the app's `use azul::{..}` paths were checked against the parent's generated
`target/codegen/reexports.rs`, and the builder / callback signatures used against
`target/codegen/azul.rs`. The Python scripts byte-compile; the E2E's dev-server start was run
(node only, no app binary). No app binary was run (none existed while this was written).

## What was built

### 1. Engine: the video leftovers of VIDEO_REVIEW (all RED first)

| Review item | Fix |
|---|---|
| 11: `stream.rs` never applied `VideoConfig::output_format` (double swizzle) | `open_session_decoder(config.output_format)`: BGRA8 by default, NV12 for the YUV path (`f990d6c99`). |
| 6: matrix detection by pointer equality | VideoToolbox: `CFEqual` dlsym'd (`copy_decoded`); AVFoundation: `*value == **kCVImageBufferYCbCrMatrix_ITU_R_601_4` (CF `==` is `CFEqual`) - camera and screen share share `publish_pixel_buffer` (`a79c61e21`, `19356b1db`). |
| 7: encoder hard-wired to '420v' + Rec.709 | `VtEncoder.source` (`session_source`): the pool's pixel format ('420v' / '420f' / BGRA) and the YCbCr matrix tag come from the frames; a frame in another matrix / range gets a session made for it (first frame a keyframe). BGRA frames now come from the session pool too (`19356b1db`). |
| 8: decoder output switch only on an IDR | The decompression session decodes at the stream's own size; an `OutputStage` (a `VTPixelTransferSession` + a destination `CVPixelBufferPool`, optional symbols: macOS 10.8+ / iOS 16+) scales and converts to the asked output. `set_output_size` / `set_output_format` apply at the NEXT picture; no session is recreated for them, no reference frame is lost. Attachments propagate (`CVBufferPropagateAttachments`), so the matrix survives scaling (`19356b1db`). |
| 12: `cut_frame` `mem::take` realloc per frame | `mem::replace(buf, Vec::with_capacity(room))`: the worker keeps the room the capture slot writes the next frame into (`d2c07bafa`). |
| "encode and decode still on the UI thread" | `CodecThread` in `video_codec/mod.rs`: the engine is MADE on its own thread (no engine has to be `Send`), jobs run in order, the handle only queues and pulls; idle it sleeps in `recv`; dropped it skips the queue and joins. `VideoEncoder::encode` hands the frame over (a queue of three: a realtime encoder that falls behind drops frames, `encode` returns false), `recv_packet` pulls, new `flush` waits. `VideoDecoder::decode` / `set_output_*` are queued in order, `recv_frame` pulls, `flush` waits. `open_on_this_thread` (crate) keeps the engine on a caller already off the UI thread: the `<video>` worker and the whole-file pipeline. `DecodeEngine` holds the Vulkan / VideoToolbox engines - one copy of the per-backend dispatch instead of four (`b8cd68319`). |
| zero-copy IOSurface path | The smallest step: `NativePicture` - a decoded picture kept as a retained, IOSurface-backed CVPixelBuffer (the decoded buffer itself, or the stage's transferred one), copied into bytes only on demand (`to_frame`); `VtDecoder::set_native_output` / `take_native`. The copy moved out of the stage's lock. Next step (not built): an external image bound with `CGLTexImageIOSurface2D` in the GPU path (VIDEO_PATH "Zero copy" 2) (`9ec56f6cc`). |
| JPEG fallback must not be macOS's default | A peer whose caps have not arrived gets NO video yet instead of JPEG (`video_wire::wire_codec`, `assignment_among`, `1ccb08331`); the probes wait with `flush` (an async encoder would otherwise have failed the probe and fallen back to JPEG); the forced-keyframe rule tolerates the encoder thread's output lag (`OUTPUT_LAG_PACKETS`) and puts back a force the encoder did not take (`not_taken`), so the async encoder is never "broken" into JPEG; `VideoEncoder::is_hardware` (new) and the codec line "Video: H.264 (VideoToolbox, hardware)" + stdout `AZMEET_ENCODER <stream> <size> hardware|software` say where encoding runs. |

Also: the CoreVideo pixel-format constants and the RawImageFormat -> pixel format rule were a
twin in `camera/avfoundation.rs` and `video_codec/videotoolbox.rs`; one copy now in
`capture_slot.rs` (`cv_pixel_format_for`, `CV_PIXEL_FORMAT_*`).

### 3. AzMeet on the S10 CallShell

New modules (pure, unit-tested): `chat.rs` (wire kind 8 `[8][1][seq][sent_ms][len][text]`,
`ChatLog`: listed once by (sender, seq), unread while the panel is closed, newest 500),
`speaker.rs` (`level_db`, `ActiveSpeaker`: a 600 ms run of speech takes the stage unless the one
on it still speaks; the stage stays with the last speaker; GAP 400 ms), `tiles.rs` (`arrange`: a
shared screen takes the stage in any view; speaker view: pinned, else active speaker, else first;
this side's own share never its own stage; `tile_need`: a hidden tile or one under 24 device px
asks for nothing), `pace.rs` (15 ms while media flows, 250 ms after a quiet second), `args.rs`
(`--screen lobby|call|settings`, `--theme flat|flora`, `--mode light|dark|system`, `--name`).

`ui.rs` (new): the whole window from a `CallView` the app builds (`snapshot`), every colour the
system's or the widgets' (follows flat / flora and light / dark; video tiles keep a dark backdrop),
`NoTitle` + `Titlebar`, inside `ShellThemeScope`:
- **Lobby** = the CallShell with this side's camera preview as its one tile, the join form in the
  side panel (name, meeting server + whether it answers, New meeting, Join with a link, the
  device pickers), the microphone (hidden capture widget) and level meter in the devices slot,
  Mute / Start video / Settings in the controls bar.
- **Call** = the CallShell with `arrange`'s tiles: stage + filmstrip or gallery; every tile 16:9
  (the stage fills the stage), initials until a stream arrives, name label, speaking ring;
  side panel tabs People / Chat (unread count) / Statistics (People, Microphones, Speakers, Video,
  Audio, Network - the FB1-fixed lines, wrapping inside the panel); devices slot: mic meter +
  invite link; controls: Mute, Start/Stop video ("not shown to anyone" when culled), Share,
  Deafen, Speaker/Gallery view, Drop a video packet (test pattern runs), Settings, Leave.
  The chat field fills its row from a zero flex basis.
- **Settings** on `ShellSettingsLayout`: Devices (microphone, speaker, camera facing), Video
  (quality: automatic 720 / data saver 360 / low 180 - caps what this side asks for), Appearance
  (Flat / Flora, System / Light / Dark via `set_theme` / `set_mode`), About; Back / Escape.
- Shortcuts: Ctrl/Cmd+D microphone, Ctrl/Cmd+E camera, Escape closes the settings.
- Every control and tile has an id (`azmeet-mic`, `azmeet-chat-field`, `azmeet-tile-ben-camera`,
  ...). `AZMEET_PANEL=people|chat|statistics|closed` picks the side panel at start (the node
  scripts open the statistics, whose lines they read - `meet-e2e.mjs` `appEnv` sets it).

`lib.rs`: async codec (send_h264 submits, `drain_h264` / `drain_encoders` / `drain_decoders` in
the pump; `give_up_h264`, `stream_targets` one helper each), chat send / receive (stdout
`AZMEET_CHAT <name>: <text>`), active speaker fed by every received audio frame (also while
deafened) moving the speaker view's stage, culling through `arrangement` + `tile_role` +
`is_node_visible` (measured with the tile sizes every 2 s), the quality cap, the adaptive pump
(re-arms its timer), the statistics tick by time and a repaint for statistics only while their
panel is open and the text moved (it rebuilt the whole window every 2 s before). The old
hand-rolled layout is gone.

### 4. Scripts

- `scripts/azmeet_e2e.py`: the meet dev server, Ada (`AZMEET_AUTOCREATE`) and Ben
  (`AZMEET_JOIN=<link>`), headless, EACH UNDER `run_capped.sh` AT 1000 MB / 140 s (two apps run
  at once - the house rule's exception); asserts each window lays out the other's camera tile
  inside the window, decodes the other's video (`--require-h264`), a chat message sent with Enter
  arrives (stdout, unread count, chat panel, the sender's field empties) and the answer sent with
  the Send button comes back; screenshots both.
- `scripts/azmeet_cpu.py`: two scenarios, sequential: **quiet** (mics muted, cameras off): CPU
  mean per app <= `--quiet-max` (1.0 %), no DOM rebuild, no display-list rebuild in the window;
  **video** (test pattern): every encoder in hardware (`AZMEET_ENCODER ... hardware`), no
  display-list rebuild for video frames, every damaged rect inside the other's camera tile
  (`get_frame_report` after `reset_frame_counters`); prints the CPU of each.
- `layout/tests/a_chat_field_keeps_its_width_while_text_is_typed.rs` (verification of the user
  report; expected GREEN after FB1 `43c226479`).

## Coordination

- LIFECYCLE (done) owns the reaping of widget threads; nothing here touches `run_all_threads` or
  unmount. The codec threads are owned by their handles (joined on drop, queue skipped), so they
  need nothing from it. One interaction to know: this side's camera tile moves between a gallery
  cell and a filmstrip cell when a stage appears or goes; the `CameraWidget` node is remounted
  and its capture worker restarts - with LIFECYCLE's node-owned threads the old worker is now
  stopped, not leaked. (A stable mount across that move would need a keyed node; not done.)
- Shared files touched: `layout/src/widgets/mod.rs` (one name appended to the CHROME contrast
  group), `layout/src/widgets/shells/mod.rs` (one fixture appended to `every_shell`),
  `layout/tests/all.rs` (one pair appended), `dll/src/unified/video_codec.rs` (two stubs).

## What is left

1. **Zero copy, steps 2 and 3**: bind `NativePicture`'s IOSurface in the GPU path (an
   `ExternalImageHandler` arm with `CGLTexImageIOSurface2D`, two planes for the `YuvImage`) and
   switch AzMeet's decoders to native output for GPU windows; encode from the capture's
   `CVPixelBuffer` on the capture worker (a "H.264" `FrameConsumer` kind - an API change).
2. **Event-driven network delivery**: the pump still polls iroh (15 ms with media, 250 ms quiet);
   0 % needs `IrohEndpoint` to wake the loop on an event (an app-event source like the tray's).
3. **Device selection**: the microphone and speaker picks are kept but `MicrophoneWidget` /
   `AudioSink` take no device (`AudioConfig` has no device id) - an engine API. The camera pick
   (facing) applies.
4. **The numbers**: run `azmeet_cpu.py` and the E2E on the rebuilt binaries; nothing was measured
   here (no binary existed while this was written).
5. **AzMeet niceties not built**: pinning a tile by double-click (only `AZMEET_STAGE`), a
   screen-share source picker (no capturable-window list API), reactions / raise hand, chat
   history persisted to files (the S3 layout), "starts in ..." from the room times (M6).
6. **Codec**: the byte path still copies each picture into CPU memory; `VtEncoder::encode` still
   calls `CompleteFrames` per frame (now on the encoder's own thread - it keeps one packet per
   frame, in order, which the keyframe rules use).
