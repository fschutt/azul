# SHEETS: AzSheets (the Excel clone, ledger A8) and the CellGrid widget (2026-10-01)

Branch `wt/sheets` from `16d19442c`. Nothing was compiled or run (house rule; the prebuilt binaries are
gone tonight). Every Rust file was parse-checked with stable `rustfmt --edition 2021 --check`, the Python
E2E with `py_compile`. The engine layer was written by a fork on `wt/sheets-engine` and cherry-picked
(its own report: `scripts/SHEETS_ENGINE_REPORT.md`).

## What was built

### 1. Engine fix: a11y roles for a grid, and a cell's place in the whole grid

`core/src/a11y.rs`: `AccessibilityRole::Grid` and `AccessibilityRole::GridCell` (appended at the end of
the enum, ABI-stable); `AccessibilityInfo` gains `row_index: OptionUsize` and `column_index: OptionUsize`
(1-based, `aria-rowindex` / `aria-colindex`; placed after `described_by`, before `role` /
`is_live_region`, so the repr(C) struct keeps decreasing alignment). `Default`, `assign` and the four
`to_full_info` literals carry them. `layout/src/managers/a11y.rs`: `map_role` sends them to accesskit's
`Role::Grid` / `Role::GridCell`; `build_node` sets accesskit `row_index` / `column_index`. Why in the
engine: a virtualised grid renders a window of its rows, so the DOM position cannot tell a screen reader
that the first rendered row is row 1000. RED `218807a01`, GREEN `06e80205d`.

### 2. `CellGrid` (layout/src/widgets/cell_grid.rs, both theme files, tests, manifest)

A reusable spreadsheet surface, generic over its data: the app answers a DATA callback (text + kind of
one cell) and a STYLE callback (fill, ink, four border colours, bold / italic / underline / strike,
horizontal / vertical alignment, wrap, font size) for the cells in view only. AzContacts or a records
app can back it with rows.

- Virtualised rows AND columns: only the visible window is in the DOM. The grid scrolls by WHOLE cells,
  as Excel does: the wheel (3 rows per notch, remainder kept), the keyboard and the window move
  `CellGridView::top_row / left_column`. Frozen header row (A, B, C...), header column (1, 2, 3...) and
  freeze panes (`with_frozen(rows, columns)`) are drawn first, then a freeze line, then the scrolled
  window - they stay put by construction, and a 1,048,576-row sheet needs no 26 M px scroll extent (f32
  cannot address it to the pixel; excel.md question 8). Hidden rows / columns = size 0, skipped by the
  window and by the cursor.
- Column widths / row heights: sparse overrides in px; the header edge resizes by dragging (live preview,
  `ResizeColumn` / `ResizeRow` on release), a double-click on a column edge asks for an auto-fit.
- Selection model: active cell + anchor + several ranges (Ctrl+click adds one), whole rows / columns
  (header click, Shift+Space, Ctrl+Space), select all (corner, Ctrl+A), Shift+arrows, Ctrl+arrows to the
  data edges (Excel's rule over the data callback within the content extent), Ctrl+Shift+arrows, Home,
  Ctrl+Home, Ctrl+End, PageUp / PageDown (cursor and window by a screen), Enter / Tab (Shift backwards),
  the window following the cursor.
- In-cell editing without a TextInput (no focus juggling across rebuilds - ComboBox's pattern: the
  focused grid takes `Focus(TextInput)` and the text changeset, cancelling the engine's own insertion):
  a typed character starts an edit that replaces the cell (Enter mode: arrows commit and move), F2 /
  double-click open the cell's content (Edit mode: Left / Right / Home / End move the caret), Enter /
  Tab commit and move, Escape cancels, a click elsewhere commits. The editor is an overlay with a caret.
- Fill handle at the current range's corner: dragging it previews the reach (down / up or left / right,
  whichever is further), the release reports `Fill` with the range.
- Clipboard: Ctrl+C / Ctrl+X put the current range on the clipboard as tab-separated text AND an HTML
  table (`ClipboardContent.html`) from the data callback (a whole column is clipped to the data);
  Ctrl+V hands the clipboard text to the app (`Paste`).
- Delete reports `Delete`; `read_only` turns off edits, fill, paste and delete.
- One set of handlers on the grid node; the grid hit-tests itself from the pointer position (cells carry
  no callbacks): `LeftMouseDown` (+ pointer capture), `MouseMove`, `MouseUp`, `DoubleClick`, `Scroll`.
- THE APP OWNS THE STATE: every `CellGridEvent` carries the next `CellGridView` (selection, scroll, edit
  text and caret, drag) plus what to do (commit, fill, resize, paste...). The app stores it and rebuilds.
- a11y: the grid node is one Tab stop with role `Grid`, its name, and the active cell's A1 name as its
  value; rows are `Row` with `row_index`; the headers `ColumnHeader` / `RowHeader`; cells `GridCell`
  with their whole-sheet `row_index` / `column_index`, `Selected` when selected.
- Looks: `themes::flat::cell_grid` (Excel 2010) and `themes::flora::cell_grid`, appended at the end of
  both theme files; `None` follows the app theme (`follow_app_theme`; the callbacks are asked ONCE and
  both builds share the answers). A filled cell without its own ink gets black or white, whichever reads
  on the fill. `decl::border_right` added (border_left's twin) at the end of decl.rs.
- Registered: `pub mod cell_grid` (in place of the commented-out `spreadsheet` stub), the lint manifest
  (`label_convention::every_widget_dom`, fixture `cell_grid::fixtures::small()`), the theme-contrast
  CHROME group, and the wheel guard (`wheel_ownership`: the grid is a scroll surface, like a scroll box,
  not a closed control).

### 3. AzSheets (examples/azul-sheets, package `AzSheets`, lib `azsheets`, bin `AzSheets`)

- `engine.rs`: the `SheetEngine` trait (load/save xlsx, evaluate, undo/redo, sheets add / rename /
  delete / move / colour, cell input / value / formatted / style, style patches incl. borders, clear,
  auto-fill, insert / delete rows and columns, widths / heights / hidden rows, frozen panes, grid lines,
  extent, defined names) and its types. `ironcalc_engine.rs`: the IronCalc 0.8.3 adapter (+ mapping
  functions with tests). `fake_engine.rs`: the fake the tests drive. `ops.rs`: engine-agnostic
  selection statistics, sort, remove duplicates, filter, find, CSV export, the AutoSum range.
- `worker.rs`: the engine thread (`azsheets-engine`, 256 MB stack - IronCalc evaluates recursively and a
  ~3000-cell chain overflows a normal stack), messages in order; every reply carries a `Snapshot` of the
  window in view (cells, deduplicated styles, widths, heights, frozen panes, grid lines, extent, the
  selection's statistics, names, undo state). `Command::SumRange` added for AutoSum.
- `lib.rs` (the UI): the UI thread NEVER blocks: a callback puts an `EngineMsg` on the engine's channel
  (ordered) and starts one short azul `Thread` that waits for the reply, does the save / export file I/O
  through the Drive, and writes it back; replies older than the newest applied are dropped. The window:
  `ShellThemeScope` > `DocumentShell` with the app-drawn `Titlebar` (`WindowDecorations::NoTitle`), the
  ribbon (FILE -> backstage; HOME: clipboard + undo / redo, font, alignment, number formats + decimals,
  styles + borders, cells incl. sheet insert / delete / rename / move / tab colour, editing: AutoSum,
  fill down / right, sort, filter, find, clear; INSERT: chart placeholder, function; FORMULAS: Insert
  Function, AutoSum, Name Manager, define name, Calculate Now; DATA: sort A-Z / Z-A, filter / clear,
  remove duplicates, export CSV / PDF; VIEW: gridlines, headings, freeze panes / top row / first column
  / unfreeze, zoom, flat / flora, light / dark), the formula bar (name box = go to "B7", "B3:D6",
  "Sheet2!A1", or define a name for the selection; fx; the formula field editing the same text as the
  cell; function autocomplete from a 100-function catalogue, `functions.rs`), the CellGrid, side panels
  (Insert Function by category, Name Manager, Find, Charts placeholder), sheet tabs (add, click, double-
  click renames inline, colour underline; move / colour / delete in HOME > Cells), the status bar (READY
  / CALCULATING..., the last message, Average / Count / Sum, zoom - / +). Backstage: Info, New (blank /
  Budget 2027 sample), Open (the workbooks in the data folder + browse for an .xlsx), Save, Save As (a
  copy under a new id), Export (CSV, PDF via `Pdf::from_dom_in_callback`), Close, About. Shortcuts:
  Ctrl/Cmd+S, Z, Y, Shift+Z, B, I, U, F, O, N, F9, Escape.
- Files (the S3 split): `sheets/<uuid>.xlsx` + `sheets/<uuid>.json` (title, zoom, sheet, active cell,
  top-left; IronCalc keeps widths and frozen panes in the xlsx itself) through azul-storage's
  `LocalDrive` rooted at `AZSHEETS_DATA`, else `<user data dir>/Azlin`; exports to `exports/`. All file
  I/O on azul Threads.
- `--sample` opens the Budget 2027 workbook (Summary with SUMs, frozen rows, number formats, a
  `GrowthRate` defined name; Monthly; Assumptions). `--open file.xlsx`, `--screen workbook |
  backstage-info | backstage-new | backstage-open`, `--theme flat|flora`, `--mode light|dark`, `--size
  WxH` (`args.rs`, tested).
- `model.rs`: the UI arithmetic without azul (fetch spans with overscan - a small sheet fetched whole -,
  fill targets, decimal steps, status-bar numbers, colours, auto-fit width, the internal clipboard's
  TSV via the csv crate), tested.
- stdout lines for scripts: `AZSHEETS_READY`, `AZSHEETS_REPLY`, `AZSHEETS_CELL <A1> <text>`,
  `AZSHEETS_STATS count=.. sum=..`, `AZSHEETS_FROZEN r c`, `AZSHEETS_SAVED <id>`, `AZSHEETS_OPENED <id>`,
  `AZSHEETS_EXPORTED <path>`, `AZSHEETS_SHEETS <names>`.
- Registered: root `Cargo.toml` member, `scripts/workspace_test_members.txt`, the `dll_tests` step "Run
  AzSheets tests" (with `--release`: the 5,000-cell chain test needs IronCalc's release stack frames).

### 4. `scripts/azsheets_e2e.py`

(focus_node + text_input + Enter), checks `AZSHEETS_CELL A3 9` and the grid's text; Shift+Up twice ->

panes still frozen.

## Decisions taken (unattended) and the one question the user asked

- IronCalc pinned to `=0.8.3` (crates.io `max_stable_version` on 2026-10-01; the version the engine
  study benchmarked). The API was read from the 0.8.3 crate sources.
- Whole-cell scrolling instead of a native scroll box with spacers. Mid-run the user asked whether I know
  the infinity demo (`examples/rust/src/infinity.rs`, 1M rows on `Dom::create_virtual_view`): yes - it
  keeps the row band in a VirtualView with the row numbers inside the rows and avoids horizontal
  scrolling (`overflow-x: hidden`), because a header outside the view cannot follow a native horizontal
  scroll (azul treats `position: sticky` as relative). I offered a hybrid (the scrolled rows in a
  VirtualView for pixel-smooth vertical scrolling, columns stepped by whole cells) and kept the whole-
  cell design pending an answer. The geometry, navigation and hit testing are pure functions, so the
  hybrid would replace `geometry()`'s vertical axis and the wheel handler only.
- Sort / remove duplicates move cell INPUTS through one paste (one undo step): formulas keep their text
  (references are not rewritten) and styles stay (IronCalc has no sort; `paste_from_clipboard` with a
  serde-built `ClipboardCell` is the follow-up that would move styles and rewrite references).
- The ribbon's Copy / Cut / Paste use an internal clipboard (range + inputs); Ctrl+C / X / V on the grid
  use the system clipboard (TSV + HTML). azul has no API to read the system clipboard outside a paste
  event.
- excel.md questions answered by the build: 2 (find, sort: app-side over the engine, sort = one undo
  step), 3 (charts: none; an INSERT > Chart placeholder panel says so), 4 (PDF: the used range up to 500
  x 26 cells as a table, A4, `exports/<title>.pdf`), 7 (Insert Function inserts the call, no live
  result), 8 (whole-cell scrolling, no virtual extent). Open: 1 (font family), 5 (ODS), 6 (second
  window), 9 (incremental recalculation).
