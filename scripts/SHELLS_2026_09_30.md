## What was built

### `layout/src/widgets/shells/` (one file per piece, `mod.rs` re-exports)

ONE Office-like design (Outlook 2010 / Windows Explorer), `ShellLook` per theme
(`themes::flat::shell_look` / `themes::flora::shell_look`, appended at the END of each theme
file under `// ==== shells ====`), merged per part (`follow_look`, `theme_blocks::follow_props`)
so every shell is built ONCE and the app's slot content is never cloned. Structure lives in the
shells' `*_BASE` statics (R5), paint and metrics in the look. Every piece: a `#[repr(C)]`
builder with `create*`, `with_*` / `set_*`, `swap_with_default`, `dom(self) -> Dom`,
`theme: OptionUiTheme` (pin, or follow the app theme), both modes through `decl::themed_*`.

Shared pieces:
- **`OfficeShell`** (`office_shell.rs`): title row (`<header>#shell-title`) | ribbon row
  (`#shell-ribbon`) or the full-window backstage (`#shell-backstage`) | the body: N panes between
  nested `SplitPane`s (a pane with `width` is a RAIL outside the splits), the right bar
  (`<aside>#shell-right-bar`) | a bottom pane on a vertical splitter | status row
  (`<footer>#shell-status`). Panes are `<nav>` / `<main>` / `<aside>` / `<section>` by
  `ShellPaneKind` (landmarks: `AccessibilityRole` has no Navigation / Main / Region, the
  element type gives them), named by their label, a keyboard stop with a focus ring. **F6 /
  Shift+F6** cycle the panes at WINDOW level (`EventFilter::Window(VirtualKeyDown)` on the root,
  as the Backstage's Escape): the pane holding the focus (walked up from
  `get_focused_node_for_seat(0)` by DOM id) or the last one reached, then the next / previous,
  wrapping; `prevent_default`; `on_pane_focus(index)`. Ctrl / Alt / Cmd + F6 are left alone.
  Splitter drags report `on_pane_resize(pane_index, ratio)`.
- **`ShellNavigationPane`** (`navigation_pane.rs`): a `<nav>` of a header slot, collapsible
  GROUPS (the `Accordion` in its Groups variant, a `TreeView` per group), a MODULE SWITCHER of
  big buttons (PageTabList / PageTab, roving tabindex: Up / Down / Home / End, Enter or a click
  selects, badge via `Badge`) and a collapse chevron; `collapsed` renders the strip of module
  icons (each still a tab named by its label). ONE callback: `on_event(ShellNavigationPaneEvent
  { group, index, kind, expand })` with kinds GroupToggled / NodeClicked / NodeToggled /
  ModuleSelected / CollapseToggled; the app owns every state and rebuilds. **For MAILWIDGETS**:
  the API is general (groups + tree + module switcher); S4's navigation slot takes its `dom()`.
- **`ShellCommandPalette`** (`command_palette.rs`): an overlay (backdrop + Dialog panel) with a
  search `TextInput` and the matching commands as roving rows (Up / Down / Home / End, Enter runs,
  Escape closes; in the field Enter runs the first match, Down goes to the rows, Escape closes);
  `palette_matches` = case-insensitive subsequence ("nmsg" finds "New message"), matched against
  "Category: Label". Callbacks: `on_query(String)`, `on_run(command_index)`, `on_close`.
  Closed = an empty node with `__azul-native-command-palette-closed`.
- **`ShellSettingsLayout`** (`settings_layout.rs`): search row | `<nav>` categories (roving
  tabs, `on_category(index)`) | `<main>` sections (`<section>` titled, the app's content); a
  non-empty search hides the sections whose title does not match (`on_search(String)`).
- **`ShellEmptyState`** (`empty_state.rs`): icon, one line, detail, an action `Button`; a
  Grouping named by its line; grows and centres itself in its pane.
- **`ShellThemeScope`** (`theme_scope.rs`): the app's root: the theme's ground + ink + font, the
  theme marker class, `__azul-accent-<name>` and the accent family as custom properties
  (`--az-accent`, `-deep`, `-soft`, `-glow`, `--az-on-accent`, the night values under the dark
  mode) - `ShellThemeAccent::{Blue, Leaf, Plum, Clay, Slate}` (flora.css's ramps),
  `colors(dark)` for Rust. (The engine's build-scope guard `azul_core::app_theme::ThemeScope`
  is a different thing; the app THEME itself stays `AppConfig::with_theme` /
  `CallbackInfo::set_theme`.)

### Engine / widget bugs found (root causes)

1. **`tree_view::LABEL_STYLE` shipped a dark text twin with no light half** - masked by two
   path-bound entries in `widgets::theme_pairs::KNOWN_HALF_PAIRS`, so it failed the pair lint
   wherever the tree is embedded at another path (the navigation pane). Fixed at the root: the
   label declares its light ink (`TEXT_COLOR`, the container's own, which it inherited anyway)
   beside the twin; the two masks are gone (RED: masks removed in 48f139892; GREEN in 4bb2f0855).
2. Twin helpers (reported, not merged): `themes::decl` and `themes::style_kit` are two sets of
   the same declaration builders (`fill`/`bg`, `themed_fill`/`themed_bg`, `padding`, `radius`,
   `focus_halo`, ...); the fresh widgets (tile, details pane, address bar, the shells) use `decl`.
   Two per-widget "no duplicate property" lints exist (`radio_group::no_duplicate_properties`,
   `popover::the_panel_style_has_no_display_toggle_and_no_duplicates`); the shells' lint in
   `shells/mod.rs` is a third shape (per node, conditions-aware) - a shared `theme_checks`
   helper would unify them.
3. `backstage.rs` calls the user's callbacks as `(cb)(refany, info)` (house rule: `.invoke`);
   not touched.

S4 (`__azul-native-command-palette-panel` in the tree), Escape closes it; `set_theme flora` +
