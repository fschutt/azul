## What was built

1. **`TerminalView` widget** (`layout/src/widgets/terminal_view.rs`, registered in `widgets/mod.rs`): the surface of a
   terminal - a grid of styled runs (16 / 256 / true colour, bold, dim, italic, underline, strike, inverse, hidden),
   a cursor (block with its character in the ground colour, hollow, underline, bar), a selection wash, a scroll bar.
   - GENERIC OVER ITS DATA: a data callback `(RefAny, TerminalGridSize) -> TerminalScreen` answers with the rows in
     view for the grid the view has room for (a new grid = the app's cue to resize the engine and the PTY).
   - SCROLLBACK VIRTUALIZED: the view is a `VirtualView` HOST (the map widget's pattern: an outer node with the
     handlers + the shared data as its dataset, a merge callback, a VirtualView child that renders), so it knows its
     own bounds and PTY output re-renders ONLY the view (`trigger_all_virtual_view_rerender`, no window rebuild).
     Scrolling inside it is the scroll-window pattern in WHOLE LINES (cell_grid / data_table): the position is the
     engine's display offset; the wheel (cell_grid's `take_wheel`), the scroll bar (data_table's `thumb`, now
     `pub(crate)`) and Shift+Page Up / Down / Home / End move it. Only the rows in view are ever built; 100k or 10M
     lines cost the same, no f32 px extent.
   - INPUT, as pure tested functions (`TerminalModes::encode_key / encode_text / encode_paste / encode_mouse /
     encode_focus`): xterm cursor keys (CSI / SS3 in application cursor mode, `CSI 1;m` with modifiers), tilde
     codes, F1-F20, C0 controls, Alt as ESC prefix (when the user wants Meta; AltGr = Ctrl+Alt left to the layout),
     Cmd keys left to the app, the application keypad, typed text as UTF-8, bracketed paste (ESC stripped so a paste
     cannot close the bracket), X10 / UTF-8 (1005) / SGR (1006) pointer reports per mouse mode (1000 / 1002 / 1003),
     focus reports (1004). Copy / paste chords: Cmd+C / Cmd+V on macOS, Ctrl+Shift+C / V elsewhere (Ctrl+C stays the
     interrupt; Ctrl+Shift+letter otherwise left to the window off macOS). Selection gestures (press / drag, Alt =
     block, double-click = word) and the wheel (scrolls, or is reported, or arrow keys on the alternate screen).
   - COLOURS from the theme: `TerminalPalette` (16 ANSI + ink / ground / cursor / selection, each a light / dark
     pair), `TerminalPalette::flat()` (One Half Light by day, Campbell at night) and `::flora_ink()` (the planning
     doc's "Flora ink": `#211F1B` / `#E4E1D6`, dark room `#141414` / `#E2E2E2`, ANSI from the accent families),
     both APPENDED to `themes/flat.rs` / `themes/flora.rs` under a `// ==== terminal_view ====` banner. The view
     uses the app theme's palette unless the app gives one; mode switches need no rebuild (themed pairs).
   - In the widget manifest (label convention, theme pairs, contrast: CHROME group) and the wheel-ownership list.
2. **Engine fix - a terminal could not paste** (root cause): `core/src/events.rs` gave the paste chord to the engine
   only on a text-editing focus or over a selection, and no callback can READ the clipboard (`get_clipboard_content`
   only answers inside a Paste event). Now `InputInterpreterState::focus_hears_paste` (the focused node has a
   `Focus(Paste)` callback - `getters::node_has_callback_for`), set by the dll shell and the e2e runner, makes the
   paste chord the engine's paste (the clipboard read + the deferred Paste event the node prevents). Copy / cut /
   select all are unchanged (a terminal's Ctrl+C / Ctrl+A stay its keys). RED test in `core/src/events_test.rs`.
3. **AzTerm** (`examples/azul-term`, package `AzTerm`, lib `azterm`, bin `AzTerm`, registered):
   - `vt.rs`: alacritty's `Term` read as the view's `TerminalScreen` - at the display offset (`Line(-n)` is history,
     reading never moves the view), runs of one style AND one width class (a wide character its own 2-column run,
     spacers skipped, zero-width marks kept), trailing blanks dropped, the soft wrap, colours, attributes, the cursor
     in view (hidden when hidden or scrolled out; Beam = Bar), the selection in view rows clipped, TermMode as
     TerminalModes.
   - `session.rs`: `Session::spawn` = `alacritty_terminal::tty::new` (forkpty-equivalent / ConPTY) + its `EventLoop`
     thread + `Notifier`; resize = `Term::resize` + `on_resize` (TIOCSWINSZ, once per change); `Session::replay` =
     a recording fed into a `Term` with no PTY that echoes typing (`--sample`, deterministic E2E). `Signals`
     (atomics + the title) polled by a 16 ms UI timer; a program's answers (`PtyWrite`, e.g. `CSI 6n`) go straight
     back to the PTY.
   - `lib.rs`: the S8 `DeveloperShell` - activity bar (new tab, settings), side bar of tabs (Button toggled = the
     active one), the TerminalView of the active tab in a positioned pane, the status bar (tab, grid, scrollback,
     UTF-8); the data callback resizes the session and answers `vt::screen`; the event callback writes bytes,
     scrolls (`scroll_display`), selects (alacritty `Selection` via `viewport_to_point`), copies
     (`selection_to_string` -> `set_clipboard_content`); window keys Cmd / Ctrl+Shift + T, W, ], [, =, -; appkit
     args / settings page / About; `ShellThemeScope` (slate accent); flat + flora x light + dark through the palette.
   - `sample.rs` (a cargo build, git status, a listing, the 16 / 256 / true colours; a 5,000-line log), `ids.rs`
     (`__azterm_` ids).
   - `scripts/azterm_e2e.py`: sample sessions, typing echoed, a second tab with > 4,000 lines of scrollback,
     Shift+Page Up, tab switching, dark mode, screenshots.

## Crates (new, in examples/azul-term/Cargo.toml only)

- `alacritty_terminal = "0.26"` (0.26.0, Apache-2.0): the VT engine AND the PTY. Why: the xterm-compatible state
  machine Alacritty and Zed's terminal run on; grid + scrollback ring indexed by `Line(-n)` (read a window without
  mutating), TermMode for the encoders, a Selection that rotates with output, the display offset kept stationary when
  output arrives while scrolled up; its `tty` is the PTY on Unix and ConPTY on Windows with a reader thread.
  Rejected: `vt100` (scrollback reads need `set_scrollback` mutation, no selection / damage), `termwiz` (heavy; the
  terminal model wezterm-term is not on crates.io), `vte` alone (only a parser), `portable-pty` (a second crate with
  nix 0.28 / filedescriptor / serial2 when alacritty's tty already does it).
- Pulled in, NOT yet in Cargo.lock (cargo-vet exemptions for the parent): `alacritty_terminal 0.26.0`, `vte 0.15.0`,
  `rustix-openpty 0.2`, `signal-hook 0.4.x` (unix), `miow 0.6`, `windows-sys 0.59` (windows). Already in the lock:
  base64 0.22, bitflags 2, home, libc, log, parking_lot, polling 3, regex-automata 0.4, unicode-width 0.2, piper.

## api.json (for `azul-doc autofix add`; module `widgets` unless noted)

All in `azul_layout::widgets::terminal_view::*`. Constructors are `create*`; every struct `repr(C)`.
- `TerminalColor` (enum repr(C, u8), Debug Clone Copy PartialEq Eq Hash Default): `Foreground`, `Background`,
  `Indexed(u8)`, `Rgb(ColorU)`.
- `TerminalStyle` {fg: TerminalColor, bg: TerminalColor, bold, dim, italic, underline, strikethrough, inverse,
  hidden: bool} (Copy, Eq, Hash, Default); `create()`, `colored(fg, bg)`.
- `TerminalRun` {text: String, columns: u32, style: TerminalStyle}; `create(text: String, columns: u32, style)`.
  + `TerminalRunVec` (module vec), `OptionTerminalRun` (module option).
- `TerminalLine` {runs: TerminalRunVec, wrapped: bool}; `create(runs: TerminalRunVec)`, `plain(text: String)`;
  `text(&self) -> String`, `columns(&self) -> u32`. + `TerminalLineVec`, `OptionTerminalLine`.
- `TerminalPoint` {line: u32, column: u32}; `create(line, column)`.
- `TerminalSelection` {start: TerminalPoint, end: TerminalPoint, block: bool}; `create(a, b)`, `create_block(a, b)`.
  + `OptionTerminalSelection`.
- `TerminalCursorShape` (enum): Block, HollowBlock, Underline, Bar, Hidden.
- `TerminalCursor` {line: u32, column: u32, shape}; `create(line, column, shape)`, `hidden()`.
- `TerminalMouseMode` (enum): Off, Click, Drag, Motion. `TerminalMouseEncoding` (enum): Default, Utf8, Sgr.
- `TerminalMouseButton` (enum): Left, Middle, Right, WheelUp, WheelDown, None. `TerminalMouseAction` (enum):
  Press, Release, Motion.
- `TerminalModes` {mouse, mouse_encoding, application_cursor, application_keypad, bracketed_paste,
  focus_reporting, alternate_screen, alternate_scroll, alt_sends_escape: bool}; `create()`;
  `encode_key(&self, key: VirtualKeyCode, modifiers: KeyModifiers) -> U8Vec`, `encode_text(&self, text: String)
  -> U8Vec`, `encode_paste(&self, text: String) -> U8Vec`, `encode_mouse(&self, button: TerminalMouseButton,
  action: TerminalMouseAction, point: TerminalPoint, modifiers: KeyModifiers) -> U8Vec`,
  `encode_focus(&self, focused: bool) -> U8Vec`.
- `TerminalPalette` {black, red, green, yellow, blue, magenta, cyan, white, bright_black, bright_red, bright_green,
  bright_yellow, bright_blue, bright_magenta, bright_cyan, bright_white, foreground, background, cursor, selection:
  ChartColor}; `uniform(c: ChartColor)`, `flat()`, `flora_ink()`, `of_app_theme()`; `ansi(&self, index: u8) ->
  ChartColor`, `color_of(&self, color: TerminalColor) -> ChartColor`. + `OptionTerminalPalette`.
  (`TerminalStyleColors` and `colors_of` are Rust-only.)
- `TerminalGridSize` {columns: u32, rows: u32}; `create(columns, rows)`, `fitting(width: f32, height: f32,
  cell_width: f32, line_height: f32)`.
- `TerminalScreen` {lines: TerminalLineVec, selection: OptionTerminalSelection, history: u32, scroll: u32, cursor:
  TerminalCursor, modes: TerminalModes} (custom impl Default); `create(lines: TerminalLineVec)`, `empty()`;
  `selected_text(&self) -> String`.
- `TerminalSelectionKind` (enum): Simple, Word, Line, Block.
- `TerminalViewEventKind` (enum): Input, Scroll, SelectStart, SelectExtend, SelectEnd, SelectClear, Copy.
- `TerminalViewEvent` {bytes: U8Vec, scroll: u32, point: TerminalPoint, kind, selection_kind, right_half: bool};
  `create(kind)`, `input(bytes: U8Vec)`, `scrolled(scroll: u32)`.
- Callbacks (module callbacks, like DataTable's): `TerminalViewOnEventCallbackType` = `extern "C" fn(RefAny,
  CallbackInfo, TerminalViewEvent) -> Update` (wrapper `TerminalViewOnEvent` / `OptionTerminalViewOnEvent`,
  `TerminalViewOnEventCallback`); `TerminalViewDataSourceCallbackType` = `extern "C" fn(RefAny, TerminalGridSize)
  -> TerminalScreen` (`TerminalViewDataSource` / `OptionTerminalViewDataSource`, `TerminalViewDataSourceCallback`,
  the ctx_field form like `DataTableDataSourceCallback`).
- `TerminalView` {data_source, on_event, accessibility_name: String, id: String, font_size: f32, line_height: f32,
  palette: OptionTerminalPalette} (custom impl Default); `create()`; `set_data_source` / `with_data_source(data:
  RefAny, callback: TerminalViewDataSourceCallbackType)`, `set_on_event` / `with_on_event(data, callback:
  TerminalViewOnEventCallbackType)`, `set_palette` / `with_palette(palette)`, `set_font_size` / `with_font_size(px:
  f32)`, `set_line_height` / `with_line_height(px: f32)`, `set_accessibility_name` / `with_accessibility_name(name:
  String)`, `set_id` / `with_id(id: String)`, `swap_with_default`, `dom(self) -> Dom`.
- Rust-only (keep out of api.json): `xterm_256_color` (free fn), `TERMINAL_FONT_SIZE`, `TERMINAL_WHEEL_LINES`.
- AzTerm uses `TerminalScreen::empty`, the struct fields above, `TerminalLineVec::from_vec`,
  `TerminalRunVec::from_vec`, `OptionTerminalSelection`, and the two callback types from `azul::callbacks`.
