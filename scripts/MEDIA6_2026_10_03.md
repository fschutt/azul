# MEDIA6 - AzPhoto, AzVideoCut, AzPaint finished; text into pixels (2026-10-03)

Branch `wt/media6` from `25d78e309`. Nothing was compiled (house rule); every Rust edit was
parse-checked with `rustfmt --check`, every Python script with `py_compile`. The LOOK and two
diagnoses ran the prebuilt binaries (aa59b2d84) headless through `run_capped.sh`.

## 1. What was built

### Engine (owned by MEDIA6)
- **Text into pixels** (`layout/src/cpurender/text_raster.rs`, new). `TextRasterStyle` (family,
  size, line height, colour, bold, italic). The lines are shaped by the text engine
  (`shape_text_for_parsed_font`) and rasterised by cpurender's own glyph path (`render_text`, now
  `pub(super)`) in grayscale into a transparent pixmap. Entry points:
  - `text_image_with(fc, text, style)`: a straight-alpha RGBA8 image as big as the line boxes.
  - `draw_text_with(fc, image, text, style, x, y)`: source-over into an RGBA8 / BGRA8 image,
    straight or premultiplied.
  - `text_image` / `draw_text`: the same on a per-thread system font cache.
  - `CallbackInfo::text_image`: uses the window's own `font_manager.fc_cache`, so there is no
    second font scan.
  - The font resolves as family + bold/italic, then family, then `sans-serif`, each through
    fontconfig's fallback.
  - RED: `layout/tests/a_text_rasterises_into_a_raw_image.rs` (exact pixels with the Azul Mock
    Mono memory font).
- **Engine bug fixed: an image patched in place came back stale.** `window.rs`
  `apply_image_change` copy-on-wrote the root display list (`Arc::make_mut`). The solver's
  structural-identity cache (`layout_cache.cached_display_list`) kept the pre-patch Arc, so the
  next cache-hit relayout (a hover change, a `RefreshDom` without structural change) served the
  replaced image back. The canvas's inputs had not changed, so nothing redrew it until a resize.
  - The CSS-transition patch path already swapped the patched Arc into the cache; the image path
    now does the same (ROOT only, and only when the cache was serving that list).
  - This hit every callback canvas frame and every same-size `change_node_image(_rect)`.
  - RED: `layout/tests/an_image_patched_in_place_survives_a_cached_relayout.rs` (both routes).
- **`RawImage::fit_within(w, h, max_w, max_h) -> PhysicalSizeU32`** (core): the thumbnail fit
  rule as a size, so the C API can replace AzVideoCut's private copy (DEDUP_OFFICE D15). RED in
  `core/src/image_scale.rs` tests.

### AzPhoto
- **Text tool** (was a stub). Click to start a text, type in the options bar's field, and the
  text shows as a live layer. Enter or Commit places it as one History state "Text"; Escape drops
  it; another tool, a click elsewhere or any other edit commits it. Font, size, bold, italic and
  the foreground colour restyle it live.
- **Live Move tool.** The layer follows the pointer while dragging: a live edit, reset to the
  layer as it was on every move, so nothing is lost off the edge. One "Move" state on release.
  The engine gained `begin_live` / `live_reset` / `apply_live` / `end_live` / `cancel_live` /
  `pixel_target`.
- **Tool rail.** The chosen tool is `Button::with_toggled`; pixel tools on an adjustment or a
  locked layer are `with_disabled` with a reason.
- **Canvas movement on `MouseMove`.** `MouseOver` fires on ENTRY since 2a7712f66, so brush,
  marquee, lasso and move got no points between press and release.
- **Exports go into the data tree:** `photo/<uuid>/exports/<name>.png|jpg`, written by the export
  job through the Drive. No save dialog, no `--export-dir`.
- **appkit:**
  - switches: `--data-dir`, `--mode` with `system`, a bare image argument
  - the kit's data root, app config and window (`--shot`)
  - the settings page (Edit > Settings, Mod+, and F1; theme and mode remembered)
  - ABOUT and a SHORTCUTS table
- **Dialogs:** every sheet is azul's modal `Dialog`; Help > About is the standard `AboutDialog`.
- **CloseGuard.** "Save changes?" while modified. Save writes, then `close_window` once the job
  finished; Don't Save; Cancel.
- **`__azphoto_` ids.** Every id and marker is a const in `src/ids.rs`; the tool ids are prefixed
  in `Tool::dom_id`.
- **D16: the look follows the theme.** The palette holds theme-following values: tints over the
  scope's ground, `system:` lines and text, `var(--az-accent-soft)` selection, a raised tint for
  the document tab. The accent is Clay (theme_scope.rs: "Slides, Video editor, Music, Photo").
- **History buttons fit (P3).** Measured on the prebuilt binary at 1400 x 900: the History
  section ran to y 890 against a panels column ending at 877. Undo / Redo moved into the
  section's title row.

### AzVideoCut
- **The editor fills the window** (V1, the big one). The body had no height and kept its 8 px
  margin, and the theme scope did not grow, so every pane collapsed to 0 px and dark mode showed
  the white canvas around it. The loading screen now has its title row.
- **`fit_within`** is a one-line adapter over `RawImage::fit_within`; the bin's and the source
  monitor's scaling go through `RawImage::thumbnail` (`fit_to`) (D15).
- **Dialogs:** a running export shows the standard `ProgressDialog`, whose Cancel stops the job;
  the export form stays as the pre-step. About is the `AboutDialog` (D12).
- **appkit:**
  - switches; a bare project id replaces `--project`
  - the kit's data root (`AZVIDEOCUT_DATA` and `store::data_root` are gone)
  - the settings page with Playback and Export sections, plus the kit's Appearance, Data,
    Shortcuts and About; it replaces the hand-made dialog and the two toggles that forgot the
    choice
  - the kit's keys first in `on_key`; ABOUT and SHORTCUTS
- **Look:** `__azvideocut_` markers as consts; accent Clay.
- **Already right, verified:** exports through the Drive into `videocut/<id>/exports/`, the
  project autosaved after every edit (so no "save changes?" is needed), `UndoHistory<Sequence>`.

### AzPaint
- **The stroke is drawn while it is drawn.** Diagnosed with the prebuilt binary and
  `AZ_PAINT_DEBUG`, three causes:
  1. Movement was on `MouseOver`, so no `on_pointer_move` ran during the drag.
  2. `poke_canvas` passed the 1-based `DomNodeId` encoding as the 0-based `NodeId`, so it asked
     the node AFTER the canvas for a frame.
  3. The engine bug above.
- **Undo / redo** through `azul_appkit::UndoHistory<Vec<Stroke>>`: a stroke, an erase and a Clear
  are one step each, Clear is undoable (it was not). Edit > Undo / Redo carry Mod+Z /
  Mod+Shift+Z as menu accelerators, which the engine dispatches (headless too).
- **appkit** (new dependency, `features = ["azul"]`):
  - switches: `--screen paint|settings|about`, `--sample` (three strokes), a picture to paint
    over
  - data root, remembered look, `--size`, `--shot`
  - the settings page (Help > Settings, Mod+, and F1); Help > About is the `AboutDialog`
- **Exports into the data tree.** Export PNG (Mod+S) rasters the canvas on the CPU through
  `cpu_raster`, the same function the canvas's CPU path uses. Export SVG (Mod+Shift+S) writes the
  strokes. Both become kit file jobs on a Thread at
  `paint/exports/<stem>-<secs>-<n>.<ext>`, reported as `AZPAINT_EXPORTED <key> <bytes>`.
  Removed:
  - the save dialog
  - the `export_path` round trip through the render callback, with its `std::fs::write`
  - `FileDialog::save_bytes`
- **Look:** `__azpaint_` ids and markers as consts (no per-run `Uuid::short` markers); the canvas
  id is `__azpaint_canvas`; the body has no default margin.
- **Script lines:** `AZPAINT_RASTER <rev>` and `AZPAINT_STROKES <n>`.

### E2E
- `scripts/azpaint_e2e.py` (new): checks dark pixels along the stroke BEFORE the release, after
  it, after undo (clean) and after redo, plus PNG and SVG files under `paint/exports/`.
- `scripts/azlin_e2e.py`: `read_png` and `dark_pixels`, no third-party modules.
- `scripts/azphoto_e2e.py`:
  - `--data-dir` and the `__azphoto_` ids
  - the export checked in `photo/<uuid>/exports/`
  - a live move: canvas updates before the release, one Move state
  - a text step: the field gets "Hello", Enter, a fifth layer, one Text state
- `scripts/azvideocut_e2e.py`: `--data-dir`; the program monitor must be at least 150 px and the
  timeline at least 120 px tall, reaching the window bottom.

## 3. api.json (exact methods - never `Type.*`)

Module `image`:
- **New class `TextRasterStyle`.** External `azul_layout::cpurender::TextRasterStyle`, `repr(C)`,
  derive `[Debug, Clone, PartialEq]`.
  - struct_fields: `font_family: String`, `size_px: f32`, `line_height: f32`, `color: ColorU`,
    `bold: bool`, `italic: bool`.
  - constructor `create(font_family: String, size_px: f32, color: ColorU)`, fn_body
    `azul_layout::cpurender::TextRasterStyle::create(font_family, size_px, color)`.
  - `with_bold(self: value, bold: bool) -> TextRasterStyle`, `object.with_bold(bold)`.
  - `with_italic(self: value, italic: bool) -> TextRasterStyle`, `object.with_italic(italic)`.
  - `with_line_height(self: value, line_height: f32) -> TextRasterStyle`,
    `object.with_line_height(line_height)`.
- **`RawImage.from_text`** (static): `(text: String, style: TextRasterStyle) -> OptionRawImage`,
  fn_body `azul_layout::cpurender::text_image(text, style)`.
- **`RawImage.draw_text`**:
  `(self: refmut, text: String, style: TextRasterStyle, x: f32, y: f32) -> bool`, fn_body
  `azul_layout::cpurender::draw_text(object, text, style, x, y)`.
- **`RawImage.fit_within`** (static):
  `(width: u32, height: u32, max_w: u32, max_h: u32) -> PhysicalSizeU32`, fn_body

## 4. Least sure to compile

1. **`AzString::from_const_str` in the GENERATED crate (cross-task, read first).** PLAN.md
   mandates `const X: AzString = AzString::from_const_str("__azmail_x")`, but
   `target/codegen/dll_api_external.rs` (aa59b2d84) has no `from_const_str` on the external
   `AzString`. Only my three apps use it so far: `examples/azul-photo/src/ids.rs`, AzVideoCut's
   three markers, AzPaint's `mod ids`. Every wave-6 app that follows the rule will need it.
   - Fix: the Rust bindings generator emits, for `AzString`,
     `pub const fn from_const_str(s: &'static str) -> Self { Self { vec: AzU8Vec { ptr:
     s.as_ptr(), len: s.len(), cap: s.len(), destructor: AzU8VecDestructor::NoDestructor,
     flags: 0 } } }`, mirroring `css/src/corety.rs:221` and `macros.rs:146`.

   - `ParsedFont::from_bytes(..)?.with_source_bytes(Arc<FontBytes>)`
   - `fc.get_font_by_id` returning `OwnedFontSource::{Disk(FcFontPath), Memory(FcFont)}`
   - `FontManager::<FontRef>::new(FcFontCache::default())` then `insert_font(FontId::new(), ..)`;
     `render_text` finds it via `resolve_font_by_hash(parsed.hash)`

## 6. Seen broken, not fixed (owners)

- **AzReview** `examples/azul-review/src/ui.rs:547`: movement on `HoverEventFilter::MouseOver`.
  Same bug as Paint and Photo: since 2a7712f66 it fires only on entry. Owner: AzReview's task.
- **Text raster limits:**
  - LTR only (`BidiDirection::Ltr`), no wrapping, no alignment.
  - A placed text is pixels, not a re-editable text layer (Photoshop's are live).

  - The header is a fixed dark bar in every theme and mode (deliberate, unchanged).
  - No "save changes?": the strokes are not a document, only exports are written.

  dialog ("Export now" in export.html) while the collapsed layout hid it. Not re-verified.
