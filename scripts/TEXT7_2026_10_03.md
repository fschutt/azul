## What was built, item by item

1. **text-indent narrows the first line box (pdfocr, top priority).** Root cause as the brief said:
   the greedy path broke the first line against the full width and `position_one_line` then added
   the indent to the pen after justify had spread the line over the full width. Now the indent is
   GEOMETRY of the line box (CSS Text 3 s8.1, "a margin applied to the start edge of the line box"):
   - ONE choice of which lines are indented, `text3::cache::text_indent_of_line(constraints,
     is_first_formatted_line, is_after_forced_break)` (first formatted line; `each-line` also after a
     forced break, never after a soft wrap; `hanging` inverts), and ONE geometry,
     `text3::cache::indent_line_box(&mut LineConstraints, indent, direction)`: the start-side
     segment (leftmost in ltr / vertical, rightmost in rtl) starts `indent` further in and is that
     much narrower (wider for a negative indent) BEFORE the line is broken. The breaker fills,
     justify spreads over, and the alignment places the line in what is left. `position_one_line`
     no longer adds the indent (its `is_after_forced_break` parameter is gone).
   - The first formatted line is the PARAGRAPH's: perform_fragment_layout reads it from the cursor
     (at the start of the content), so a continuation fragment of a flow chain is not indented.
     The multi-column balance probe breaks its dry-run lines the same way.
   - Knuth-Plass uses both helpers: the DP narrows a line after a forced break under `each-line`
     (was a TODO), and its positioner justifies and aligns inside the indented line box (it had the
     same "justify over the full width, then shift" bug).
   - Intrinsic sizes count the indent (Chrome does; a percentage counts 0): `measure_intrinsic_widths`
     adds each line's indent to max-content and to the first word of a line for min-content (with
     no indent the scan is bit-identical to before). Without this a float / `min-content` box with
     a text-indent would now wrap its first line. sizing.rs used to hand the scan
     `UnifiedConstraints::default()`; it now passes the IFC root's indent through ONE resolver,
     `solver3::getters::resolve_text_indent` (length vs font sizes / viewport, % vs containing
     block or 0 when intrinsic, DOM-declared fast path inside), which also replaces
     `fc::translate_to_text3_constraints`' inline copy.
   - Tests: pdfocr's three (`a_left_aligned_first_line_ends_inside_the_paragraph`,
     `a_justified_first_line_ends_inside_the_paragraph`, `an_indent_in_points_narrows_the_first_line_too`)
     + justify flush with the line below, negative indent, hanging, only-the-first-line after `<br/>`,
     `each-line`, rtl, float shrink-to-fit, `width: min-content`. The existing
     `the_first_line_of_a_paragraph_starts_text_indent_further_in` (start positions) is unchanged
     by construction (the first line still starts at the indent).
2. **A run shaped before its font loads stays invisible.** The per-item shaping cache keys a group on
   text + layout style + bidi level + script, never on the loaded faces, and stored the empty result
   of a shaping whose face was not loaded yet. Now the deficit is also counted per thread
   (`note_font_shape_deficit`, the one place both counters move) and the miss path caches a group
   only if its shaping had every face. The multi-face path skipped a segment whose face was not
   loaded WITHOUT counting it - it is counted now (the frame report's `font_shape_deficit` may
   report it where it silently read 0).
3. **bolder / lighter relative to the parent (CSS Fonts 4 s2.2).** Both were fixed weights
   (900 / 300) AND the keyword itself was inherited: every `<b>` / `<strong>` (UA `bolder`) and its
   text asked for Black, a `<b>` in a `<b>` was no bolder. Now:
   css `StyleFontWeight::computed(self, parent)` (the table, ONE place) + `is_relative()`;
   core compact builder: a node's own keyword slot is computed against its parent's (pre-order)
   right after the font-size step, so children copy a number; core cascade:
   `compute_inherited_values` resolves the keyword against the parent's computed weight (like
   font-size) and the raw parent-to-child propagation drops a relative winner
   (`inherits_its_computed_length`); layout `getters::get_computed_font_weight`, the one weight
   reader of the three sites (run style, chain collection, its dedup key) - the compact cache is
   computed already, the cascade (pseudo-states) hands back the node's own keyword, resolved there.
4. **dll font-index-style off-by-one** (dll/src/desktop/shell2/common/layout.rs ~1558): the
   GeolocationProbe permission subscription used `NodeId::from_usize(i)` (1-based FFI decoder) on
   an `enumerate` index, naming the node BEFORE the probe. One line: `Some(NodeId::new(i)).into()`.
   Test: a headless dll test (new `headless/tests/permission_probe.rs`, Linux only - see below).
5. **line-height 19px -> 19.55.** Already fixed in wave 5 (TEXTENG 4c4ea42d9: the strut's synthetic
   0.8 / 0.2em split; the ledger item predates it - pdfocr probed azul at 2e92c759b). Read the
   current path: glyph boxes and the strut both go through `LayoutFontMetrics::line_metrics_px` +
   `split_leading` of the same first available face (MAILENG6). Pinned on SCREEN (TEXTENG pinned
   paper): five lines, UA default / Helvetica / Times / Courier (the macOS +15% ascent faces) at
   11pt and 16px, plus pdfocr's positioned justified 12pt Times region with `line-height: 16pt`.
6. **line-height rem / vw / vh.** Also done in wave 5 (TEXTENG's `StyleLineHeight` enum, pinned on
   paper at a 16px root). Pinned on screen: 2rem under a 20px root (a 12px container, an 18px
   paragraph), vh / vw / vmin / vmax in an 800 x 600 window, and 5vh after the SAME LayoutWindow is
   laid out again at 800 x 800 (caches surviving, as across a resize). `table_markup` gained
   `lay_out_in(lw, markup, w, h)` (`laid_out` now calls it - no second copy).

- `css.StyleFontWeight` gains two Rust `pub const fn`s, `computed(self, parent: StyleFontWeight) ->
  StyleFontWeight` and `is_relative(self) -> bool`. They are Rust-only helpers for the cascade; if

## Seen broken, not fixed (other owners or out of scope)

  is the first child of its parent element" - `<div style="text-indent:50px">aaa<div>bbb</div>ccc
  </div>` indents "ccc" too (the anonymous IFC inherits the div's indent; fc.rs, LAYOUT7).

  first line (kp_layout drains the cursor without knowing where the paragraph started), and it
  takes its base direction from the logical items, the greedy path from `direction`.

  (`get_vertical_align_for_node` has no viewport; five callers in fc.rs / sizing.rs / getters.rs,
  LAYOUT7) - TEXTENG's open item.

  node, not tier-2 values (font-size, line-height): a stylesheet-only change of those on the same
  DOM may be served stale run styles if nothing else invalidates the warm cache (not verified;
  LAYOUT7 / PAINT7).
- `fc::convert_font_weight` keeps its static Bolder -> Black / Lighter -> Light fallback (now only
