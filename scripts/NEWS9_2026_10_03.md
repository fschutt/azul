## What was built

`examples/azul-news` (package `AzNews`, lib `aznews`, bin `AzNews`, link-dynamic azul, azul-appkit,
azul-storage, azul-pim), registered in the root `Cargo.toml`, `scripts/workspace_test_members.txt`
and a `dll_tests` step in `.github/workflows/rust.yml` (which also runs the feed server's tests).

- **Feeds** (`feed.rs` on `xmltree.rs` + `dates.rs`): RSS 0.9x / 1.0 (RDF) / 2.0, Atom 1.0 / 0.3,
  JSON Feed 1.0 / 1.1 into one model (`Feed`, `Item`: id, plain-text title, absolute link,
  author, published / updated, summary + content HTML, a 240-char excerpt, the base the content's
  links point from, picture, enclosures, categories). Malformed real feeds are read as far as
  they go: `xmltree` is a LENIENT tree on quick-xml 0.41 (a bare `&` is text, a mismatched end tag
  closes up to its element, a stray one is ignored, a cut-off feed keeps what was read, HTML's
  named references stay for the HTML parser, undeclared `media:` prefixes still match, `a < b`
  is text) after a charset step (BOM, valid UTF-8, the declaration, the HTTP charset,
  Windows-1252 last). Dates: RFC 822 in its real forms (wrong weekdays, `Sept`, named zones,
  `GMT+0200`, no zone, German weekdays), RFC 3339 / ISO 8601 variants, US dates with AM / PM.
  Titles and excerpts are plain text through azul's HTML parser (`Xml::create_from_html`, the
  engine's one entity table); text becomes HTML through `Xml::encode_text`.
- **Subscriptions / OPML** (`opml.rs`): the list IS an OPML 2.0 file (`news/subscriptions.opml`,
  folders as outlines, AzNews' feed id as `azId`); import reads any OPML leniently (nested
  folders as `A / B`, `xmlurl` in any case, title-only outlines, duplicates once); export writes
  `news/exports/subscriptions-<unix>.opml` INTO the data tree.
- **Read state** (`state.rs`): `news/feeds/<id>/state.json` (read / starred / later ids,
  `aznews.state` v1), apart from the articles so a refresh never touches the marks.
- **Library** (`library.rs`): the views (all, unread, starred, read later, folder, feed, broken),
  newest-first list with azul-pim's search, Outlook's date groups (azul-pim's `DateGroup`, moved
  there from AzMail), unread counts, mark-all, merge of a refresh (first-seen kept, articles the
  feed dropped kept inside the keep window or when starred / saved, 500 per feed, marks pruned).
- **Files** (`store.rs`): `news/subscriptions.opml`, `news/feeds/<id>/{feed.json,items.json,
  state.json}`; load / write / delete jobs for azul-appkit's file Thread (azul-storage Drive).
- **HTTP** (`fetch.rs`, `jobs.rs`): through azul-storage's one Transport seam (`AzulTransport` =
  azul's `HttpRequestConfig`, from azul Threads). A refresh is a conditional GET (If-None-Match /
  If-Modified-Since; 304 = nothing to parse), one write-back per feed as it answers. Add feed
  takes a website or feed address (`example.org` gets `https://`, `feed://` works), a web page's
  `<link rel="alternate">` feeds are found and each read for a preview. User-Agent
  `AzNews/0.1 (+https://github.com/fschutt/azul)` - no personal data (the coordinator's rule).
- **Reader view** (`reader.rs`): `article()` parses the article with `Xml::create_from_html` and
  builds a NEW Xml tree by a whitelist walk (text blocks, headings (h1 -> h2), quotes, lists,
  code, tables with colspan / rowspan, figures, captions; scripts, styles, forms, frames, media,
  svg and nav go with their content; unknown elements keep their content), links and pictures
  absolute (tracking parameters off when the setting says so), tracking pixels gone, pictures
  as `[image: alt]` placeholders unless loaded, and the reader stylesheet in its head
  (`reader_css`: serif, the chosen size and measure; colours inherited from the app theme and
  mode, sepia paper on request). Its pictures are listed by `Xml::scan_external_resources` and
  fetched + decoded (`RawImage::decode_image_bytes_any`, fitted to 1600 px) on a Thread, then put
  into the image cache under their address (`CallbackInfo::add_image_to_cache`), where the
  article's `<img src>` finds them. Shown with `Dom::create_from_parsed_xml` in azul's
  `ReadingPane` (title, feed, date, author, reading time, link; the InfoBar "Load pictures").
- **Window** (`ui.rs`): the S4 `PimShell` (`.office_shell()`, `NoTitle` + the app-drawn title
  row via azul-appkit), navigation (`ShellNavigationPane`: Articles group with badges, Feeds
  group with folders and feeds and unread badges, Broken feeds), the list (search, All / Unread,
  date groups, unread dots, stars, two lines, Show more, Mark all as read with a confirmation),
  the reading pane (article + Previous / Next / Open original / Star / Read later / Mark unread;
  Add feed; OPML import preview with checkboxes; a feed's page: rename, folder, refresh,
  unsubscribe), the toolbar, the status bar (last refresh, unread), the settings page (Reading:
  font size, line width, paper, pictures always / on click / never, strip tracking; Refresh: on
  start, every 15 min / hour / 4 hours, keep a week / month / three months), keys (j / k / s / m
  / l / o / r while no field has the focus, Mod+N / O / E, Escape), a refresh timer,
  `--sample` (42 feeds in 6 folders, 891 articles, 214 unread, two broken feeds), `--screen
  articles|add|import|feed|settings`, `--theme`, `--mode`, `--data-dir`, OPML files as arguments.
  "Open original" goes through a new shared `azul_appkit::files::open_external` (open /
  xdg-open / cmd start; web addresses and existing paths only).
- **E2E**: `scripts/aznews_e2e.py` (on `scripts/azlin_e2e.py`) against
  `examples/azul-news/scripts/feed_server.py` (a local web of feeds: RSS with ETag /
  Last-Modified and 304s, Atom, JSON Feed, a malformed feed, a 404, a web page with feed links, a
  PNG, an OPML list, POST /bump). Not run (no binary).

## Decisions

- feed-rs rejected: not in Cargo.lock (brings its own quick-xml, mediatype, regex, uuid,
  siphasher); roxmltree / azul's strict loaders refuse a whole feed for one bare `&`; azul's
  HTML parser has HTML semantics (`<link>` is void, CDATA is a bogus comment). Own parser on
  quick-xml in lenient mode (what feed-rs itself is built on).
- One HTTP client: azul-storage's Transport seam, no ureq in the app; tests use a fake web.
- The subscription list is OPML (a user-facing file the S3 bucket will hold); per-feed meta,
  articles and marks are three small JSON files (a mark is one small write).
- Feeds on documentation hosts (example.com / .net / .org, `*.example`, `*.invalid`: the
  sample's) are never refreshed (`links::is_documentation_host`).
