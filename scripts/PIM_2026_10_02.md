### One task store (B12)
- ONE format: AzTasks' `aztasks.task` v1 at `tasks/<list>/<task-uuid>.json` (decision: no rename, so
  AzTasks' files need nothing). AzCalendar's To-Do bar reads and writes it through `azul_pim::task` +
  a `LocalDrive`; AzTasks reads and writes it as before.
- Where: AzCalendar's tasks root is `azul_appkit::data::data_root(named data folder, AZTASKS_DATA, user
  data)`: with `--data` / `AZCAL_DATA` everything stays in that one folder (tests, the E2E; name the
  same folder for AzTasks to share it), else `<user data>/Azlin` - AzTasks' default root.
- Migration of the other's files: at start AzCalendar moves its old `<data>/AzCalendar/tasks/default/*.json`
  (`azcalendar.task`) into the store (list `default`, the store's copy of an id wins, old file removed);
  when both are one folder the store loader reads an old file in place, names it in `Loaded::migrated`,
  and AzCalendar (`tasks::load`) and AzTasks (`take_loaded`) write it back in the shared format.
- New To-Do bar tasks go to AzTasks' default list (its setting, else its first list in navigation order,
  else `default`); a list folder without `list.json` shows as "Tasks" for `default`. Ticking off a
  repeating task in the To-Do bar spawns its next occurrence exactly as AzTasks does (`Task::complete`).
