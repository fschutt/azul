## Built

### 1. `layout/src/widgets/chart.rs` - the Chart widget (new, ~4600 lines incl. tests)
- Kinds: `Line`, `Area` (line + 10 % wash to the baseline), `Bar` (grouped), `StackedBar`, `Scatter`, `Pie`, `Donut`.
- Data: `ChartSeries` = name + `ChartPointVec` (x, y f64) + optional own `ChartColor`; `categories: StringVec` makes x a
  category axis (point i in category i; bars AND lines at band centres, so a line and a bar over the same data line
  up). Pie / donut = series 0 over the categories; past 8 slices the rest fold into "Other".
- Axes: nice 1-2-5 ticks (`nice_step` / `nice_ticks`, ends rounded out), one unit per axis (`0 / 5K / 10K`,
  `0.0 / 0.2`), bars always from zero, stacked charts fitted to their stacks, `with_y_range` for a stable axis,
  gridlines at the y ticks, a baseline, axis titles, a title, a legend (>= 2 series, or a pie's slices; one
  series is named by the title), category labels thinned when bands are narrow.
- Drawing = the engine's existing SVG path, nothing new: the plot div carries `SvgNodeData::ViewBox{0,0,w,h}` (1 unit =
  1 px); every series is ONE node over the plot (insets 0, like the XML parser's `<path>`) with `SvgNodeData::Path`:
  lines are a STROKE (border width + colour = `stroke`/`stroke-width`, `display_list::svg_stroke_for`), bars / dots /
  wedges / area washes a FILL (background clipped to the path). Gridlines, baseline, crosshair, markers are 1 px /
  small boxes. Dots and wedges carry a 2 px surface-colour ring (the "gap" between touching marks); stacked
  segments a 2 px geometric gap; bars <= 24 px, 4 px rounded data end, square at the baseline.
- Large series: lines are M4-decimated per pixel column (`decimate_line`: first / lowest / highest / last of every
  run in a column, drawing order kept, short lines whole, non-finite points dropped); scatters keep one dot per
  occupied cell (`thin_scatter`, smaller dots past 2000). 500k points -> <= 4 per column in the path.
- Hover / click without a rebuild: the plot's last child is the overlay (one Tab stop, role `Chart`, name = title,
  description = `Chart::summary()`), holding the crosshair, one marker per series and the tooltip (the TOOLTIP
  widget's own skin, `tooltip::skin_of`... via the theme `tooltip_skin().tip`; a live region). `ChartState` (the
  overlay's RefAny) keeps the FULL data + bar rects + slices; `MouseMove` finds the point (nearest x of the nearest
  line by binary search on sorted x; nearest dot within 32 px; the bar under / over the pointer; the slice under
  it) and `show()` writes left / top / opacity with `set_css_property` and the tip text with `change_node_text`.
  `Click` (pointer, Enter / Space via the engine's activation, a11y default action) reports a `ChartSelection` to
  `on_select`; `with_selected` draws a ring in the accent. Keys: Left / Right points, Up / Down series, Home / End,
  Escape hides (only when something is shown), others left to the app; `prevent_default` on taken keys.
- Colours: `CHART_PALETTE` = the dataviz reference categorical order (blue, orange, aqua, yellow, magenta, green,
  violet, red) with dark-mode steps, VALIDATED with the dataviz validator on flat (#FFFFFF / #212529) and flora
  (#F2F1ED / #232323): every hard gate passes in both modes; light mode has 3 slots < 3:1 on the surface -> the
  relief is the legend + the table view. The `ShellThemeAccent` stones FAIL as series colours (lightness band,
  chroma floor, leaf/clay CVD dE 2.1), so the accent colours the selection ring and the focus halo only:
  `with_accent(ChartColor)` / `with_shell_accent(ShellThemeAccent)` (stone by day, glow at night via
  `ShellThemeAccent::colors`). Text never wears a series colour.
- Themes x modes: `ChartSkin` per theme (APPENDED `chart_skin()` under `// ==== chart ====` in `themes/flat.rs` and
  `themes/flora.rs`); `ChartLook::of(theme)` builds every part from the pinned skin or from both merged with
  `theme_blocks::follow_props` (stacked onto bases with `stack_parts`) - the DOM is built ONCE (no
  `follow_app_theme` double build of 500k points). Every colour is a light/dark twin pair.
- A11y: role Chart + name + summary description on the Tab stop; `with_show_table(true)` adds a `<table>` (role
  Table): a row per category, a row per point, or one summary row (points / lowest / highest / mean / last) per
  series past 100 points; a pie: category / value / share.
- Registered: `pub mod chart;` appended to `widgets/mod.rs`; `("chart", chart::fixtures::sample().dom())` appended to
  `label_convention::every_widget_dom()`; `"chart"` appended to the theme-contrast `CHROME` group.

## For other tasks / the parent
- PAINT7 (perf, no RED test written - a cache is a design choice, not a wrong pixel): every display-list build
  re-rasterises EVERY `SvgNodeData::Path` clip mask (`rasterize_svg_clip_to_r8`, an RGBA buffer of 2x the paint
  rect, then R8) and every stroke mask (`rasterize_svg_stroke_to_r8`) - nothing caches them by (path, size). A chart
  has one plot-sized mask per series (two for a line: the empty fill clip AND the stroke), so a hover that
  restyles the tooltip (a relayout + display list) re-rasterises all of them. Worth a cache keyed by the path's
  hash + paint size, or skipping the fill clip of a node that paints no background (a line's).
- The tutorial's code blocks use the Chart API, which the examples lint (`doc/src/lint_examples.rs`) checks against
  api.json: it is red until the api.json entries above are generated.
- E2E: no app shows a chart yet (the dashboard is DATATABLE7's crate), so nothing was run headless. Once merged,
  the dashboard's E2E script should: `get_node_hierarchy` -> find `__azul-native-chart-overlay`, `focus_node` it,
  key Right, `wait_frame`, read the tooltip text (`__azul-native-chart-tooltip`), key Enter, read the caption
  `__azdashboard_charts_caption`; type a table filter and check the bar chart's tick labels changed.
