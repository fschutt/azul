## 2. The exit segfault

Root cause: AZ_E2E's verdict printer thread (`e2e-result-printer`, run.rs) called `exit()` while the
headless loop, the windows' worker threads, the font registry's threads and the debug server still
ran; the atexit handlers (the PGO profile writer, framework teardown) ran under them (exit 139 on the
instrumented build). Normal builds: 6 AZ_E2E runs of the prebuilt AzPaint this session all exited
with their verdict code (1), no crash seen - but the race is the same.

- `common::process_exit::ExitRequest` (+ `EXIT_REQUEST`): the worker records the code (first wins)
  and wakes the loop; it exits itself only when no loop takes requests (desktop backends: unchanged)
  or after a 10 s grace.
- The headless `run()` takes requests: on one it leaves the loop, joins every window's threads
  (children too: `shutdown_all_threads`), signals the font registry to stop, and exits on the UI
  thread through `run::exit_from_ui_thread` (stops the debug server's thread, bounded 1 s, then
  `exit_dumping_profile`). The `EndProcess` exit goes the same way (it was a raw
  `std::process::exit(0)` that skipped the PGO dump).

## 3. Menus in headless

`show_menu_from_callback` was a no-op. Now it builds the same menu window the X11 / Wayland fallback
opens (`desktop::menu::show_menu`) and queues it as a child of the window; `pump_children` lays it out,
pumps it and gives it a debug timer, so a script reaches it by `window_id`: `azul-menu`, and a menu
opened while another is open (a submenu, a second drop-down) takes the first free `azul-menu-2`,
`-3`, ... Clicking an item runs its callback and closes the menu (the menu renderer's own callback).

New debug op `{ "op": "list_windows" }` -> `{ window_count, windows: [{ window_id, is_default,
is_this }] }`: the windows the debug server reaches (OP_POLICY: ALLOW, observation).

Not done: dismissing a headless menu by an outside click or Escape (no pointer grab headless: a script
closes it by clicking an item, or `close` with its `window_id`).

## 4. A window id for layout callbacks

`LayoutCallbackInfo::get_window_id() -> AzString`: the window's `FullWindowState::window_id`, read by
`layout()` to tell several windows of one kind apart (CAL3: one editor per event). Carried in
`LayoutCallbackInfoRefData` (new LAST field `window_id: &AzString`; the info holds the ref data by
pointer, so `LayoutCallbackInfo`'s own layout is unchanged). Every construction site passes it (the
desktop shells' `regenerate_layout`, the web renderer, the tests).

## 5. Child windows in headless E2E

Routing by `window_id` (MAIL2) works: verified live against the prebuilt AzCalendar -
`scripts/azcalendar_e2e.py --only editor,repeat` PASS (Ctrl/Cmd+N opens the editor window, the
script types into it by `window_id`, Save & Close writes the weekly event). The stage had failed on
the script itself: its `click` helper waits two frames on the clicked window, which Save & Close had
just closed - fixed in the script.

Engine fix: `announce_debug_request` set ONE wake flag, taken by whichever window's loop looked first;
the window a request is forwarded to kept its debug poll at the 2 s idle rate, so each op against a
second window could wait up to 2 s. Now every window re-arms once per announcement
(`DebugWakeSeen` in `E2eScratch`, `take_debug_request_wake_for`).
