- `Mailer::send_raw(from, recipients, message) -> Vec<RecipientOutcome>`: a finished message to many
  recipients (To + Cc + Bcc go into the envelope only). Direct: recipients grouped by domain, MX hosts by
  preference (`resolve_mx`: NXDOMAIN is permanent, DNS trouble temporary, no MX = the domain itself),
  `Config::ports` (default now `[25]`), next MX on connect failure or a 4xx before RCPT. Relay:
  `Config::relay(host, port)`, everyone in one session. Per recipient: `Accepted { server }`,
  `Deferred { reply, reason }` (4xx, no connection, timeout), `Rejected { reply, server }` (5xx with the
  enhanced code `5.7.1` parsed; `server` empty = refused locally, e.g. a malformed address).
- STARTTLS only when the server offers it AND this build can speak TLS (the crash-mail bug: without the
  `tls` feature it used to say STARTTLS and continue in plain text). Certificates verified (webpki roots +
  optional extra PEM roots, `tls::client_config_with_roots`), SNI = the MX / relay host name. A failed
  handshake reconnects without TLS unless `require_tls`. rustls without default features; provider from
  `tls-rustcrypto` (pure Rust, what azul uses), `tls-aws-lc` (the old default) or the caller.
- Wire rules: every line end CRLF (`normalize_crlf`), dot-stuffing (`dot_stuff`, `wire_data`),
  `BODY=8BITMIME` when the data is not ASCII and the server offers it. Command timeout 60 s, data-end
  timeout 300 s, both on the socket (also under TLS). AUTH never in plain text to another computer.
- `MessageBuilder` (`message.rs`): Date, From, To, Cc, Reply-To, Subject, Message-ID, In-Reply-To,
  References, extra fields, `MIME-Version: 1.0`; text (7bit or quoted-printable), `multipart/alternative`
  with HTML, `multipart/mixed` with base64 attachments (RFC 2231 `filename*` + RFC 2047 `name`), RFC 2047
  encoded words for non-ASCII headers and display names, quoting of specials, folding near 78 columns,
  CR/LF stripped from header values (no header injection). The output is ASCII with CRLF only.
- `Mail::format` (the old one-recipient API) writes `MIME-Version` and quoted-printable for non-ASCII
  text; `send_sync` runs on the new engine.
- DKIM (`dkim` feature): `DkimConfig::from_pem` (PKCS#1 or PKCS#8), `sign_message` through
  **mini-mail-auth** (rsa-sha256, relaxed/relaxed). The old `signing` path was a no-op on mail-auth
  (`Signer`, `Mail::sign_with_dkim` are gone); `signing` = `dkim` + key generation.

`examples/azul-mail/src/send.rs` (`pub mod send;` is the only line added to `lib.rs`), the exact interface
MAIL2 codes against, plus:

- `send_mail(mail_root, account_id, settings, mail) -> SendStatus` (blocking, from an azul Thread):
  build (`build_message`), sign (DKIM key from a file or from `settings.dkim_key`), write
  `<mail_root>/<account>/outbox/<id>.eml` + `<id>.json`, deliver, file.
- Filing: all recipients done and at least one accepted -> the `.eml` moves into the account's Sent folder
  in MAIL1's layout: `mail/sent/<yyyy>/<mm>/<uid>.eml`, a line in `mail/sent/index.jsonl`
  (`message::index_entry`, flag `\Seen`), `mail/sent/state.json` (created for a never-synced folder; a
  synced folder's UIDVALIDITY / last UID untouched). Local UIDs count up from `LOCAL_UID_FLOOR` =
  `0xF000_0000`, far above server UIDs. The mail store root honours `account.json`'s `folder`.
- Outbox state machine (`OutboxEntry`: per recipient pending / sent / failed, attempts, `next_attempt`):
  every recipient accepted -> `Sent { message_id }` (without angle brackets, as `index.jsonl`);
  some pending, none failed -> `Queued { reason }`, retried after 5 min, doubling to 4 h, given up after
  5 days; any permanent failure -> `Failed { reason }` (filed in Sent when someone got it; left in the
  outbox as `failed` when nobody did; still-pending recipients keep being retried).
  `retry_outbox(mail_root, account_id, settings, force) -> Vec<(id, SendStatus)>`,
  `outbox_entries(...)` for an Outbox view.
- Policy list `<account>/send_policy.json` (written with the defaults on first use): gmail.com,
  googlemail.com, yahoo.com = relay; outlook.com, hotmail.com = direct; unknown = direct; a subdomain
  follows its parent. In direct mode a relay-only domain is not contacted (Queued: "takes mail only from a
  trusted relay ...") unless `ignore_policy`. A 5xx from the domain's own server teaches the list
  (`learned`, with the reply and the date) unless it is about the address (5.1.x, 5.2.x, "no such user",
  "mailbox unavailable", ...); an entry with `source: user` is never overwritten; the SMTP route never
  teaches anything.
- `file_message(store_root, folder_key, bytes, flags, now)`: files any locally written message like a
  synced one; MAIL2 can file drafts with it (`folder_key = "drafts"`) instead of a second writer.
- `bin/azmail-send`: the send path from the command line (for the E2E script).

## SendSettings (what MAIL2's "Sending" settings page shows)

Stored as `<AzMail folder>/<account>/sending.json` with `SendSettings::save(mail_root, id)` /
`SendSettings::load(mail_root, id)`; never a secret in it.

| Field | Type / default | The page shows |
|---|---|---|
| `route` | `SendRoute::Direct` (default) or `SendRoute::Smtp { host, port }` | "How mail leaves": (o) "Directly to the recipients' mail servers (no account)" / (o) "Through an SMTP server" with Host and Port (a local test server: `127.0.0.1`, the sink's port) |
| `tls` | `TlsPolicy::Opportunistic` (default) / `Required` / `Off` | "Encryption (STARTTLS)": When offered / Always / Never (test servers) |
| `extra_ca_file` | `Option<PathBuf>`, None | Advanced: "Also trust this certificate" (PEM file picker; a test server's) |
| `helo_name` | `String`, empty = the sender's domain | Advanced: "Name of this computer (EHLO)" |
| `direct_port` | `u16`, 0 = 25 | Advanced, direct only: "Port" (only a test MX on this computer needs another) |
| `ignore_policy` | `bool`, false | Advanced, direct only: "Try direct delivery even where a trusted relay is needed" |
| `dkim` | `Option<DkimSettings { domain, selector, key_file: Option<PathBuf> }>`, None | "Sign with DKIM" checkbox; Domain (default: the address's domain), Selector (default `azmail`), Key: "from a file" (picker) or "stored in the keyring" |
| `dkim_key` | `Option<Secret>`, `#[serde(skip)]` | not shown: before sending, a callback reads the keyring entry `send::dkim_keyring_key(id)` (= `AzMail/<id>/dkim`) with `keyring_get` and puts it here; an "Import key..." button stores a PEM file's content there with `keyring_store` |

Also worth a page section: the policy list (`PolicyList::load(account_dir)`: domain, route, source,
reason; editing a row sets `source: user`) and the Outbox (`outbox_entries`; "Send now" =
`retry_outbox(.., force = true)` on a Thread; "Delete" = remove `<id>.eml` + `<id>.json`).

How MAIL2 calls it: Send button -> build `OutgoingMail` -> (callback) read the DKIM key from the keyring
if `dkim.key_file` is None -> Thread: `SendSettings::load`, set `dkim_key`, `send_mail` -> write back
Sent (close the window; it is in Sent) / Queued (it is in the Outbox; say why) / Failed (show the reason).
Send/Receive or a timer: Thread `retry_outbox(root, id, &settings, false)`.

## What is left

- Publish micromail 0.2.0 (and mini-mail-auth 0.1.1), drop the patch; then the crash-mail migration above.
- MAIL1's sync and local Sent mail: `sync::plan_folder` treats a state whose UIDVALIDITY differs as
  "renumbered" and moves `mail/sent/` to `stale/sent/<old>/`. A Sent folder AzMail created has
  UIDVALIDITY 0, so the first IMAP sync of Sent would move the locally sent mails aside. Fix (MAIL2's
  `sync.rs`, not touched here): treat a state with `uidvalidity == 0` like "never synced" but keep its
  index, or carry entries with `uid >= send::LOCAL_UID_FLOOR` (and their files) across a renumbering.
- Relay = SMTP submission with AUTH (PLAIN / LOGIN over TLS, XOAUTH2) for the "needs a relay" domains; the
  policy check could also look at the MX host (Google Workspace domains have Gmail's MX).
- SMTPUTF8 / IDN addresses (refused locally today), SIZE limits, a DKIM DNS-record helper on the page
  (micromail's `signing` feature has `format_dkim_dns_record`).
- MX lookups go through microdns to public resolvers (1.1.1.1, 8.8.8.8): a network that blocks outbound
  DNS gives "could not look up the mail servers" (queued). Host names resolve through the system first.
- Direct delivery from a home connection: port 25 is often blocked and big providers check SPF / DKIM /
  reverse DNS; that is what the policy list and the relay route are for.
