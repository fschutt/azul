## What was built

`examples/azul-reader` (package `AzReader`, lib `azreader`, bin `AzReader`), registered in the
root `Cargo.toml`, `scripts/workspace_test_members.txt` and the `dll_tests` job of
`.github/workflows/rust.yml` (step "Run AzReader tests").

- **EPUB through azul's parsers** (`epub.rs`, `xmltree.rs`): the zip through `azul::zip::Zip`,
  `META-INF/container.xml` -> the OPF (metadata, manifest, spine, `linear="no"`), the cover
  (EPUB 3 `cover-image`, EPUB 2 `<meta name="cover">`, a name with "cover"), the table of
  contents (EPUB 3 nav `toc`, else the EPUB 2 NCX, else each chapter's title), href resolution
  (relative, `..`, `%xx`, `#fragment`), UTF-8 / UTF-16 text. Every XML file is read by
  `xmltree::parse_document`: azul's strict XML loader (`Xml::from_str`) first, the HTML5-like
  parser (`Xml::create_from_html`) when the strict parse fails or the item is HTML.
- **The reading tree** (`content.rs`, `bookcss.rs`): a chapter becomes a new `Xml` tree
  (`html > head > style` + `body`) for `Dom::create_from_parsed_xml`: the reader's base sheet,
  then the book's sheets (linked + inline) FITTED to the reader; scripts, forms, media, frames,
  drawings dropped; `id` / `class` / fitted `style` / `colspan` / `rowspan` / `dir` / `lang`
  kept; `<img>` (and an `<svg>` that frames an `<image>`) -> `src="azreader:<book>/<path>"`
  (the image-cache name) with an explicit size that fits the page; a missing picture leaves
  `[alt]`; the plain text collected for anchors (TOC `#fragment`) and bookmark excerpts.
- **Pages** (`paginate.rs`, `position.rs`): the chapter in the READING COLUMN (the page's text
  width, the reader's type stated on the box) is laid out once by azul's paged layout with the
  READING POLICY (atomic lines, widows / orphans, break-inside avoid, atomic rows) on a
  `Thread`, pictures decoded there; its break ys are the page starts (`PageMap`). A page on
  screen is a clip window over the same column (`overflow: hidden` box of the page's span,
  the column moved up by the page's start) - what the engine's own slicer does. One or two
  pages side by side (`PageGeometry`, Auto by width). A position is (chapter, fraction of the
  chapter's height) and survives a reflow; the book's progress weighs chapters by file size.
- **Library** (`library.rs`, `jobs.rs`): each book is a folder in the data tree
  `reader/books/<uuid>/` - `book.epub|txt|html`, `info.json`, `state.json` (position,
  bookmarks, last read, progress, finished), `cover.png` (240x360 at most) - written through
  azul-storage's `Drive` (`LocalDrive` at the data root) from an azul `Thread`: scan, import,
  open, delete. Shelves (All / Reading / Not started / Finished), sort (Recent / Title /
  Author), search.
- **Plain files** (`plainbook.rs`): a `.txt` becomes chapters at its headings ("CHAPTER I",
  "Book Two", "PROLOGUE", ...; Gutenberg hard-wrapped paragraphs joined; long chapters split at
  60 000 characters); an `.html` file is a one-chapter book read by the HTML5-like parser.
- **UI** (`lib.rs`, `ribbon.rs`, `ui_library.rs`, `ui_reader.rs`, `ui_settings.rs`, `ids.rs`):
  the S1 `DocumentShell` for both screens (title row = azul-appkit's `Titlebar`, the ribbon,
  the navigation pane, the status bar) in a `ShellThemeScope`; the library's shelves + covers
  grid (`TODO(WIDGETS9A)` IconGrid) + empty state; the reader's pages with turn zones, swipes,
  the running head and folio, the Contents and Bookmarks panes; the ribbon READ / VIEW tabs;
  the "Reading" section on azul-appkit's settings page (text size, line spacing, margins, font,
  paper Auto / White / Sepia / Night, one / two pages, justified / left); About; keys (arrows,
  PageUp / PageDown / Space, Home, Mod+D bookmark, Mod+T contents, Mod+B bookmarks,
  Mod+Plus / Minus, Mod+O add, Mod+L library, Escape). `--sample` makes and opens a two-chapter
  public-domain EPUB (`sample.rs`); files on the command line are added and the first opens.
  Every id / class is a `const AzString` with the `__azreader_` prefix.
- **azul-appkit** gained `css` (the mechanics of reading an outside style sheet: comments,
  rules, at-rules, blocks, declarations, unsafe values) - AzReader's sheet policy sits on it.
- **Engine** (dll): `Pdf::compute_pagination_with_policy` - see "Root cause" below.

## Root cause fixed in the engine: the pagination query tore lines

`Pdf::compute_pagination` (the only public pagination query that runs off the UI thread) laid
the document out with `FakePageConfig::new()`, whose `BreakPolicy` is all off - the plain
interval slicing, which cuts every page at exactly N x page height, through whatever line lies
on the edge. A document editor that only counts pages does not notice; a reader whose page IS
the slice shows half a line at the bottom and the other half at the top of the next page.
`CallbackInfo::query_pagination` takes a `FakePageConfig` but runs on the UI thread with an
empty image cache. Fix (dll only - `layout/src/solver3/page_breaks.rs` belongs to another
session and is untouched): `Pdf::compute_pagination_with_policy(.., policy: BreakPolicy)`;
`compute_pagination` delegates to it with the default policy (behaviour unchanged);
`engine::styled_dom_pagination` became `styled_dom_pagination_with_policy` (its only caller was
`compute_pagination`); the wasm stub has the twin. RED: `paginate.rs`
`a_page_of_text_never_ends_inside_a_line` (20 px lines, 105 px pages: every page starts on a
multiple of 20) - it does not build until the api.json entry below exists.

## api.json (for `azul-doc autofix add`; nothing edited by hand)

- `pdf.Pdf.functions.compute_pagination_with_policy`:
  args `self: ref`, `styled_dom: StyledDom`, `page_width_px: f32`, `page_height_px: f32`,
  `font_cache: FontCacheSnapshot`, `image_cache: ImageCacheSnapshot`, `policy: BreakPolicy`;
  returns `PaginationSnapshot`; fn_body
  `object.compute_pagination_with_policy(styled_dom, page_width_px, page_height_px, &font_cache, &image_cache, policy)`;
  doc: "`compute_pagination` with the break-awareness `policy`: `atomic_lines` never ends a
  page inside a line of text, `widows_orphans` honours CSS widows / orphans,
  `honor_break_inside` keeps a `break-inside: avoid` box whole, `atomic_table_rows` a table
  row. The default policy (all off) is the plain interval slicing."
  `BreakPolicy` is already in api.json (module pdf, repr C, Copy) - the app builds it with a
  struct literal (`paginate::reading_policy`).
- Nothing else: the app uses only existing API.
