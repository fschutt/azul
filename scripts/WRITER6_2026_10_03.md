## 1. What was built

### 1.1 Undo / Redo reach an editor that owns its history (core + layout + dll)

Design: the browser keydown model (UI Events default actions). The page's keydown handler runs first;
the built-in undo of an editing host is the key's DEFAULT action, cancelled by `preventDefault()` - how
ProseMirror and Google Docs own Ctrl+Z.
- `core/src/events.rs` `handle_key_down`: primary+Z / Shift+Z / Y of the PRIMARY seat no longer emit
  `AddAndSkip(SystemChange::UndoTextEdit / RedoTextEdit)`; the KeyDown reaches the callbacks. A second
  seat keeps its `SeatShortcut`.
- `core` `DefaultAction`: new variants `UndoTextEdit { target }`, `RedoTextEdit { target }` (appended).
- `layout/src/default_actions.rs`: primary+Z (undo), primary+Shift+Z / primary+Y (redo) in any
  contenteditable focus (rich or plain text) decide them; prevented -> nothing; outside an editing host
  -> nothing (the key is the app's).
- `dll/src/desktop/shell2/common/event.rs`: the keyboard default-action match runs them through the
  existing `apply_system_change(SystemChange::UndoTextEdit / RedoTextEdit)` arms (one undo body), primary
  seat only.
- The RichTextEditor's key handler takes Ctrl/Cmd+Z / Shift+Z / Y: `RichTextCommand::Undo / Redo` on its
  ONE history, `prevent_default` (the engine's text undo never runs behind its back).

### 1.2 Editing shortcuts on a non-editable focus (SMALL6's bug, same block)

Copy / Cut / Paste / Select all are claimed by the interpreter (`AddAndSkip`) only on a text-editing
focus or while text is selected (`InputInterpreterState::has_selection`, now handed to
`handle_key_down`); Ctrl/Cmd+D only on a text-editing focus. Elsewhere (a focused keypad button) the
KeyDown reaches the app's handler - AzCalculator's Ctrl/Cmd+C after a click on a button.

### 1.3 The RichTextEditor takes its formats from the engine (RTE section 8.3 / 6)

- `RichTextEditorState::sync_text` folds each edit's text in as before (the unchanged ends keep their
  runs, links and code), then sets the NEW text's bold / italic / underline / strike from the edit
  report (`DocumentTextEdit::runs`, TEXTENG): typing after the engine's Ctrl/Cmd+B at a caret and an
  inline formatted paste keep their formats in the model (DEDUP_EDITORS D1 / A3.2).
  `RichTextDoc::apply_reported_formats` (crate-only) does the run surgery.
- A format toggled at a caret (key or toolbar) starts from the engine's pending format
  (`CallbackInfo::get_typing_formats`).
- DECISION: `RichTypingStyle` / `RichTextEditorState::typing` stay (an api.json field; inline code has
  no engine format; the toolbar's pressed state at a caret).

### 1.4 Pages of one document (`RichTextEditor::page_doms`, RTE section 8b)

`page_doms(page_starts: U32Vec, first_page, page_count) -> DomVec`: one editing host per page
(`<host id>-page-<first block>`, no padding of its own), the blocks named by their index in the WHOLE
document (`<host id>-<index>`), every page sharing ONE editor state (one `EditorData`). The editor's
node -> block mapping no longer assumes one host: `host_of` walks up to the nearest host of the editor
(the one host or a page) and `model_path` adds the page's first block; `host_node` falls back to the
callback's page, then the caret's page. Typing, structural edits (a page's `ReplaceChildren` indices
offset too), the selection, the caret and commands all use it.

### 1.5 AzWriter (examples/azul-writer) - rewritten on the building blocks (RTE section 8 a-e)

- The window: S1 `DocumentShell` + `OfficeShell` (appkit's `Titlebar` title row under `NoTitle`, the
  ribbon or the `Backstage`, the pages, the `StatusBar`) in a `ShellThemeScope`, behind a `CloseGuard`
  ("Save changes?": Save saves on a Thread and closes when the save answered; Don't Save closes; Cancel
  stays). Follows the app theme and the OS mode; the hand-rolled `palette.rs` / `fonts.rs` are gone (W1).
- The text: ONE `RichTextEditorState` (`model.rs` `DocumentModel` = the state + the file id + the saved
  Markdown + a pagination generation). One undo history (Ctrl/Cmd+Z, the ribbon's Undo / Redo); the
  app's own undo stack, `ir::apply_operation`'s inverses and `ir.rs` itself (the twin model, A1 / A3.7)
  are gone; Ctrl/Cmd+B over a selection works (A3.3); formats come from the engine.
- The pages (`paginate.rs` + `pages.rs`): the engine's pagination (`Pdf::compute_pagination` over the
  document exactly as the editor renders it, at the A4 text width, on a `Thread`, one at a time per
  document generation) -> the first block of every page -> one sheet per page, each sheet ONE page host
  of `RichTextEditor::page_doms`. NOT a pagination of its own: it replaces document.rs's DomSplit glue.
  Print layout (A4 sheets) / Web layout (one sheet); zoom scales the sheet, the margins and the text.
  The paper follows the mode (`system:background` / `system:text`, as the editor's content colours);
  the PDF is black on white (W2).
- The ribbon (`ribbon.rs`): HOME - B / I / U / S / code pressed from `is_current_format`, lists and check
  items, indent / outdent, alignment and quote pressed from the caret's block, the style gallery (Normal,
  Heading 1-3, Quote, Code - each its own kind; a pick never toggles a style off), Undo / Redo disabled
  when there is nothing; INSERT - table, page break, line; VIEW - print / web layout, zoom, settings,
  about. The placeholder tabs and the blind flip went (A3.5).
- Files (`storage.rs`, `commands.rs`): every document is `writer/<uuid>.md` in the data tree (ids from
  `Uuid::from_seed(azul_storage::ids::random_seed())`), exports `writer/exports/<title>.pdf|md`; every
  durable write is an azul-appkit file job on a Thread (no `std::fs::write` from a callback). Backstage
  (`backstage.rs`): Info, New (blank, import a Markdown / Word file), Open (the documents of the data
  tree, by title), Save, Export, Close. Word import (`docx.rs`) into RichBlocks: runs and formats,
  alignment, outline levels, bullet / numbered items with their level, tables, page breaks.
- azul-appkit: args (`--screen editor|open|new|settings`, `--size`, `--theme`, `--mode`, `--shot`,
  `--sample`, `--data-dir`, files to import), data root, settings file and page, the About facts (shown
  in azul's `AboutDialog` in a `Modal`), the shortcut table. `--sample` writes the sample document (two
  pages, every block kind) into an empty data folder.
- Names: every id / class once in `ids.rs`, prefix `__azwriter_`.
- E2E: `scripts/azwriter_e2e.py` (new; section 4).
- Dropped dev flags: `--paginate-twice`, `--dump-xml`, `--frame-log`.

### 1.6 AzNotes (examples/azul-notes)

  A16); it no longer clears `flags.close_requested` by hand.

  tags are cleaned with `azul_pim::task::normalize_tag` (AzTasks' twin of `markdown::clean_tag`, deleted);

- azul-appkit: args (+ AzNotes' `--note <id>`), the data root (`--data-dir` / `AZLIN_DATA` / `Azlin`:
  the notes stay `notes/<notebook>/<uuid>.md` under it; INFRA6's startup migration moves an old
