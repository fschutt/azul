## The finding first
The backlog item ("threads of widgets REMOVED from the DOM are never terminated ... -> terminate on unmount",
ledger engine backlog 4) was already done on 2026-10-01 by **7c1c12389**, which is in the base. That commit
added `layout/src/managers/thread_owner.rs`: a thread added by a node's `AfterMount` / `NodeResized` / `Updated`
callback is bound to that node by the dispatcher. `LayoutWindow::remap_node_ids` (the unmount path HEADLESS6 also
uses) orphans it, including nodes in the child DOM of an unmounted VirtualView, and sends `TerminateThread`.
`run_all_threads` drops the orphan's write-backs and retires it once it has finished, or detaches it after a
2 s grace. The headless RED/GREEN test is
`shell2::headless::tests::the_worker_of_a_node_that_unmounts_is_told_to_stop_and_is_gone_after_a_frame`.
The ledger entry is stale. **Mark backlog 4 done in the ledger.**

THREADS8 checked everything around that mechanism and fixed the three gaps it found, RED test first each time.

## What was built
1. **The `<video>` test-pattern and replay workers ignored `TerminateThread`** (`layout/src/widgets/video.rs`).
   They took `_recv` and never read it. So a `<video>` without a registered decoder (or with `with_frames`)
   kept producing frames after it unmounted, until the 2 s grace detached it (with the "did not acknowledge"
   warning). Every per-frame `Tick` and resize message also piled up unread in its channel. A test even pinned
   this ("test_worker_ignores_terminate_and_scrolls_the_pattern"). Fix: each frame starts with the shared
   `capture_common::terminate_requested`, which the camera / screencap / mic workers already use. No new
   helper. (The dll's real decoder, `video_codec/stream.rs`, and the camera / screencap / mic workers already
   stop on Terminate.)
2. **A closing window stopped its workers one after the other.** Dropping the `threads` map ran each
   `Thread` destructor in turn: send Terminate, then wait up to 2 s, before the next worker had been told
   anything. So closing a window cost the SUM of its workers' stop times on the UI thread, and N x 2 s when
   workers were stuck in a device read. Fix: `managers::thread_owner::stop_all(&mut threads)` tells every
   worker first, then polls them together through the existing `poll_orphan` against ONE shared
   `ORPHAN_GRACE`, detaches whatever is left, and clears the map. It is called from a new
   **`impl Drop for LayoutWindow`**, which covers every shell's close path in one place, and from headless
   `shutdown_threads` (which used `threads.clear()` before).
3. **Timers a node started on mount never stopped.** `map_on_after_mount` (`widgets/map.rs`) adds a 250 ms
   tile-sweep timer that returns `Continue` for ever. A map that left the DOM kept waking the app 4x/s and
   kept its tile cache alive, and a remount added a second sweep. Fix: timers follow the same rule as
   threads, in the same manager:
   - `ThreadOwnerManager` gained `bind_timer` / `timer_owner` / `forget_timer`, plus a stop list
     (`take_timers_to_stop` / `timers_to_stop`). Threads and timers now share one `follow` function.
   - `LayoutWindow::remap_node_ids` takes `timers` out of the "no node ids" group and drops the timers of
     unmounted nodes from `lw.timers` at the unmount.
   - `dispatch_events_propagated` collects the `AddTimer` changes of lifecycle callbacks (the same
     `binds_threads_to_node` test) and binds each timer to its node after the changes are applied.
     Applying `AddTimer` / `RemoveTimer` forgets any old owner of that id.
   - A provided `PlatformWindow::stop_timers_of_unmounted_nodes` drains the stop list into `stop_timer`
     (NSTimer / SetTimer / timerfd / headless). It runs at the start of `dispatch_pending_lifecycle_events`
     (after every rebuild pass) and of `invoke_expired_timers`.

## Least sure to compile
- `impl Drop for LayoutWindow`: a Drop type cannot have fields moved out of it (E0509). I found no by-value
  destructure or field move of a `LayoutWindow` in layout/, dll/ or layout/tests: every `let LayoutWindow {..}`
  binds with `ref` / through `&`. A move I missed (an example crate, a cfg'd test) would show up as E0509.
  The fix there is to clone or `mem::take` the field.
- `stop_all`: `running.retain(|thread| !poll_orphan(told, thread, now))` relies on `&&Thread -> &Thread` deref
  coercion. `drop(running)` before `threads.clear()` ends the borrow explicitly.
- headless test: `window.start_timer(..)` is the `PlatformWindow` method (the trait is imported in the fn);
  `Timer::create(.., TimerCallback::create(sweep_tick), ..)`.
- thread_owner timing tests: 3 x 300 ms workers must close in < 600 ms (serial ~930 ms). 3 stuck workers
  must close in < 3 s (serial 6 s). On a heavily loaded CI box the first margin (~280 ms) is the tighter one.

## Seen / not done
- I ran no binary. The prebuilt binaries are the base, where these gaps still exist, and an unmount is hard to
  trigger in AzWidgets / AzMaps (the video card and the map stay mounted). The headless tests cover it. A
  manual check after the build: AzMaps, switch to a screen without the map, then `ps -M <pid>` / an idle-CPU
  sample should show no 250 ms wake-ups.
- `Timer.node_id` (the public field a timer callback's `get_node_size` reads) is not remapped on rebuild, so
  it can point at a different node after a DOM change. This is a separate small bug, not fixed here.
- The e2e runner (`layout/src/e2e/runner.rs`) applies `AddTimer` itself and does not bind lifecycle timers.
  That is harmless for scenarios.
- Behaviour change for apps: a timer started in a node's `AfterMount` / `NodeResized` / `Updated` now stops
  when that node unmounts, the same rule threads have followed since 7c1c12389. AzCalendar starts app-wide
  timers from its root's `AfterMount`, but the root carries an id, so reconciliation always matches it. An
  app that wants a timer to outlive the node should start it from a non-lifecycle callback (or the
  window-create callback).
