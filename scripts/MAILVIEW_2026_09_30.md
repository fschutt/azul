# MAILVIEW - engine bugs that block mail display

Branch `wt/mailview-engine`, from `d8be2016d`. Nothing was compiled (house rule). Every Rust file was
parse-checked with `rustfmt --check`. Where it helped, behaviour was confirmed headless against the
parent's prebuilt binaries (`target/release/AzWidgets` / `AzMail`, `AZ_BACKEND=headless`, `mount`
scenarios). The probe script is `scratchpad/mv/probe.py`, and its scenarios are in `scratchpad/mv/e2e/`.

Two user rulings arrived during the task and changed items 1 and 8:
- **A (item 1):** `href` goes through the component's arguments, not the attribute table.
- **B (item 8, corrected):** no per-subtree light mode in the engine. AzMail's sanitizer puts
  the mail on paper, and the paper follows the mail's own dark rules.

## What was built, item by item (root causes)

### 1. E-XML-2: `<a href>` keeps its link, through the `a` component's arguments

- **Root cause:** nothing in the loaders produced `AttributeType::Href`.
- **The dead filler:** a generic filler, `xml_attrs_to_data_model`, existed with no caller. The
  builder had a typed twin, `e2e::builder::data_model_with_args`.
- **The render fn:** the builtin render fn (`builtin_dom`) read only `text`.

The first fix (`589f75168`, an attribute-table entry) was replaced per ruling A. The table
(`core/src/xml_attributes.rs`) is back to its base, byte for byte.

**`azul_core::xml::data_model_with_attributes(dm, attrs)`** is THE one filler of a component's
declared fields from attributes, for builtin and user components alike:
- It matches names case-insensitively.
- It parses values to the field type (String, Bool with HTML boolean semantics, the integers,
  the floats).
- An unparsable number keeps the default. Undeclared attributes are ignored.
- It replaces the dead `xml_attrs_to_data_model`. The builder's `data_model_with_args` now
  delegates to it, so the two twins are one function.

**`apply_builtin_element_args(tag, args, node)`** is the render side for the builtin elements:

| Element | Arguments landed on the node |
|---|---|
| `a`, `area`, `link` | `Href`, `Target`, `Rel` |
| `base` | `Href`, `Target` |
| `img` | `Src`, `Alt` (so an app can read the URL and the alt text) |

**`apply_builtin_args_from_attributes(tag, attrs, node)`** is what both XML loaders call per
element: core's `apply_xml_node_attributes` and the fast loader's `finalize_open`. Only the
elements listed above build a model.

**The builtin render fn** (`builtin_dom`) now passes the arguments a caller set as the element's
attributes, so a component instance renders like its markup. "Set" means differing from the
declared default (`argument_attributes`).

**How the app routes a click:**
1. The `<a>` now carries `href`.
2. With E10 below, the `<a>` is the frontmost hovered node under a click on its text.
3. A click callback on the mail container finds it: `info.get_hovered_nodes()`, then the first
   node with `info.get_node_attribute(node, "href")`.
4. `:link` also gets `cursor: pointer` (item 3).

AzMail itself does not register that callback yet. azul has no "open URL" API. That is app work
for the M-tasks.

#### Builtin components whose declared fields are not honoured yet (for the component audit)

**Honoured:**
- Through component arguments: `a` (href, target, rel), `area` (href, target, rel), `link`
  (href, rel), `base` (href, target), `img` (src, alt).
- By the element's own reading: `img` width and height (the intrinsic size).
- By the attribute table:
  - `td` / `th` colspan and rowspan;
  - the form-control fields of `input`, `select`, `option`, `optgroup`, `textarea`, `button`;
  - `bdo`'s `dir` (the table's `dir`).

**Not honoured** (the field is declared but nothing reads it):
- `ol`: `start`, `type`. The numbering always starts at 1 and follows the UA `decimal`. Mail
  uses both.
- `q` / `blockquote` / `del` / `ins`: `cite`. `del` / `ins`: `datetime`. This is metadata with no
  rendering.
- `area`: `shape`, `coords`, `alt`. `link`: `type`. `map`: `name`. `time`: `datetime`.
  `data`: `value`. `abbr` / `acronym` / `dfn`: `title`.
- `form`: `action`, `method`. `label`: `for`.
- `fieldset`: `disabled`. `output`: `for`, `name`. `progress` / `meter`: `value`, `min`, `max`,
  `low`, `high`, `optimum`. These elements are outside `is_form_control_tag`, so the table skips
  them.
- `details` / `dialog`: `open`.
- `audio` / `video`: `src`, `controls`, `autoplay`, `loop`, `muted`, `preload`.
- `source` / `track`: `src`, `type`, `kind`, `srclang`, `label`, `default`.
- `canvas` / `embed` / `object`: `width`, `height`, `data`, `type`. `param`: `name`, `value`.
- `col` / `colgroup`: `span`.
- `meta`, `script`, `style`: their fields (by design, they draw nothing).
- `icon`: `name` (an icon is named by its text).

**Not declared at all**, though mail needs them:
- `li` `value`.
- `table` `width` / `cellpadding` / `cellspacing` / `border`.
- `td` / `th` `width` / `align` / `valign` / `bgcolor`.

AzMail's sanitizer turns `align`, `valign`, `bgcolor` and `width` into CSS. It drops
`cellpadding`, `cellspacing` and `border` (the exploration's probe rewrite moved them onto the
cells). That is an AzMail gap: a receipt's bordered table loses its borders.

### 2. E10: inline elements are hit on their text runs

- **Root cause:** `CpuHitTester` walks layout nodes that have a size. It is the one hit tester on
  every backend (`CommonWindowState::perform_hit_test`).
- A non-replaced inline element has no size, so a click on a link inside a paragraph reached the
  paragraph.

**Fix:** `push_inline_fragment_entries` (`layout/src/headless.rs`).
1. The display list already carries one `TAG_TYPE_CURSOR` hit area per text run (one per line
   and style run, keyed by the text node).
2. For every run, each inline element between its text node and the first non-inline ancestor
   gets an entry with the run's rect. A link wrapped over two lines gets two entries, and the gap
   between them stays the paragraph's.
3. The entries take the chain, clips and paint rank of the nearest boxed ancestor, and are placed
   after it, so they are the frontmost hit.

**What follows from it:**
- The `<a>` gets its own click callbacks and `:hover`, and bubbling still reaches the paragraph.
- `CursorTypeHitTest` sees the UA `cursor: pointer`.
- `get_hovered_nodes()` lists the `<a>` first.
- The selection code already accepts an inline box as the hit node (`owning_ifc_root`).

### E-RUN (found on the way): a glyph run's extent missed its last letter

**Symptoms:**
- A link's underline stopped under "lin".
- `<u>W</u>` had no underline.
- A one-letter `<mark>` had no background.
- A one-letter link had no hit area.

**Root cause:** the display list's three run passes (inline background and border, decorations,
hit area) measured a run from its first glyph's pen to its **last** glyph's pen. A paint run
carries no advances.

**Fix:** `SimpleGlyphRun` / `CompactGlyphRun` gain `end_x`, the pen after the last glyph.
- Both builders fill it: the per-glyph walker, and the dense twin from the cluster's or its detail
  glyphs' advances.
- The three passes end there.
- `simple_runs_bit_equal` compares `end_x` within 1e-3.

### 3. E-UA: the HTML rendering defaults

The UA table (`core/src/ua_css.rs`) now follows the HTML Living Standard's rendering sections
15.3.3 and 15.3.4:

| Elements | Default added |
|---|---|
| `em`, `i`, `cite`, `var`, `dfn`, `address` | italic (`address` is also a block) |
| `s`, `del` | line-through |
| `ins` | underline (`u` already had it) |
| `code`, `kbd`, `samp`, `pre` | monospace |
| `blockquote`, `figure` | `margin: 1em 40px` |
| `pre`, `dl`, `menu`, `dir` | 1em block margins (`menu` / `dir` also the 40px list padding) |
| `dd` | 40px left margin |
| `small`, `sub`, `sup` | 0.83em (`sub` / `sup` also get their vertical-align) |
| `big` | 1.2em |
| `caption` | centred |
| `mark` | yellow background, black text (`BackgroundContent` joins `UA_PROPERTY_TYPES`) |
| a **link** (`is_link`: an `<a>` with an `href`) | `color: #0000EE` (#9E9EFF in the dark mode), `cursor: pointer` |

`tag_to_node_type` now reads legacy tags as the element whose rendering they share. They used to
become the unknown tag's block:

| Legacy tag | Read as |
|---|---|
| `<strike>` | `s` |
| `<tt>` | `code` |
| `<font>`, `<nobr>` | span |

**Cascade bug found and fixed:** a UA default is a declared value, so it must beat an inherited
value.
- The slow path let the restyle inheritance walk's copy block the UA default. A link under
  `<td style="color:#333">` painted #333, and `<code>` under `font-family: serif` stayed serif.
  The compact path was already right.
- `normal_props_present` now counts inherited `cascaded_props` only on text nodes. A text node
  keeps "inherited beats its own row", so its I-beam still yields to a button's pointer.
- `apply_ua_css_in_tree` then runs `hand_ua_defaults_down`, because the walk ran before the UA
  pass: every node below such an element that declares nothing takes the element's default.
- `StyledDom` calls the tree variant. `apply_ua_css(node_data)` keeps its signature.

### 4. E-BR: a block holding only `<br>` is one line tall

- **Root cause:** `perform_fragment_layout` gave the line a band of line-height, but measured the
  IFC's height from the positioned items' bounds. A `ShapedItem::Break` has no geometry, so the
  line measured 0.
- **Fix:** it now tracks the bottom of the lowest line box (`line_box_extent`) and makes the
  unclipped bounds at least that tall (CSS 2.2 10.6.3 and 9.4.2).
- **Scope:** horizontal writing modes only. The Knuth-Plass path (justify / pretty) is unchanged.
- **Height with `line-height: normal`:** the strut is `font_size * (0.8 + 0.2)`, so a blank
  line is 1em (16px). A real text line is slightly taller (~18.4px).

### 5. E-OL: list markers dropped on some items

- **Reproduced:** `<ol>` with five items painted only "2." and "4.", and `<ul>` painted no bullet.
  With `AZ_NO_LCD_PRETILE=1`, all of them painted.
- **Where it breaks:** the markers were in the display list, but outside their own text item's
  clip rect (the li's content box).
- **Root cause:** an outside marker hangs at a negative inline offset. The IFC's text clip grew
  toward the end edges on a visible axis, never toward the start.
- **How that loses the marker:**
  - WebRender clips a text item to its clip rect, so no markers showed on the GPU.
  - The CPU's pre-blended LCD tile path clips too.
  - The sweep path, used when digit and dot tiles overlap, does not clip. That is why "2." and
    "4." survived.
- **Fix:** `display_list.rs` extends the clip on a visible axis back to the IFC's unclipped ink
  bounds (`x` / `y < 0`).

### 6. E-CSS-1: CDO / CDC around a stylesheet

- **CSS:** `new_from_str` splits the sheet at its top-level `<!--` / `-->` (outside blocks,
  comments and strings: `top_level_rule_segments`). It parses each run with a bounded tokenizer,
  so warning positions stay absolute. A sheet without them takes the old single pass.
- **XML:** `<style>` is raw text in HTML, but xmlparser reads `<!-- -->` in it as a comment,
  and both loaders dropped it. Both now keep a comment inside `<style>` as `<!--text-->` and a
  CDATA section as its text.

### 7. E-XML-4: named entities

- There is ONE table, `azul_core::xml::html_named_entity`: the 252 HTML 4.01 names plus
  `apos`, sorted and binary-searched.
- Both decoders fall back to it: `azul_layout::xml::decode_xml_entities` (both loaders, text and
  attributes) and core's `decode_entities` (`prepare_string`).

### 8. E-MODE: dropped from the engine; AzMail's paper instead (ruling B, corrected)

- The engine RED (`f0b198335`) was removed (`e062843b8`).
- The unfinished `color-scheme` CSS property was never committed. It is kept at
  `scratchpad/mv/color_scheme_property_dropped.patch`.

**AzMail's sanitizer** (`examples/azul-mail/src/html.rs`) now writes:

```
<html><head><style>...</style></head><body><div class="azmail-paper">...</div></body></html>
```

**The paper:**

| Mail | Paper |
|---|---|
| Without dark rules | White with dark text in either mode. No `prefers-color-scheme` in the sheet, so a dark app changes nothing. Links get #0b57d0. |
| With dark rules | Keeps them. The paper gets its own `prefers-color-scheme: dark` rule (#1e1e1e / #e8e8e8), so it follows the app's mode and the mail's dark rules fire on a dark sheet. |

**`<style>` is kept where it is safe** (`sanitize_style_sheet`):
- Kept: rules and `@media` blocks whose declarations pass the existing `style` allowlist
  (`parse_style`).
- Every selector is scoped to the paper: `body`, `html` and `:root` ARE the paper.
- Dropped: other at-rules, comments, CDO / CDC, URLs and positioning.

**`Sanitized::has_dark_rules`** is set by any of:
- a kept dark `@media`;
- a `color-scheme` / `supported-color-schemes` meta naming dark;
- a `color-scheme` declaration naming dark.

**Tests:** string-level tests pin each case, including a mail without dark rules staying white in
a dark app. AzMail's tests are string tests; its CI job links azul dynamically.

### 9. R1's open table items

- **Mixed cell** (`<td>Label<div>..</div></td>`, Outlook's `<td>text<p class=MsoNormal>`):
  - Root cause, in two parts: the fresh layout tree built a table cell's children with the
    catch-all (no anonymous block for loose text; the reconciled tree did wrap it), and
    `layout_cell_for_height` took the inline branch, whose clearing wiped the block's text.
  - Fix: `process_node` builds a `TableCell`'s children with `process_block_children`. Only a
    cell whose children are all inline-level takes the inline branch.
- **Min-content:** the `TableCell` arm of `calculate_used_size_for_node` now returns the
  min-content width under a min-content constraint. The cell's text wraps during measurement,
  and a narrow table's prose stays inside it.
- **Colspan in table intrinsic sizes:**
  - A cell's widths go to the columns it spans. A spanning cell starts after the previous span and
    is spread evenly by what its columns lack.
  - It uses `fc::get_cell_spans`, now `pub(crate)`, so there is one helper.
- **Confirmed headless before the fix:**
  - the block text was missing;
  - the 220px table's text ran to x=366;
  - the shrink wrapper was 396px wide for a ~336px header.

## E-XML-3: the two loaders still disagree (noted, not unified)

They now share the entity table, the component-argument path and the `<style>` comment handling.
They still differ in:
- tag case: the tree loader does not lower-case, so `TABLE` becomes the unknown tag's `Div`;
- an element left unclosed at the end: the tree loader errors;
- foreign `o:p` elements;
- the HTML5-lite auto-close rules.

## For the report only: a lenient XHTML mode in azul's xmlparser

The user is weighing a very lenient parser mode against an html5-to-xhtml converter in AzMail.
Of the exploration's failures (1.2 / 1.3), a lenient mode would fix:

| Failure | Lenient feature that fixes it |
|---|---|
| 03 Outlook raw: `InvalidQuote` on `<meta http-equiv=Content-Type` | unquoted attributes |
| 08 legacy raw: `InvalidQuote` on `<BODY BGCOLOR=#FFFFFF>` | unquoted attributes |
| 08: `<TABLE>` becomes a `Div`; `<BR>` is not seen as void, so everything after it nests under it | case-insensitive tags |
| 04 receipt raw: `noshade` on `<hr>` | boolean attributes |
| `<!-- ---- -->` fails with `InvalidCommentData` | lenient comments |
| `<` inside an attribute value | lenient attribute values |
| C0 control characters | drop them |
| the tree loader's `UnclosedRootNode` | close open elements at the end |
| p / li / td / tr / option without end tags | implied end tags, in both loaders alike (they differ today) |

- **Already fixed by this branch:** named entities, and CDO / CDC in `<style>`.
- **Out of the parser's reach:**
  - 04 receipt norm's panic (fixed by R1);
  - legacy presentation (`bgcolor`, `<font color>`, `<center>`, `cellpadding`), which needs
    a rewrite or UA presentational hints;
  - live form widgets from `<form>`, which is a sanitizer concern.

## What is left

- **The "first text line" smear / vanish** (exploration 1.3's harness caveat):
  - AzWidgets-specific and persistent: it survives `relayout` and extra frames.
  - It appears only when the scenario window is less than ~700px tall.
  - The display list HAS the first text item, but it is not painted. It is not the pre-tile path
    (`AZ_NO_LCD_PRETILE=1` changes nothing), and the frame damage is `full`.
  - The same mount in the AzMail binary paints fine.
  - Likely some AzWidgets UI state keyed by NodeId (a scroll offset or clip) that survives
    `mount`.
  - Repro: `scratchpad/mv/e2e/first1.json` (760x400) vs `firsth800.json`.
- **CPU raster:** the pre-tile LCD path clips per pixel to the text item's clip. The sweep and
  grayscale paths only skip a fully clipped run. Any other ink outside a text clip still paints
  on one path and not the other.
- **`list-style-position: inside`** on an `<ol>` is not honoured: the markers stay outside.
- **`ol` / `li` numbering:** `start`, `type` and `value` are not honoured (see the component
  list above).
- **AzMail:**
  - no click handler routes a link's `href` yet (the engine side is done);
  - `cellpadding` / `border` on tables are dropped, not rewritten;
  - "Load images" can now read `src` from the `Src` attribute of the image node.
- **E-BR:** the Knuth-Plass path (justify / `text-wrap: pretty`) still measures from items.
- **Table:** rowspan is ignored in the table's intrinsic sizes, and a spanning cell's extra is
  spread evenly rather than by the columns' max-content ratio.
