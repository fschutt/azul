Branch `wt/wpt-reg`, cut from `05ef3a8f4` (the gate binary was built from `889dccf30`; the two
differ only in `dll/.../transient.rs` and `scripts/azlin_e2e.py`, so the gate's results hold for
this base). Nothing was compiled (house rule): every fix is marked "(unverified)" in its commit.
Every root cause was SEEN first - the gate's diff PNGs (`target/wpt/reftest_diffs`, kept in
`/tmp/wpt/gate_snapshot`), and the prebuilt AzPaint (headless, capped runner) with E2E `mount`
scenarios: `get_display_list`, `get_layout_tree`, `get_all_nodes_layout`,
`get_node_css_properties`, and `AZ_E2E_SHOT_DIR` screenshots - then read off the code.

## 0. The key finding: the "regressions" were mostly never passing

`tests/wpt/reftest_expectations.txt` was SEEDED on 2026-09-30 from a sweep through the debug
server (its header says so) and has NEVER been blessed from this runner. Since then agents took
entries out by PREDICTING their fixes (`8fba0bcdf`, `8a8d980ea`, `978441b69`, `4958a31e7`,
`03ba7769c`), without a run. 12 of the 19 are such predictions (border-collapse-offset-002,
collapsing-border-model-003/009, height-table-cell-001, height-width-table-001,
anonymous-table-ws-001, table-cell-width-s, table-width-s and the TABLE ones) or entries the seed
sweep wrongly saw passing. Only a few are true regressions from recent commits (the list markers:
`116feca4d` / `1b580afc3`; the references that started rendering a feature the test pages lack:
TABLE_A's percentage columns, `fit-content`, `list-style: none`). Each one below is decided on what
Chrome / the WPT reference shows, not on history.

How the root causes were seen (reusable, no cargo): `/tmp/wpt/tools/mk.py <name> <pages..>`
writes an E2E scenario that mounts each page (body + its `<style>`), screenshots it and prints
its display list / layout tree; `/tmp/wpt/tools/run_e2e.sh <name>` runs it on the prebuilt
AzPaint (`AZ_BACKEND=headless AZ_E2E=.. AZ_E2E_SHOT_DIR=..`) through `run_capped.sh`;

state - a later page with the same stylesheet text was not restyled (the m9x run: a list item
with neither margin nor marker) - give each page its own scenario or a distinct stylesheet.

## 6. Left / seen on the way

- Features the 6 listed tests need: `:not()` (a new `CssPathPseudoSelector` variant: api.json),
  the table wrapper box (caption outside the table box; the table's border/background painted
  around the grid only), `display: inline flow-root list-item`, `list-style-type: <string>`,
  `::before` (WPT8 sec. 7 has the design), HTML's conditional `th` centring with `inherit`
  honoured over the UA value, float clearance across sibling blocks (floats inside a non-BFC
  block are not visible to a later sibling's `clear`).
- TWIN (NO DUPLICATION): `fc::get_border_info` (the collapsed-border resolution) duplicates
  `getters::get_border_info` with other defaults - a style without a width is 0 there and
  `medium` in the painter, no colour is black there and currentcolor in the painter. Merging
  them (the fc one resolving the getters' used values) is the clean fix; it moves the
  collapsed-border tests, so not done blind.
- The static position is recorded in block flow only: an absolute box inside an inline
  formatting context or a flex / grid container still takes its parent's content-box origin.
- E2E `mount`: a second mount with an identical stylesheet skipped the cascade for the new DOM
  ("pre-cascade fingerprints equal") - the new nodes kept no style (seen, not chased).
