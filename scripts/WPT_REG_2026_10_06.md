# WPT_REG - the 19 reftest "regressions" of the 2026-10-06 gate (wave 9 follow-up)

Branch `wt/wpt-reg`, cut from `05ef3a8f4` (the gate binary was built from `889dccf30`; the two
differ only in `dll/.../transient.rs` and `scripts/azlin_e2e.py`, so the gate's results hold for
this base). Nothing was compiled (house rule): every fix is marked "(unverified)" in its commit.
Every root cause was SEEN first - the gate's diff PNGs (`target/wpt/reftest_diffs`, kept in
`/tmp/wpt/gate_snapshot`), and the prebuilt AzPaint (headless, capped runner) with E2E `mount`
scenarios: `get_display_list`, `get_layout_tree`, `get_all_nodes_layout`,
`get_node_css_properties`, and `AZ_E2E_SHOT_DIR` screenshots - then read off the code.

## 0. The key finding: the "regressions" were mostly never passing

`tests/wpt/reftest_expectations.txt` was SEEDED on 2026-09-30 from a sweep through the debug
server (its header says so) and has NEVER been blessed from this runner. Since then agents took
entries out by PREDICTING their fixes (`8fba0bcdf`, `8a8d980ea`, `978441b69`, `4958a31e7`,
`03ba7769c`), without a run. 12 of the 19 are such predictions (border-collapse-offset-002,
collapsing-border-model-003/009, height-table-cell-001, height-width-table-001,
anonymous-table-ws-001, table-cell-width-s, table-width-s and the TABLE ones) or entries the seed
sweep wrongly saw passing. Only a few are true regressions from recent commits (the list markers:
`116feca4d` / `1b580afc3`; the references that started rendering a feature the test pages lack:
TABLE_A's percentage columns, `fit-content`, `list-style: none`). Each one below is decided on what
Chrome / the WPT reference shows, not on history.
