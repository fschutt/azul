## What was built

**Before:** `var()` was substituted at PARSE time, per stylesheet string, blind to conditions
(`parser2::css_blocks_to_stylesheet`, one flat map, last definition wins). A `:root { --x }` in one
sheet never reached a `var(--x)` in another sheet or in a node's own declarations, and
`@theme(dark) { :root { --bg } }` next to a light definition collapsed to whichever came last.

**Now** (one resolver, consulted by both cascades):

1. **Definitions are declarations.** `--name: value` parses to
   `CssDeclaration::CustomProperty(CssCustomProperty { name, value })` (value kept verbatim), in
   stylesheet rules and in a node's own style alike, under the rule's `@theme` / `@media` / `@os` /
   pseudo-state conditions. Stored per node by the cascade and INHERITED: the nearest definition
   wins (pitfall 1: priority does not cross inheritance distance; a node's own definition beats the
   rules matching it).
2. **References stay unresolved in the declared value.** `var(--a, var(--b, 1px))` is one
   `CssDeclaration::Dynamic` with `dynamic_id = "a,b"` and the innermost literal as fallback.
   `CssPropertyCache::restyle` resolves them per node under the live `DynamicSelectorContext`
   (the `env()` precedent): stylesheet references through placeholders in `css_props` (cascade
   order kept), a node's own references into `CssPropertyCache::resolved_inline`. Every cascade
   reader of inline style now goes through ONE view, `CssPropertyCache::inline_properties`
   (slow path x10 sites, compact builder, both inheritance passes, hit-test tagger,
   restyle-on-hover). A light/dark flip re-resolves through the restyle path, no DOM rebuild.
3. **Resolver** (`css/src/custom_properties.rs`): `CustomPropertyMap::cascade` (parent map +
   own definitions, `var()` inside a definition substituted WHERE DEFINED, cycles make every name
   in them invalid at that node, value size capped at 64 KiB and nesting at 128 against hostile
   themes); `VarResolver` / `resolve_var` (first name of the chain whose value parses as the
   property, else the fallback; memoised per restyle). Per-node maps
   (`core/src/custom_property_cascade.rs::CustomPropertyEnvs`) are shared structurally: a `:root`
   palette is one map for the whole DOM.
4. **Pseudo-states**: a `:hover { --x }` definition applies while hovered; a resting `var(--x)`
   consumer that WINS its property is re-resolved for that state ("state variant") unless the
   state declares the property itself - `.btn:hover { --bg } .btn { background: var(--bg) }`
   works like on the web.
5. **Missing variable**: the declared fallback; no fallback = the property's initial value, a
   parse warning (`CssParseWarnMsgInner::VarWithoutFallback`) and, at runtime, a warning once per
   name via `diagnostics::emit` (`AZ_SUPPRESS=var_fallback`).
6. **`var()` on `background` / `background-color`** (a shorthand expanding to ONE longhand) is
   accepted - the design's own example `background: var(--azul-button-face, system:button-face)`.
   Multi-longhand shorthands (`margin`) are still refused. A value is a `var()` only if it IS the
   call (`var(--a) 1px` used to be silently truncated to `var(--a)`).
7. **Invalidation (pitfall 11).** Resolution happens in the restyle, so a variable change is a new
   `cascade_epoch` like every cascade input (the DL key and `StyleCache` key already carry it).
   `set_dynamic_selector_context` re-runs the cascade when variables depend on the context, even
   with an EMPTY author sheet (a node's own conditional definition or `env()`), and
   `restyle_retained` no longer skips an empty sheet when nodes use variables. The reconcile
   (`diff.rs`) reports a definition-only change (`NodeChangeSet::CUSTOM_PROPERTIES`, in
   `AFFECTS_LAYOUT`, `RelayoutScope::Full`: any descendant may read it) and a changed `var()`
   consumer as its property; the node/style fingerprints hash every declaration kind - before,
   a definition edit fingerprinted as "unchanged" and a DL patch would splice stale readers.
8. **Lint (gap 1).** Every `var()` must declare a fallback: an ERROR in the widget manifest lint
   (`layout/src/widgets/mod.rs::var_fallbacks`, next to `theme_pairs`, walking each widget's own
   declarations and attached sheets), a parse warning at runtime; the reftest
   `CssWarningCollector` (`doc/src/reftest/mod.rs`) shows the parse warning automatically.
9. **Codegen**: a flat style (`lower_styles`) resolves a `var()` against the stylesheet's own
   definitions (what the parser used to do) - the ENV goldens for all 35 languages are unchanged.
10. Docs: `doc/guide/en/styling.md` section rewritten (the old one described a removed API).

  `specific_rules` AFTER `css.sort_by_specificity()`, and `CustomPropertyMap::cascade` takes the
  LAST definition of a name - so once rank is in the sort key, a spin-off's `:root { --x }` beats
  its base's automatically, with no change on my side. Two places evaluate conditions for
  variables and must follow R2's matching: the rule gate `rule_applies` in `restyle` (already
  yours) and `applying_state` in `core/src/custom_property_cascade.rs` (a node's OWN

  `build_compact_cache_with_inheritance_debug` would not. A node's own definition beats any

## What is left

- **Pitfall 2 lint** (a colour variable set in one mode block must be set in the other or at top
  level): not built - it belongs to the rice loader lint (R4 step 4); the data it needs is
  `CssCustomProperty` + rule conditions, both available now.
- `var()` inside other tokens (`box-shadow: 0 0 4px var(--c)`, `calc(var(--x) * 2)`) is not a
  reference yet - the property parser sees the raw text and rejects it (unchanged from before).
  Definitions may hold such text already (substitution is token-level inside definitions).
- Widgets have no Rust constructor for a `var()` consumer or a definition in
  `CssPropertyWithConditions` (a static-property type); today they go through
  `NodeData::with_css("background: var(--x, system:..)")` / `Css::parse_inline`. Worth a small
  api addition when the widgets move to variables (theme rework step 5).
- `layout/src/icon.rs::copy_appropriate_styles_vec` copies only static declarations, so a `var()`
  on an `<icon>` node is dropped when the icon resolves (pre-existing for `env()` too).
- `StyledDom` composition (`append_child`): the appended subtree keeps the variables it was
  cascaded with until the next restyle (same limitation the author rules have).
- Ancestor `:hover` variables reach a descendant in the DESCENDANT's own hover state
  (`.card:hover { --fg } .card .label { color: var(--fg) }` recolours the label while the pointer
  is on the label, not on the card's padding) - the engine's existing rule for inherited state
  values; the same-node pattern works. Documented in `custom_property_cascade.rs`.
- Pathological input only: past `MAX_REFERENCE_DEPTH` (128) the invalid result is cached, so
  which names of a >128-deep definition chain survive depends on name order.
- Invalidation granularity: a variable change is a whole-DOM epoch (like a theme flip). The
  per-node reconcile flag is precise for app-driven definition edits; nothing finer (per-variable
  reader sets) was needed by the tests.
