# OFFICE7 - the Office apps' leftovers (wave 7, 2026-10-03)

Branch `wt/office7` from `2e55eef06` (the wave-6 integration). Brief: `scripts/waves/wave7/OFFICE7.md`.
Progress file: `scripts/OFFICE7.PROGRESS.md`. Nothing was compiled (house rules): every edited Rust file was
parse-checked with `rustfmt --emit stdout`, every Python script with `py_compile`. The LOOK ran the prebuilt
wave-6 binaries headless, one at a time through `run_capped.sh`, `wait_settled` before every screenshot.

## 1. What was built (brief items in order)

1. **AzWriter / AzNotes ids are `const AzString`** (`AzString::from_const_str`, the prefix ruling) - every
   `ids.rs` entry; the id-taking helpers (backstage buttons; AzNotes' toolbar, header, sheet, settings
   helpers) take the `AzString`. AzNotes' `editor::HOST_ID` alias of `ids::NOTE_BODY` is gone (one name).
2. **AzReview's ink follows the pointer on `MouseMove`** (MouseOver fires on entry since 2a7712f66: a stroke
   kept one point and every drag was taken for a click). The ink layer is its own function (`ui::ink_layer`)
   so a unit test reads its handlers; the E2E checks the archived stroke holds the moves.
3. **AzWriter**
   - `Update::max_self` folds the ribbon's updates; `commands::merge` (its twin) and its test are gone.
     Needs the api.json method (section 3).
   - **The import reads the picked file on a Thread, through the Drive pattern**: azul-appkit gained the one
     way to read a file the user picked outside the data tree - `files::outside_read(path)` (the folder for
     a drive and the `Get` job; the key is the file's name), `files::read_outside(path)` (before the window:
     a file on the command line) and `ui::spawn_outside_read(info, path, reply_to, tag, on_done)` on the
     kit's one file thread, whose drive is now `LocalDrive::new` for the data tree and
     `LocalDrive::without_manifest` for a folder outside it (no `.azlin/` in the user's folder). AzWriter's
     dialog callback hands the path over; the answer arrives in `on_files_done` as tag `IMPORT` and
     `commands::finish_import` makes it the new document (`commands::imported` turns the read into the
     document or the sentence the user reads). AzMail's attachments are read with `read_outside` too.
4. **AzNotes' title reads as a title**: the field says `font-size: 22px; font-weight: bold` (as an `<input>`
   would). The weight shows now; the size needs two engine fixes I found and handed over with RED tests
   (section 6): the TextInput's value `<p>` pins 11 px (WIDGETS7), and a stretched flex-container item loses
   its `min-height` (LAYOUT7: the title field is 17 px in its stretching row, the tag field 22 px).
5. **AzMail's files go through the azul-storage Drive - ONE Drive at the data root, the account as its
   scope** (MAIL6 sec. 8, DEDUP_EDITORS B3):
   - `store::LocalFolder` (its own temp-file-and-rename writer) became `MailStore` over a `DriveFolder`:
     inside the data tree a `ScopedDrive` of the tree's ONE `LocalDrive` (its writes land in the one
     `.azlin/cache`), outside it (an account synced to a chosen folder elsewhere, `AZMAIL_DATA` outside the
     data root, `azmail-send --data`) a `LocalDrive::without_manifest` of its own. `DriveFolder::of(path,
     data_root)`, `outside`, `locate`, `child`, `path`; `MailStore::{put, get, delete, size_of, keys,
     subfolders, move_prefix, folders}`.
   - `account.rs` (`account_dir` / `mail_root` give DriveFolders; `save` / `load` / `load_all` read and write
     `<id>/account.json` through the drive), `send.rs` (`sending.json`, `send_policy.json`, the outbox
     entries and messages, the Sent copy of `file_message`), `sync.rs`, `compose.rs` (drafts), `sample.rs`,
     the windows and `azmail-send` all go through `MailStore`; `store::write_atomic` is deleted - no file
     of AzMail is written beside the Drive any more.
   - The durable (fsync) flag is gone (decision, section 8). The reading pane keeps its `em` zoom with a
     `TODO(LAYOUT7)` to move to CSS `zoom` (not in my base).
6. **AzShow**
   - **Text boxes on the shared RichTextEditor / RichTextDoc; `ir.rs` (AzWriter's former IR, 1344 lines) is
     deleted.** A box's `TextBody` is shown and edited as a `RichTextDoc` in azul's `RichTextEditor`:
     read-only on the slide, in the rail, the show and the PDF; editable while edited (its typing, Enter /
     Backspace across paragraphs, B / I / U / S from the keys and the ribbon, its ONE undo history). Every
     edit comes back through `on_change` (`views::on_text_change` -> `text::set_from_rich`).
     `Editor::text` keeps the editor's state while it still shows what the body holds (`text::state_for`);
     the body stays the truth. A bullet is a `Bullet(level)` item; an unbulleted paragraph keeps its level by
     index. Gone: `sync_typing`, `apply_structural`, `toggle_range`, `FormatAxis` (azul's `RichFormat`
     instead), the DocumentEdit / TextChanged hooks. For slides the editor needed two things it did not
     have, added minimally in WIDGETS7's `rich_text_editor.rs` with a RED test first:
     `RichTextEditor::with_line_height(factor)` (slides use 1.15; 0 keeps the editor's 1.5) and list / check
     / quote indents proportional to the font size (an em of the 14 px default: identical at 14 px; a
     thumbnail's bullets no longer start past its middle, AzWriter's zoom scales its lists too).
   - **Tables are edited in place**: a double-click on a table edits its cells (`Editor::activate`); each
     cell is an editing host of its own in the slide's themed rendering (`views::editable_cell`); typing is
     folded into the cell (`Editor::set_cell`), Enter stays in the cell, Tab / Shift+Tab go to the next /
     previous cell (`views::next_cell`), Tab in the last cell adds a row (`Editor::add_table_row`, one undo
     step); Escape leaves. The focus after a rebuild is now a DOM id (a text's host or a table's cell).
   - **The presenter window opens on a chosen monitor**: SLIDE SHOW > Monitors (a DropDown: Automatic, then
     every connected screen from `get_monitors`); `PresenterMonitor::resolve` picks the chosen one while it is
     connected, else the first screen that is not the show's (none with one screen); `start_show` sets the
     new window's `window_state.monitor_id` (the shells place a new window by it). Remembered in
     settings.json (`presenter_monitor`).
   - **The drop line in the slide rail** (ThumbnailStrip, a minimal edit of WIDGETS7's file): DragOver on a
     thumbnail draws a 3 px line in the system accent on the side the drop lands (`drop_target`), as a
     transient override in the item's right shadow slot; DragLeave, the drop and a DragEnd without a drop
     take it away.
7. **AzSheets**
   - **Format Cells' OK is ONE undo step**: `SheetEngine::update_styles(area, patches)`. The fake engine
     takes one snapshot. IronCalc's UserModel makes every call a step and cannot group them, so the engine
     runs every change through IronCalc's own paths (style paths, borders that reach the ring of cells
     around the area), reads the resulting styles of the area and its ring, undoes the changes and writes the
     result back as ONE `on_paste_styles` - one step. Whole rows / columns keep a step per change (IronCalc's
     row / column styles). The worker has one style command, `Styles` (the ribbon's one change and OK's
     several); `Command::Style` is gone.
   - **Replace inside the grid's own edit**: with the active cell in edit (the grid keeps its edit open while
     the dialog has the focus), Replace replaces in the text being edited (`replace_in_edit`), the edit stays
     open - before, it changed the stored input and the commit wrote the old text over it.
   - **Any colour**: the Font, Fill and Border tabs have a `ColorInput` ("More colors") beside the presets;
     `FormatDraft::{set_font_color, set_fill, set_border_color}` read any `#rgb` / `#rrggbb` / `#rrggbbaa`
     with azul's `ColorU::parse_hex` and keep `#RRGGBB`. Borders are no longer always black.
   - Not done, decided (section 8): a font family picker, border line styles, merges that shift with
     inserted rows.
