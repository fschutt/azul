## What was built

### `examples/azul-notes` (package `AzNotes`, lib `aznotes`, bin `AzNotes`, link-dynamic)

Three panes on the S4 `PimShell` under the app-drawn `Titlebar` (`NoTitle`), in a
`ShellThemeScope` (Leaf accent), flat + flora, light + dark:

- **Navigation** (`ShellNavigationPane`): New note / New notebook / Settings in its header;
  groups Library (All notes, Pinned, Trash, with counts), Notebooks (nested tree with counts,
  opened / closed by the user), Tags (with counts). A click shows that scope; the open note
  stays when the list holds it, else the list's first note opens.
- **Note list** (azul's `MessageList` with the new `MessageListMark::Pin`): title, first line,
  notebook + tags, date ("09:14", "Yesterday", "Tue", "Sep 30", "2025-09-30"), a glyph for a
  checklist / image / code note, the pin on pinned notes; sections Pinned, then Today /
  Yesterday / Previous 7 days / Previous 30 days / months (by title: Pinned, Notes); search as
  you type over title + text + tags + notebook (every word; `#tag` matches tag prefixes);
  Arrange by date modified / created / title and the direction; Delete moves to the Trash
  (in the Trash a confirmation deletes for good); empty states.
- **Editor pane**: where the note is and when it was edited; pin, version history, export PDF
  (`Pdf::from_dom_in_callback`, A4) and Markdown, move to Trash; the Trash bar (Restore /
  Delete forever); the title field; tag chips + a tag field (Enter / comma / leaving it adds);
  the formatting toolbar (H1-H3, bold, italic, underline, strikethrough, inline code, bulleted /
  numbered / check lists, outdent / indent, quote, code block, link, rule; the caret's block
  kind pressed); the rich-text editor (`editor.rs`).
- **The editor**: the note's body is a FLAT list of blocks (paragraph, heading 1-6, bullet /
  numbered / check item with an indent level, quote, code block, rule, image) of styled runs
  (bold, italic, underline, strike, code, link), rendered as ONE contenteditable host: one
  host child per block, one block child per run, so the engine's child-index paths are model
  indices. List items are `li` directly under the host (the engine's `::marker`); a numbered
  item numbers itself with `counter-reset: list-item <n-1>`; a check item's box is an
  absolutely positioned `contenteditable=false` island AFTER the runs (out of the inline
  formatting context, walled off from the edited text) that ticks on click. Typing: TextChanged
  -> `get_unsynced_text_edits` -> `Doc::sync_block_text` (prefix/suffix diff, the runs keep
  their formats) -> ack, no rebuild. Enter / Backspace / Delete at block edges and a delete,
  type-over or paste across blocks: DocumentEdit -> split / merge / ReplaceChildren (multi-block
  paste with its b/i/u/s/code) applied to the model -> `mark_document_edit_applied`. Keys the
  editor owns: Enter in a code block (a line break; Enter on its empty last line leaves it),
  Enter on an empty list item (out a level), Backspace at the start of a list item / heading /
  quote / code block (back to a paragraph), Tab / Shift+Tab in a list, Ctrl/Cmd+B I U (the
  engine paints the typing style, the model records it; over a selection the model formats),
  Shift+X strike, E code, 0-3 paragraph / headings, Shift+7 8 9 lists, Enter ticks. **Markdown
  shortcuts as you type**: `# ` `## ` `### `, `- ` `* ` `+ `, `1. `, `[ ] ` / `[x] ` (also inside
  a bullet, so `- [ ] ` typed in a row ends a check item), `> `, ` ``` ` - only when the edit
  typed the trigger (a paragraph `# x` read from a file stays text).
- **Command palette** (Ctrl/Cmd+K, `ShellCommandPalette`): new note / notebook, the open
  note's pin, history, PDF / Markdown export, trash, **Move to <notebook>** (one per notebook),
  show a scope / notebook / tag, settings, shortcuts, about, theme and mode, and **every note
  to jump to** (newest first).
- **Settings** (`ShellSettingsLayout`): General (theme, mode), Editor (text size, the autosave
  pause, how often a version is kept, the shortcuts), Storage (the notes folder, the layout,
  read the folder again), Keyboard shortcuts, About. Kept in `aznotes-settings.txt` beside
  `notes/`.
- **Version history** (A2): a version per save under `notes/.history/<uuid>/<stamp>.md` (at
  most one every 5 minutes while typing; always on Ctrl/Cmd+S, switching notes, closing); the
  History screen lists them, draws the chosen one read-only with the lines changed from it to
  now (`model::line_diff`), and restores it (the current file kept as a version first).
- **Storage** (`store.rs` + `jobs.rs`): one Markdown file per note,
  `notes/<notebook>/<uuid>.md` with a front matter (title, tags, pinned, created, modified;
  unknown keys kept verbatim), through azul-storage's `Drive` on a `LocalDrive` rooted at the
  AzNotes folder (`--data`, `AZNOTES_DATA`, else `AzNotes` in the user's data folder), every
  call on an azul `Thread`, the answer through the write-back. Autosave 500 ms after the last
  edit (one save per note on the way; a save that raced an edit leaves the note dirty); on
  switching notes; on close (the window vetoes its close, saves, then closes). A move takes the
  note's images along and deletes the old file; the Trash is `notes/.trash/<notebook>/`; an
  empty notebook is a `notes/<notebook>/.notebook` marker. **External edits**: on window focus a
  rescan reads only files whose modified time changed (a note with unsaved edits keeps them,
  with a notice), drops notes whose file is gone. **Images** dropped on the window go to
  `notes/<notebook>/<uuid>/assets/` (`azul_storage::transfer::upload_file`) and into the note
  as `![alt](<uuid>/assets/<file>)` blocks; images are read and decoded as notes open.
- **Markdown both ways** (`markdown.rs`): pulldown-cmark 0.9 (already in the lock through
  AzWriter, same features) into the flat blocks; one canonical writer back (emphasis markers
  with whitespace kept outside, escapes for text that would read as syntax, fences that grow
  around backticks, list indents at the parent marker's width, a blank line between lists of
  different markers, `\` hard breaks, `<u>` for underline). Round-trip tests.
- **`--sample`** (`sample.rs`): 8 notes in nested notebooks (Work/Offsite, Work/Meetings,
  Personal, Personal/Recipes, Reading), tagged, two pinned, with headings, lists, checklists,
  code, quotes and links, fixed ids, dated relative to now; an empty Archive notebook. Files
  that exist are never overwritten.
- `args.rs`: `--data`, `--sample`, `--screen notes|settings|about|shortcuts|history|palette`,
  `--theme flat|flora`, `--mode light|dark`, `--size WxH`, `--note <id>`.
- stdout for scripts: `AZNOTES_DATA`, `AZNOTES_LOADED n`, `AZNOTES_OPEN id`, `AZNOTES_NEW id`,
  `AZNOTES_SAVED id key`, `AZNOTES_SCREEN name`, `AZNOTES_SCOPE label`, `AZNOTES_RUN label`,
  `AZNOTES_NOTEBOOK path`, `AZNOTES_EXPORTED pdf|md bytes`, `AZNOTES_RESTORED id`,
  `AZNOTES_OPENED_LINK url`.
- Links: Ctrl/Cmd+click on a link in the text, or Open in the link sheet, opens it with the
  system's handler (`azul::url::Url::open`). The host's blocks carry `#nb-<index>`.

Unit tests (in the crate, no window): `doc.rs` (typing keeps formats, typing style, split /
merge / cross-block delete / multi-block paste, shortcuts typed vs. read, numbering, indents,
toggles), `markdown.rs` (the sample round trip, nested formats, tricky text stays text, line
breaks, code fences, list indents, front matter incl. hand-written YAML), `model.rs` (keys,
versions, notebook names, search, scopes, sections and order, counts and tree, dates, moves /
trash / tags, a note file round trip, the line diff), `store.rs` (every job on a LocalDrive in a

## Decisions taken unattended

- D1 The editor is app-local (`editor.rs` + `doc.rs` + `markdown.rs`), written to be promoted to
  `azul::widgets::RichTextEditor`; promoting it needs a design pass on its api surface (blocks,
  runs, events) and a compiler. AzWriter's `ir.rs` is the TWIN (an IR of paragraphs / lists /
  tables with `apply_operation`); the flat block model here is the one to promote (it maps 1:1
  to the engine's child-index paths, keeps check items and indents, and has the round-trip
  Markdown writer).
- D2 Flat blocks, `li` directly under the host, `counter-reset` per numbered item, the check box
  as an abspos `contenteditable=false` island after the runs.
- D3 The note list is `MessageList` (+ the Pin mark), not a new list.
- D4 Typing syncs without a rebuild; shortcuts / toolbar / structural edits rebuild after the
  ack; switching notes / restoring / an external edit call `reset_editor_content`.
- D5 Dates in files through `azul_storage::time` (ISO 8601), local display through chrono.
- D6 Empty notebooks persist as `notes/<notebook>/.notebook` markers; the Trash is
  `notes/.trash/<notebook>/` (restorable, the notebook kept in the path).
- D7 A version at most every 5 minutes while typing (setting: every save / 5 / 15 / 60 min),
  always on explicit save, note switch, close and before a restore - a version per AUTOsave
  (every 500 ms pause) would flood the history.
- D8 Local unsaved edits win over a file changed on disk (a notice says so); the next save
  writes over it.

  screenshots (`palette.png`, `flat-light.png`, `flora-dark.png`, `settings.png`,

  rebuild (the block's element type changes under the session), the check island's hit target
  inside the editable `li`, Enter in a code block via `insert_text`, the multi-block paste.
- Typing-style formats are mirrored by the app (the sync API hands over text, not runs): a run
  the engine styled by its own typing style but the app never saw (a typing style set by the
  engine without the app's key handler) would be plain after the next rebuild. A run-level sync
  (`DocumentTextEdit` with the runs' formats) would close that seam in the engine.
- Structural undo: splits / merges are acked without an inverse (text undo works); the inverse
  needs a resume-path convention for replayed inverses (AzWriter's `apply_operation` keys on the
  resume path).
- Links open with Ctrl/Cmd+click on the span (needs the inline element's hit area, which
  `a_click_on_a_link_inside_a_paragraph_reaches_the_link` covers) or from the link sheet.
- Pasting an image (clipboard images are not decoded by the dll); dropping one works.
