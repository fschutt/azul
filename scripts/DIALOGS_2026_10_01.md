# DIALOGS - install-wizard pages, settings-dialog patterns, standard dialogs, AzSetup (2026-10-01)

Branch `wt/dialogs` from `16d19442c`. Nothing was compiled (house rule): every Rust file was
parse-checked with rustfmt (scratchpad `dialogs/parse_check.py`: each file alone, `mod x;`
neutered, `rustfmt --emit stdout`), the new leaf files are rustfmt-formatted, the Python script
byte-compiled. No app binary was run. Every test, the lints, the AzSetup build and the E2E are for
the parent (commands below). The run was resumed once after a network cut; nothing was lost.

## 1. What was built

All of it EXTENDS what the base had (WizardLayout, ShellSettingsLayout, Modal / Dialog, FileDialog,
`file::disk_space`); nothing existing was duplicated. Every new widget: a `#[repr(C)]` builder with
`create*`, `set_*` / `with_*`, `swap_with_default`, `dom()`, a `theme: OptionUiTheme` pin (unset it
follows the app theme), flat AND flora, light AND dark (every colour a `decl::themed_*` pair),
keyboard, accessibility, unit tests, the lint manifest and a theme-contrast group.

### ONE look for every dialog widget - `widgets/dialog_kit.rs` (new)

`DialogKitLook` (37 parts: page, heading, text, hint, logo, block, label, scroll_box, list_row,
size, total, check_row, check_label, description, summary_key / _row, field_row, field_label, help,
mark, modified, unit, recorder, recorder_recording, dialog, icon_info / _warning / _error /
_question, buttons, button, held, notice, category_icon) built by `themes::flat::dialog_kit_look`
and `themes::flora::dialog_kit_look` (appended at the END of both theme files under `// ==== dialog
kit ... ====`), merged per part for the follow path (`follow_look`, the shells' shape: one build,
the app's content never cloned). The structure is the kit's `*_BASE` statics plus the shells' bases
(`COLUMN_BASE`, `GROW_COLUMN_BASE`, `GROW_LABEL_BASE`, reused, not copied). Shared builders - the one
place each shape lives: `line` (a widget-owned `<p>`), `highlighted_line` (the first
case-insensitive match in a `<mark>`, `find_ignore_case` char-boundary safe), `row_button` (a
button in its box; INERT = no click, `TabIndex::NoKeyboardFocus`, announced `Unavailable`,
described by a reason, its box stacked with the `held` skin - used by the wizard, the settings
dialog and the standard dialogs), `check_row` (CheckBox named by its label + the label a click
target), `percent_text`.

### 1. Install wizard

- **`WizardLayout` (extended)**: `WizardLayoutStyle { Rail, Banner, SidePanel }` - the Windows
  installer's banner (the step's title, `subtitle`, the `icon` glyph at its right; no rail) and the
  macOS installer's side panel (glyph, the steps marked done / current / to come, the current one
  `Selected`, a List of ListItems); `WizardLayoutSize { Fill, Compact 500x380, Classic 640x480,
  MacInstaller 620x440, Large 800x600 }` (`width()` / `height()`; a fixed size sets the frame's
  width / height); the VALIDATION HOOK `set_validation(reason)` / `with_validation`: a reason
  holds Next (or Finish) - inert, dimmed, Unavailable, described by the reason - and takes the
  spacer's place in the button row (`look.reason`, the warning ink); `is_next_held()`;
  `can_go_back` holds Back the same way (an installer's progress / finish pages). Look parts
  added to the existing `WizardLayoutLook` (both theme fns filled in place).
- **`widgets/wizard_pages.rs` (new)**: `WizardWelcomePage` (logo, title, paragraphs),
  `WizardLicensePage` (the agreement in a box that scrolls - a named Document, a Tab stop with a
  focus ring - and "I accept"; `blocked_reason()`), `WizardDestinationPage` (`PathInput`, "Space
  required / available" from `format_bytes`, a Warning `InfoBar` and a reason when the drive is
  short or the folder empty), `WizardComponentsPage` (a checklist tree indented by depth, sizes set
  right, descriptions, the total; `toggle(index, checked)`: a group carries its parts, a part its
  group, a required component stays; `total_bytes()`; `blocked_reason()` when nothing is
  ticked), `WizardOptionsPage` (checkbox rows; options sharing a non-zero group are ONE
  `RadioGroup`; `choose()` keeps one radio per set), `WizardSummaryPage` (key over value in a
  scroll box), `WizardProgressPage` (status, `ProgressBar` + "42 %", current item, "Show / Hide
  details" (Expanded / Collapsed) and the log box; `is_done()`), `WizardFinishPage` (logo, title,
  text, the actions as options). ONE callback type `WizardPageOnEventCallbackType` with
  `WizardPageEvent { text, index, kind, checked }`.
- **`widgets/path_input.rs` (new)**: `PathInput` - a field + "Browse..." that opens
  `FileDialog::open_directory` (or `open_file`) under `cfg(feature = "extra")`, FileInput's resume
  shape; typed or picked, ONE `on_change(path)`. Used by the destination page and the settings'
  Path row (no twin).
- **`file::disk_space_for_new(path)` / `FilePath::disk_space_for_new`** (RED-first test): the
  volume of the nearest EXISTING ancestor - an installer's destination does not exist yet, and
  `disk_space` answers `None` for it.

### 2. Settings dialogs

- **`ShellSettingsLayout` (extended)**: `category_icons` and `category_badges` (parallel to the
  categories; a Badge per category - the match count while searching), a `footer` row under the
  body, and `ShellSettingsSection::keywords` (a search keeps a section whose SETTINGS match, not
  only its title).
- **`widgets/shortcut_recorder.rs` (new)**: `ShortcutRecorder` records a `GlobalHotkey` (the type
  apps already declare hotkeys with), shown with `to_display_string`; click / Enter / Space listen,
  the next key with its modifiers records (a modifier alone waits, Tab leaves, F-keys stand
  alone), Escape or leaving the field cancels, Backspace / Delete clears; a `HotkeyField`, one Tab
  stop, `Busy` while listening; `apply(event)` is the app's rule.
- **`widgets/shells/settings_dialog.rs` (new, module `shells`)**: `ShellSettingsDialog` builds a
  whole settings window from a table: `ShellSetting { id, label, help, keywords, section, value,
  default_value, applied, category, requires_restart }`, `ShellSettingValue { Toggle (Switch),
  Choice (DropDown), Number (NumberInput + unit), Text, Path (PathInput), Color (ColorInput),
  Shortcut (ShortcutRecorder), Slider (Slider + read-out), Radio (RadioGroup) }`. Search across
  every category (label / help / keywords / section / category name), sections retitled
  "Category: Section", the match marked, counts on the categories, "No settings match the
  search."; a changed setting carries the modified dot; "Requires restart" Warning badge; the
  button row: "Restore defaults" (the shown category), the restart notice, then OK / Cancel /
  Apply (Apply held while nothing changed) - or nothing more in `ShellSettingsApplyMode::Instant`
  (`platform()`: Instant on macOS). `apply_event` is the rule (Changed, CategoryChosen clears the
  search, SearchChanged, RestoreDefaults, Apply / Ok put changes in effect and raise
  `restart_pending` for a restart setting, Cancel drops, Start / StopRecording);
  `is_dirty`, `dirty_count`, `value_of(id)`, `matches_in(category)`. Joins the shells' lints
  (`OWN_PREFIXES` += `__azul-native-settings-dialog`, `every_shell`, `every_shell_pinned`).

### 3. Standard dialogs - `widgets/standard_dialogs.rs` (new)

Checked first: Modal / Dialog are the containers; the desktop `MsgBox` is the OS's (no "don't ask
again", no app theme); no About / progress / login / find dialog existed. Built as BODIES for a
Modal / Dialog: `MessageBox` (`MessageBoxKind { Info, Warning, Error, Question }` glyph in the
alert palette's inks, title, text, detail, buttons with a default, "Don't ask again"; an Alert
named by its title), `AboutDialog` (icon, name, version, description, copyright, credits list
`StringPairVec` in a keyboard-scrollable box), `ProgressDialog` (bar + percent, or a `Spinner`
when indeterminate; Cancel, held via `can_cancel`; Busy), `LoginDialog` (user, password field,
Remember me, an error InfoBar, Sign in held until both fields are filled, Enter submits; it STORES
nothing), `FindReplaceDialog` (find / replace fields, Match case / Whole word, the status line,
Find previous / Find next (Enter) / Replace / Replace all, held while the find text is empty,
Close). ONE callback type `StandardDialogOnEventCallbackType` with `StandardDialogEvent`.

### 4. AzSetup - `examples/azul-setup` (package `AzSetup`, lib `azsetup`, bin `AzSetup`)

A fake "AzOffice" installer on the utility shell (S9) with azul's `Titlebar` (NoTitle), window
`WizardLayoutSize::Classic` + the title row: Welcome -> License -> Destination -> Components ->
Options -> Ready -> Installing -> Done. Wizard97 framing (side panel on welcome / finish, banner
between; `--frame installer|rail|side`), Next held by each page's `blocked_reason`, the
destination's free space from `disk_space_for_new`, the components page as the tick model, Install
starts a 60 ms timer that "copies" fake files (`model::Copier`), the progress page with the log,
Finish ("Launch AzOffice now", "Open the AzOffice settings" -> opens the settings window), Cancel
asks with a MessageBox in a Modal, F1 opens the AboutDialog in a Modal. The settings window is a
`ShellSettingsDialog` of 15 settings of every kind; Apply / OK put the "Appearance" theme
(`set_theme`) and mode (`set_mode`) in effect. `--screen setup|settings|about`, `--theme`,
`--mode`, `--step`. It installs and writes nothing (decision: no durable data in a fake
installer). stdout for scripts: `AZSETUP_STEP i label`, `AZSETUP_TOTAL bytes`, `AZSETUP_PATH`,
`AZSETUP_PROGRESS`, `AZSETUP_DONE bytes`, `AZSETUP_FINISHED launch= settings=`,
`AZSETUP_SETTINGS event`. `src/model.rs` has no azul types and the unit tests. Registered:
root `Cargo.toml` member, `scripts/workspace_test_members.txt`, `dll_tests` step "Run AzSetup
tests".

`scripts/azsetup_e2e.py` (never run): Next held by the license (the reason shows, a click changes
nothing), "I accept", Browse answered by the `mock` op (`file_open`), the space lines, clearing
AzSlides lowers 547 MB -> 477 MB (screen and `AZSETUP_TOTAL`), Options, Ready (the summary lists
the components without AzSlides), Install -> `AZSETUP_DONE` and "100 %", Show details -> the log,
Next, the finish page in flora / dark, Finish (`launch=true settings=false`); then
`--screen settings`: the categories and General's settings, Appearance -> "Interface zoom".
Screenshots per step. The debug-server client is IMPORTED from AzShells' `shells_e2e.py`, not
copied. Click-by-text matches the first text CONTAINING the string, so the app's texts were chosen
unique per page (the last step is "Done", the radio "Just for me", no "Install" in the summary).

## 3. api.json (never edited by hand; for `azul-doc autofix add`)

Conventions as the house rules: constructors `create*`; `&str` -> `String`; callback args
`<Name>CallbackType` with fn_body `<Name>Callback::create(callback).to_core()`-style as the
neighbouring widgets; `Vec`s via `impl_vec!` (+ Destructor, DestructorType, Slice, Option); every
struct `repr(C)`, fields as listed (decreasing alignment). Module: `widgets` unless noted; callback
types -> `callbacks`, `*Callback` wrappers -> `dom`, `Option*` -> `option`, `*Vec` -> `vec`.
`external` paths: `azul_layout::widgets::<file>::<Type>`.

## 6. Notes, twins, what is left

- **Button has no `disabled`** (HTML `<button disabled>`): every inert dialog button goes through
  `dialog_kit::row_button` (no click, no Tab stop, Unavailable, a dimmed box). A `Button::disabled`
  field would let the theme paint the disabled face (`DISBG` / `DISTX`) and serve every widget;
  not done here (high-traffic widget, both theme builders).
- **Stepper has no vertical orientation**: the side panel is its own step list (not interactive,
  as the macOS installer's is not).
- The look is written, not seen: screenshots from the E2E (and AzWidgets' Dialogs section) are the
  first look; spacing (subtitle margins, the 240 px label column) may want tuning.
- `examples/azul-shells/src/lib.rs` uses `VirtualKeyCode` without importing it (it is not in the
  prelude) - noticed, not touched (AzShells' file).
- Twins noticed: each app's E2E script carries its own debug-server client (AzSetup's imports
  AzShells'; a shared `scripts/e2e_client.py` would retire the copies in azul-calendar /
  azul-drive / azul-mail); every section module of AzWidgets has its own `keep` helper.
- The settings dialog's Slider reports on every move and the app rebuilds - a drag may want a
  "settled" report (as the list view's) if rebuilding mid-drag proves jumpy.
- No "Next" keyboard shortcut (Alt+N) or default-button Enter on the wizard; the Modal handles
  Escape for the message boxes.
