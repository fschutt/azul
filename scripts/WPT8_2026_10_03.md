## 7. What is left (root causes known)

- **Generated content (`::before` / `::after`)** - the counter tests' real blocker. Design: (1)
  `css/src/parser2.rs parse_css_path`: `::before`/`:before` (and after) become `DirectChildren` +
  `Type(NodeTypeTag::Before)` (the tag already exists, specificity of a type selector, no API
  change); (2) a `NodeType::Before` / `After` child is inserted as the first / last child of every
  element a pseudo rule's preceding compound could match, BEFORE the cascade (in the document
  loader's sink and in `StyledDom` creation from a `Dom`), so the normal cascade, inheritance and
  compact cache style it; (3) the layout tree gives it no box when its `content` computes to
  `none`/`normal`, else an inline box (its `display`), and `fc::collect_inline_span_recursive`
  produces its text from `content` (strings, `counter()` / `counters()` with the counters map -
  `compute_counters` already visits pseudo nodes -, `attr()`, quotes). Touches core
  (styled_dom / loaders: XML8's and the parent's), so it wants its own task.
- `display: inline list-item` (WPT inline-list): a `LayoutDisplay::InlineListItem` variant
  (api.json) + a marker inside the inline layout.
- Inline boxes: per-element inline fragments (nested spans' chrome, an outer inline's background
  under an inner one's margin - inline-formatting-context-002/006, split-inline-borders); line
  breaking ignores the inline insets; a span with several text children gets its insets per text
  node (fc.rs CASE 1 makes an `Arc` per text node; `inline_offsets` tells spans apart by `Arc`).
- Backgrounds: `background-size` / `background-position` are parsed but never painted, there is no
  `background-origin` and no `auto` size (`StyleBackgroundSize` defaults to `Contain`); gradients
  and images are sized to the clip box (gradients-with-border, tiled-gradients). `background-clip`
  is one value for all layers.
- E-GRAD leftovers: `currentcolor` stops, premultiplied interpolation through `transparent`.
- The compact cache packs "no border colour" and "transparent" alike (raw 0); `get_border_info`
  now asks the cascade for a visible side without a colour - a distinct sentinel would save that
  walk for `ring_slot`-style transparent borders.
- Twins seen (NO DUPLICATION): the text-colour resolution in `display_list.rs` (`live_color`,
  ~8564-8647) duplicates the new `getters::get_used_text_color`; fc.rs has its own
  `get_border_info(ctx, node, source)` for collapsed tables.
