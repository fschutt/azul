### 2. Honest codec handles

- `video_codec::encode_engine()` / `decode_engine()` (`pub(crate)`): `Ok(backend)` or `Err(why)` for what THIS
  build can do here. Encode: VideoToolbox only (Apple + `libloading`, framework loadable). Decode: VideoToolbox, or
  Vulkan Video on x86_64 + `video-native`.
- `VideoEncoder::open`: invalid handle unless a live VT H.264 session was created (`EncoderInner::open_h264`);
  H.265 never opens. `VideoDecoder::open`: invalid unless an engine opened (`DecoderInner::open_h264`: Vulkan device
  or VT framework); H.265 never opens. Why is said once per distinct reason (`say_not_open`), replacing the four
  `Once` blocks that announced a lying handle.
- `VideoEncodeCheck::run`: `hw_encode_ready` = build engine AND hardware probe; the summary / detail lead with what
  this build's `VideoEncoder` does (`VideoEncoder in this build: cannot encode (gpu-video ENCODE is not wired yet
  ...)`).
- `PlatformCapability::video_codec`: `available: false`, reason `this build cannot decode H.264: ...` without a
  decode engine (before any hardware probe, so no `ProvisionPlan::detect` on those builds); else the hardware
  probe as before. `VideoStartupCheck` (machine / driver readiness) is unchanged on purpose.
- The VideoWidget stream: the engine check uses `decode_engine()`, and a decoder that did not open is a failed
  status (retryable) instead of waiting for frames that never come.
- AzMeet's `probe_video()` (lib.rs 1627-1680, the encode-a-test-frame probe) can become `VideoEncoder::open(..)
  .is_open()` / `VideoDecoder::open(false).is_open()`; its runtime guards (`EncoderHealth`, `decoder_is_inert`) can
  stay as belt and braces.

### 3. iroh priorities and backlog

- `IrohEndpoint::set_track_priority(track, priority) -> bool`: frames of that track (every peer) open their QUIC
  stream at `priority` (default 0). `IrohEndpoint::set_message_priority(priority) -> bool`: the message stream
  (default 1), applied before every message so it changes an open stream too. False when not bound; the wasm stub
  has both (false). Engine: `Priorities` shared by all peers of an endpoint.
- `IrohPeerStats.messages_queued` / `message_bytes_queued`: messages `send_message` accepted and the sending task
  has not yet written to the peer's message stream (raised before queueing, lowered after the write, or at once if
  the queue is gone). The send task now holds the `Arc<Peer>` (it already ended on `conn.closed()`; the receive
  and frame tasks held it before).
- AzMeet: after `bind`, `endpoint.set_track_priority(AUDIO_TRACK, 2)` puts audio above its H.264 messages; its
  `SendWindow` could read `peer_stats(peer).messages_queued` instead of counting acks.
- Guide: `doc/guide/en/data/networking.md` (priority + backlog bullets).
