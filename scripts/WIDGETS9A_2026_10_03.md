# WIDGETS9A report - IconGrid, Toolbar, TokenInput (wave 9, 2026-10-03)

Branch `wt/widgets9a`, base `e537ddbe2`. Nothing compiled (house rule); every Rust file passed `rustfmt` (parse
check). Specs: `azul-apps/planning/foundation/05-widget-backlog.md` (IconGrid, Toolbar, TokenInput rows),
`scripts/PIMDRIVE7_2026_10_03.md` s8 (TokenInput), DEDUP_WIDGETS_API F30 (Toolbar - this closes it).

All three follow the newest widgets' pattern (ThumbnailStrip / DataTable / Chart): a `XxxLook` of parts, each part
= a BASE (structure and every metric the widget computes with, in the widget file, outside every `@theme` block)
plus a SKIN (paint, appended in `themes/flat.rs` / `themes/flora.rs` under a `// ==== <widget> ====` banner);
`look_for(theme)` merges the two looks part by part (`theme_blocks::follow_props`), so the DOM is built ONCE and
follows the app theme; one `on_event` callback triple; the events carry what the app stores.

## 1. Toolbar - `layout/src/widgets/toolbar.rs`

- Items (`ToolbarItem`, kind `ToolbarItemKind`): `Button`, `Toggle` (pressed), `MenuButton` (a drop-down of
  `choices`), `Separator`, `Spacer` (the items after it go right), `Custom` (an app control - a search field - with a
  declared `width`). Per item: `id` (what its events carry), label, icon, tooltip, `disabled_reason`, `show_label`,
  `never_overflow`.
- Events (`ToolbarEvent { id, index, choice, kind, pressed }`): `Activate`, `Toggle` (`pressed` = the NEW state),
  `Choose` (`choice` of a menu button).
- Each tool IS the `Button` widget with the toolbar's parts as its styles (the ribbon's way): a quiet key (no face
  at rest, the hover face, the pressed face, the focus ring), a toggle that is on stacks the pushed-in part
  (`stack_parts`) and is announced `CheckedTrue` / `CheckedFalse` (the Button's), a disabled tool is the Button's
  (dimmed, inert, unavailable + reason, reason tooltip). Icon-only tools are named by their label (Button `alt`)
  and show it as a tooltip on hover (button.rs's tooltip handlers). Menu buttons and the more button are
  `ButtonMenu` + `Collapsed`.
- OVERFLOW: `with_available_width(px)` (0 = no limit; the app passes it as for the DataTable's viewport). A pure
  `fit()` estimates every item (`item_width`: border + padding 12, icon 20, label chars x 13 px x 0.6, arrow 16, the
  4 px gaps between parts, 2 px after each item - the SAME numbers are the bases, so a skin cannot widen an item)
  and moves items from the END into the menu of a "more" (`more_horiz`) button, never a `never_overflow` item or a
  spacer; a separator left at an end of either list or doubled goes. In the more menu a button is an entry, a
  toggle a check entry (`MenuItemIcon::Checkbox`), a menu button a submenu of its choices, a separator a
  separator, a disabled item a disabled entry. The bar clips (overflow hidden, nowrap) if an estimate is off.
- KEYBOARD (APG toolbar): one Tab stop (roving, `roving.rs`), Left / Right wrap, Home / End, Enter / Space = the
  Button's activation, Down opens a menu button's menu (and the more menu). Custom items keep their own Tab stops.
- Menus open under the tool (`open_menu_for_hit_node`; `open_menu` when the tool has no rect yet).
- Looks: flat = Explorer's command bar (window surface, row-hover blue in the selection-blue hairline, the
  selection blue pressed / checked); flora = the toolbar strip with flora's toolbar keys (`chrome_key`,
  `chrome_key_states` - the ribbon's, reused) and the ribbon's checked key.

## 2. TokenInput - `layout/src/widgets/token_input.rs`

- App-owned `TokenInputState { tokens: StringVec, text, active: OptionUsize }`; every `TokenInputEvent { state,
  token, message, index, kind }` carries the NEXT state (computed from the state the DOM was built from); kinds
  `Add` (`token` = last added, `index` = first added), `Remove`, `Text`, `Navigate`, `Refuse` (`message`), `Open`
  (a click on a chip's label).
- Chips are the `Chip` widget (removable; label opens), taken out of the Tab order (label and "x"
  `NoKeyboardFocus`): the field is ONE Tab stop, the entry. The entry is the `TextInput` widget (its default style
  + no border / transparent / grows, + the look's focus ring), wired through its `on_text_input` and
  `on_virtual_key_down` hooks.
- Commit: `,` `;` tab newline typed commit what is before them (`split_tokens`); a PASTE containing a separator
  commits every part (the inserted text is longer than one character); Enter commits the highlighted suggestion or
  the text; Tab commits the text (and leaves an empty entry). The separator never reaches the line (the hook vetoes
  the insertion and sets the line with `TextInput::set_text_in`).
- Remove: Backspace in an empty entry removes the last chip; a chip's "x"; Delete / Backspace on a focused chip.
  Left in an empty entry goes to the last chip; Left / Right walk the chips, Right past the last returns to the
  entry.
- Tokens are trimmed and added once (case folded) unless `with_allow_duplicates(true)`.
- Validation: optional `on_validate(token) -> TokenInputVerdict` (accept - optionally normalised, "Bob <bob@x>" ->
  "bob@x" - or refuse with a reason). A refused part stays typed (before what follows it) and `Refuse` reports
  why; the accepted parts of the same paste are still added. No validator: every token taken as typed (also what
  a host that does not answer gets - `HostOut::unwritten`).
- Suggestions: the app's candidates (`with_suggestions`), shown when text is typed: those STARTING with it first,
  then those containing it, never a token already there, at most `max_suggestions` (8). Floating under the field
  (absolute, top 100%, z-index 10), role List; Down / Up move the highlight (wrapping; `Navigate`), the highlighted
  option is marked + announced `Selected`, Escape hides the list until the next character, a click on an option
  adds it and gives the entry the focus.
- Looks: flat = a flat text field (field paper, the control background at night - the entry's own night fill),
  the list on the page colour with a soft shadow; flora = a flora field (field paper / the surface at night), the
  list a floating leaf (`chrome_leaf`, reused).

## 3. IconGrid - `layout/src/widgets/icon_grid.rs`

- GENERIC OVER ITS DATA: `with_data_source(data, fn(RefAny, usize) -> IconGridItem)` (the DataTable's data-callback
  shape, managed-callback Form 4); `count` items; only the items IN VIEW are asked for and built (test: 100 items,
  12 asked). `IconGridItem { label, name (a11y), icon (glyph), badge (glyph), image: OptionImageRef }`: ASYNC
  THUMBNAILS = the app answers the glyph until its thumbnail thread has the picture, then rebuilds and answers the
  image (fills the `icon_size` box).
- VIRTUALISED IN WHOLE ROWS (the DataTable's scroll window): `with_viewport(w, h)`, `with_cell_size(w, h, icon)`
  (96 x 104, 48); columns = whole cells across (the 12 px scroll bar - the DataTable's `ScrollBar` / `thumb()`,
  reused - when the rows overflow); `IconGridView::top_row` moves by the wheel (`cell_grid::take_wheel`), the keys,
  the track (a page) and the thumb (drag); a million items need no pixel extent.
- App-owned `IconGridView { selection: ListSelection (keys = item indices), drag: IconGridDrag, top_row }`; every
  `IconGridEvent { view, index: OptionUsize, x, y, kind, shift, ctrl }` carries the next view (also stored in the
  handlers' payload, so a second event before the rebuild starts from it); kinds `Select`, `Scroll`, `Activate`,
  `ContextMenu` (x / y in the grid; the app opens its menu), `DragStart`, `Drag`.
- POINTER (Explorer): a click selects (Ctrl / Cmd toggles, Shift extends - `ListSelection::select`); a press on an
  already selected item keeps the selection (`Pending`) and the release collapses it - so the whole selection can be
  dragged out; a press on empty space clears (Ctrl / Shift keep) and starts a RUBBER BAND (pointer capture) that
  selects the cells it crosses (`marquee_keys`), added to the kept selection; double-click = `Activate`; right click
  = `ContextMenu` (the item joins the selection first; empty space clears).
- DRAG OUT: every item is `draggable`; `DragStart` puts the selected indices on the drag (MIME
  `application/x-azul-icon-grid`, "1,3"; an unselected item is selected first) and reports `DragStart` - the app
  adds its own payload (paths) with `CallbackInfo::set_drag_data` in its handler.
- KEYBOARD (one Tab stop - the grid node): arrows by an item / a row (Shift extends, Ctrl / Cmd moves the focus
  alone), Page Up / Down by a screen, Home / End, the focused row revealed by `top_row`; Ctrl+A, Ctrl+Space, Enter =
  `Activate`, Menu key / Shift+F10 = `ContextMenu`, Escape clears.
- A11y: the grid is a `List`, `Multiselectable`, its value "N of M selected"; items `ListItem` named by `name` /
  label, `Selected`.
- Looks: flat = Explorer's large-icons view (steel-blue glyphs, row-hover blue, the selection blue in the checked
  hairline, the fields' ring around the focused item); flora = field paper, the accent's soft wash; the rubber band
  is each theme's selection-adorner marquee (reused); the grid rings itself inside on focus.

## 6. api.json list (for `azul-doc autofix add`; never edited here)

Module choice follows the Chart / Timeline precedent: types in `widgets`, `XxxCallbackType` in `callbacks`, the
`XxxCallback` wrapper in `dom`, vecs in `vec`, options in `option`. External paths
`azul_layout::widgets::<toolbar | token_input | icon_grid>::<Name>`. Every callback triple is shaped exactly like
`ThumbnailStripOnEvent`'s (copy its three entries and its managed statics): `XxxCallbackType` (callback_typedef),
`XxxCallback { cb, callable }` (dom), `Xxx { refany: RefAny, callback: XxxCallback }` (widgets), `OptionXxx`; the
statics `AzApp_setXxxCallbackInvoker`, `AzXxxCallback_createFromHostHandle`, `..._createFromHostHandleByref`.
Setters taking a callback are `(data: RefAny, callback: XxxCallbackType)` with fn_body
`object.with_xxx(data, callback)` (as ThumbnailStrip's `with_on_event`). Setters `self: refmut`, builders
`self: value -> Self`. Docs ASCII.
