## What existed (LIFECYCLE, 2026-10-01) and what was missing
The guard was mostly built: `doc/src/codegen/v2/abi_guard.rs` hashes the ABI of api.json (FNV-1a 64 over a sorted,
doc-free text), libazul exports `AzAbi_getHash` (the prebuilt `libazul.dylib` has `_AzAbi_getHash`), all 21
prebuilt apps import it, azul.h checks at load (GCC / Clang constructor, C++ static object). Python cannot
mismatch: the extension IS libazul (`python-extension` = `build-dll` + `link-static`, one crate, one codegen run).

Gaps the audit found:
1. Rust: three kinds of wrapper that take no `self` - so any can be a program's FIRST call - entered libazul
   unchecked: `X::create_default()` (742), `impl Default for X` -> `AzX_createDefault()` (740), and the enum-variant
   constructors (`BorderStyle::none()`, `OptionX::some(..)`, ~5300). Only constructors / static methods checked.
2. Rust: no load-time check (C had one) - a method on a struct-literal value ran unchecked.
3. MSVC compiling C (cl.exe, the C compiler of Windows): no load-time check at all.
4. No test of a real binding against a libazul with another hash (only `az_abi_check_hash` in-process).
5. Found on the way: `azul17.hpp` (every C++ header) did not compile: azul.h's variant-checker MACRO
   `AzChartKind_isBar(value)` shadowed api.json's function `AzChartKind_isBar` (`ChartKind.isBar`).

## What was built
- `abi_guard::is_first_call_kind` (Constructor, StaticMethod, Default, EnumVariantConstructor) drives
  `rust_wrapper_checks`; the ExternalBindings `impl Default` body checks too (lang_rust.rs
  `generate_abi_derived_trait_impls`). Only `dll_api_external.rs` / `azul.rs` change; libazul never checks.
- `abi_guard::rust_load_time_check`: every ExternalBindings output gets
  `#[used] static AZ_ABI_CHECK_AT_LOAD: extern "C" fn() = az_abi_check_at_load;` in the loader's initializer
  section (`__DATA,__mod_init_func,mod_init_funcs` on Apple, `.init_array` on Linux / Android / BSDs / illumos,
  `.CRT$XCU` on Windows). The loader runs `az_abi_check()` before `main`; `az_abi_check_slow` reads the static
  (`read_volatile`), so wherever a wrapper is linked the entry is linked too. Per-wrapper checks stay as the
  fallback. Verified with rustc 1.91 on macOS arm64: rlib dependency, 16 CGUs, `-O` and fat LTO - the check runs
  before `main`, even when `main` uses nothing from the rlib (rustc's synthetic symbols object keeps `#[used]`).
- azul.h: a last `#elif defined(_MSC_VER)` arm (after GCC/Clang and C++): `#pragma section(".CRT$XCU", read)`, a
  `__declspec(selectany) __declspec(allocate(".CRT$XCU"))` entry (one per program, though every TU defines it -
  the way guiddef.h's DEFINE_GUID uses selectany in C) and `#pragma comment(linker, "/include:...")` (with the
  `_` 32-bit x86 C names carry) so /OPT:REF and /GL keep it.
- lang_c.rs `generate_enum_variant_checkers`: no checker macro whose name is an api.json function (the
  declared function wins). Removes exactly one macro today (`AzChartKind_isBar`).
- `scripts/abi_guard_e2e.py`: end-to-end tests, PASS / FAIL per test:
  `c_aborts_before_main_on_another_abi` / `c_runs_against_its_own_abi` (main.c + azul.h + a stub
  `AzAbi_getHash`), `cpp_aborts_before_main_on_another_abi` (azul17.hpp by default, `--cpp-header`),
  `rust_app_aborts_on_a_libazul_with_another_abi` (copies the prebuilt libazul, patches `AzAbi_getHash` to return
  0xdead - Mach-O thin/fat or ELF, arm64 or x86_64, BTI/ENDBR pads skipped - re-signs ad hoc on macOS, starts a
  prebuilt app against it) and `rust_app_starts_on_its_own_libazul` (control). The stale-app case of 2026-09-30,
  reproduced without a build.
- CI: `c_compile_check` runs `abi_guard_e2e.py --only c,cpp` on Linux and macOS; its Windows hello-world steps
  (cl.exe and clang-cl) compile and link the new MSVC arm on every run.

Seen today (prebuilt binaries, this base): `--only c` 2/2 PASS; `--only rust` 2/2 PASS - AzCalculator against
the patched libazul aborts (exit 134) with `azul: ABI mismatch - this app was built against the azul ABI

  static constructor is not emitted - no check. Plan: one helper in abi_guard.rs that gives each emitter the hash
  literal and the message format; each emitter calls `AzAbi_getHash()` right after it loads the library.

- Duplicates noticed: none. `abi_guard_e2e.py` reuses `run_capped.sh`; the C++ SDK-header fallback is local to
  the script (this Mac's Command Line Tools ship an incomplete `usr/include/c++/v1`; Xcode-based CI is not
