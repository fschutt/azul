### 3.1 macOS: a letter pressed with Cmd stays held
- RED c5bbd8b16, GREEN 4185ed217 (dll/src/desktop/shell2/macos/events.rs).
- Root cause: NSApplication does not forward a `keyUp:` with Cmd held to the key window; `handle_flags_changed`
  only updated the modifier, so the letter stayed in `pressed_virtual_keycodes` until pressed again.
- Fix: the keyboard-state half of the handlers is a free fn (`update_keyboard_state_of`, the old method body
  unchanged); `flagsChanged:` goes through `flags_changed_keyboard_state`, which on the LAST Cmd key's release
  drops every pressed key `flagsChanged:` does not report (`FLAGS_CHANGED_KEYCODES`: modifiers + Caps Lock) and
  re-syncs the modifiers, in the same pass. Works with both run loops, no ObjC (the GLFW local-monitor
  alternative needs a block-based NSEvent monitor). mod.rs needed no change.
- RED tests (macos/events.rs `keyboard_state_tests`, macOS only):
  `a_letter_pressed_with_cmd_is_released_when_cmd_comes_up`,
  `a_letter_stays_down_while_the_other_cmd_key_is_held_and_shift_stays_down`.
- Verify ON THIS MAC: an app with no Cmd+B menu item, press Cmd+B, release B then Cmd, then hold B - one
  key-down, auto-repeat as normal, nothing "held" left over (a game-style `is_key_down(B)` reads false after).

### 3.4 `http_get` / `download_bytes` block the calling callback
- RED 156ae0192, GREEN 4fd4c5af6 (layout/src/http.rs).
- `resume_without_blocking` is the one path of all five resumable requests (`http_get`, `http_request`,
  `http_post`, `download_bytes`, `is_url_reachable`): the e2e mock store's answer for the URL is queued at once
  (`request::complete`, deterministic scripted runs); otherwise, with a transport (http feature, not wasm32), an
  `azul-http` thread runs the transfer and the request is `request::defer`-red with a poll of the thread's
  channel (the dialogs.rs mobile-picker template; the shells keep pumping while `request::has_work()`); a thread
  that cannot start or dies resumes with an error. No transport: inline as before. The per-URL mock decides,
  not `mock::is_armed()`: a bare headless launch is armed but sends unmocked HTTP for real.
  `mocked_reachable` replaces two copies of the mock-to-(reachable, error) mapping.
- RED test `http_get_from_a_callback_returns_before_the_response_arrives` (client_pool_tests: a local server
  holds its answer; http_get must return in < 1 s, the answer then arrives through the queue). The existing
  `resumable_requests_park_their_result_in_the_queue` expected a synchronous completion; it now polls the queue
  for its own request id.
- Risk (tests only): the request queue is PROCESS-WIDE and `take_completed()` drains everything; tests that
  drain it in parallel (http.rs, desktop/dialogs.rs) can take each other's entries. Before this change the
  window was a few instructions; now it is the transfer's duration (local, milliseconds). See round-2 note.
- Verify: AzMail's remote pictures / AzNews' refresh no longer freeze the window while loading.
