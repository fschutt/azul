## 1. What was built

### The mail window (Outlook 2010), `examples/azul-mail/src/ui_main.rs`

Everything is the toolkit's widgets, no hand-built chrome: `PimShell` (an `OfficeShell`) in a
`ShellThemeScope` (Blue), the app-drawn `Titlebar` (`WindowDecorations::NoTitle`), `Ribbon` +
`Backstage`, `ShellNavigationPane` with `TreeView`s, `MessageList`, `ReadingPane`, `InfoBar`,
`ToDoBar`, `ModuleSwitcher`, `StatusBar` with `StatusBarSync`.

- Ribbon: File (backstage) / Home (New: New E-mail; Delete; Respond: Reply, Reply All, Forward;
  Quick Steps: Done, Team E-mail, Reply & Delete; Move: Move, Rules; Tags: Unread/Read, Follow Up;
  Find: Unread Mail; Send/Receive) / Send / Receive (Send/Receive All Folders, Cancel All) /
  Folder (Mark All as Read, Update Folder) / View (Reverse Sort, Navigation Pane, Reading Pane,
  To-Do Bar, Plain Text, theme flat/flora, mode light/dark).
- Backstage: Info (accounts, Add Account, Account Settings, the AzMail folder), Add Account (the
  wizard), Account Settings, About (version, folder, keyboard shortcuts), Exit.
- Navigation pane: Favorites (Inbox / Sent Items / Drafts of the current account) and one group
  per account with its folder tree in Outlook order and names ("Sent Items", "Deleted Items",
  "Junk E-mail"), each with its unread count as a `TreeViewNode` badge (new widget field, below);
  module switcher Mail / Calendar / Contacts / Tasks (the last three show a `ShellEmptyState`).
- Message list: search, scope All / Unread, "Arrange by: Date" with direction, rows grouped
  Today / Yesterday / weekdays / Last Week / Two Weeks Ago / Three Weeks Ago / Last Month / Older,
  icon / from (or "To: ..." in Sent and Drafts) / subject / date / flag; a window of 200 rows
  moved by the list's scroll event. Opening marks read (local `mail/<folder>/flags.json`, written
  on the IO thread); the flag toggles locally too.
- Reading pane: subject, sender, To / Cc / Sent, the info bar "Click here to download pictures.
  ..." with a "Download pictures" action, the body: the HTML part through MAILVIEW's sanitizer on
  white paper (pictures off), or the plain text; "download pictures" re-sanitizes with web images
  kept, downloads each (`HttpRequestConfig::download_bytes`), decodes (`RawImage::decode_image_bytes`)
  and registers it under its URL (`CallbackInfo::add_image_to_cache`) - which needed the engine fix
  E-IMG below.
- To-Do bar: the month calendar (today marked), "no upcoming appointments", tasks of this run
  (type + Enter adds, a click completes).
- Status bar: item counts, unread count, the Send / Receive progress (`StatusBarSync`), the last
  notice.
- Keys: Ctrl+N New, Ctrl+R Reply, Ctrl+Shift+R Reply All, Ctrl+F Forward, F9 Send/Receive, Esc
  closes the backstage.
- Delete / Move / Rules show a notice: AzMail's sync is read-only (MAIL1's design); deleting and
  moving come with two-way sync (left, section 7).

### Accounts, `ui_account.rs`

File > Add Account is a `WizardLayout` with four steps (Your account: name, e-mail, password /
Incoming mail: IMAP host, port, "Unencrypted connection (only for a test server on this
computer)", user name, folder / Sending: "Directly to the receivers' mail servers" or "Through an
SMTP server" with host, port, "Use STARTTLS when the server offers it" / Finish), each step checked
before Next. Account Settings is a `ShellSettingsLayout` page over the same editor (sections
Account, Incoming, Sending) with Save. Finish / Save write `account.json` (no secret) and SEND's
`sending.json` next to it on the IO thread, store the password in the OS keyring
(`CallbackInfo` keyring API; a headless run uses azul's memory keyring, or `AZMAIL_TEST_PASSWORD`),
and start the first Send / Receive. Secrets never reach a file or stdout (the E2E checks).

### Send / Receive, `lib.rs`

One azul `Thread` per run: MAIL1's IMAP sync of every folder, then `send::retry_outbox` for the
account (SEND's queue); progress messages drive the status bar; `AZMAIL_SYNC_DONE` /
`AZMAIL_SYNC_FAILED` lines for scripts. File writes (account, flags) go through one IO thread
(`IoJob::{SaveAccount, SaveFlags}`), never from a callback.

### The compose window, `ui_compose.rs` + `editor.rs` + `compose.rs`

New E-mail / Reply / Reply All / Forward / opening a draft open a SECOND WINDOW
(`CallbackInfo::create_window`, window id `azmail-compose-<n>`, the window's layout callback finds
its compose state through `LayoutCallback.ctx` / `LayoutCallbackInfo::get_ctx()`), titled like
Outlook ("RE: ... - Message (HTML)"), on `DocumentShell`:

- ribbon Message: Basic Text (Bold, Italic, Underline, Bullets, Numbering, Link), Include (Attach
  File - `FileDialog::open_multiple_files`), Save (Save Draft), Discard;
- the header: a big Send button beside From (the account's sender line) / To / Cc / Bcc / Subject;
- the link bar (#compose-link), the attachments row (name, size, remove);
- the body: a contenteditable host on azul's Path 2 - the app's model is a `MailDoc` (paragraphs,
  quotes nested to any depth, bullet and numbered items, runs with bold / italic / underline /
  link) mirrored as the host's `Dom`; typed text comes back through `get_unsynced_text_edits`,
  Enter / Backspace / paste through `DocumentChangeset::apply_to_dom`; Bold / Italic / Underline
  at a caret are the engine's typing style (`toggle_text_format`), on a selection a `WrapRange`
  changeset; lists and links rewrite the model. Reply / Reply All put the caret at the top above
  "On <date>, <sender> wrote:" and the quote; Forward puts the "Original Message" block.
- Send (button or Ctrl+Enter): `compose::outgoing` checks the fields (at least one valid receiver,
  every address valid) and builds SEND's `OutgoingMail` (text/plain with "> " quotes and the HTML
  part with nested `<blockquote type="cite">`, In-Reply-To / References of the original,
  attachments); an azul `Thread` calls `send::send_mail(<AzMail folder>, <account id>,
  SendSettings::load(..), &mail)`. Sent closes the window and refreshes every window (the mail is
  in Sent Items); Queued / Failed show in the window's status line and keep it open.
- Save Draft (button or Ctrl+S): the draft as an `.eml` ("Bcc:" and "X-AzMail-Draft: 1" on top of
  SEND's `build_message`), filed by SEND's `file_message` into `mail/drafts/` (\Seen \Draft),
  replacing the previous save of the same draft; opening a draft from Drafts resumes it.
- Closing an edited window asks nothing yet: it closes (left, section 7).

### `--sample`, `args.rs`, `sample.rs`

`--screen mail|backstage|add-account|settings|compose|reply --theme flat|flora --mode light|dark
--sample --size WxH` (like AzWriter's). `--sample` installs "Ada Lovelace <ada@example.org>" with
the sample mail filed as if synced and SEND settings SMTP localhost:2525, STARTTLS off; without an
account the window opens on the Add Account wizard.

### Engine (RED first, each in its own pair of commits)

- **TreeView badge** (`layout/src/widgets/tree_view.rs`, both theme files): `TreeViewNode.badge`
  drawn after the label in the accent (selected row: the selection's ink); empty = no node.
- **E-IMG** (`core/src/resources.rs`, `layout/src/overlay.rs`, `layout/src/solver3/mod.rs`,
  `layout/src/window.rs`): an `<img src>` from markup (XML / HTML) became a NullImage tagged with
  its src and never resolved; now layout resolves it against the image the app cached under that
  src (`ImageRef::source_tag`, `ResolvedContent.image_cache`). Test
  `layout/tests/an_img_from_markup_shows_the_image_the_app_cached_under_its_src.rs`.
- **Headless child windows** (`dll/src/desktop/shell2/headless/mod.rs`): a window opened from a
  callback was created but never laid out, pumped or given timers. The pump body became
  `HeadlessWindow::pump_once(is_root)`; children live in `children`, are pumped after the root
  (`pump_children`), and closing one drops it.
- **RefreshDomAllWindows from a timer or a thread** (`common/event.rs` + headless): only the
  calling window rebuilt; now `process_timers_and_threads` asks the platform to regenerate every
  window (headless: a shared generation counter all windows watch).
- **The debug server reaches every window** (`layout/src/e2e/full.rs`): requests carry an
  optional `window_id`; a registry of windows routes a request to its window's debug timer
  (a mailbox per window), unknown ids are refused, no id = the first window.
- **Windows created at runtime get the debug timer** (`debug_server/platform.rs`, `stub.rs`,
  `run.rs`: macOS x2, Windows, X11, Wayland, headless).
