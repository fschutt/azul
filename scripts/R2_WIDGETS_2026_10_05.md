## Items

**W1 DatePicker today ring / lit wash hid the focus halo / hover face.**
Root cause: `ringed` / `washed` APPENDED the resting mark (today's ring = a resting shadow in the focus
halo's slot; the wash = a resting background) after the face's `:focus` / `:hover` declarations; a resting
declaration matches in every state, so it won there too. Fix: `marked(face, mark)` moved from
date_range_picker.rs into date_picker.rs as `pub(crate)` (the one rule for both pickers): `stack_parts(face,
mark)` then the face's state declarations again. `ringed` / `washed` (build and the click repaint) call it;
`date_range_picker::day_face` imports it.
RED: `inline_and_today_tests::a_focused_today_in_the_date_picker_shows_its_focus_halo_over_its_ring`
(plain and inside a lit range, flat + flora, light + dark: `shadowed_states` empty and `has_focus_ring`),
`range_tests::a_lit_day_in_the_date_picker_keeps_its_hover_face_over_the_wash`.
Verify: both tests, and the existing date_picker / date_range_picker suites (the repaint path now also uses
`stack_parts` instead of a plain append).

**W2 dom_lint reported text beside an absolutely positioned sibling.**
Root cause: the block-sibling loop asked only `is_block_level(display_of(..))`; an out-of-flow box has a
block display. Fix: `is_out_of_flow` (`solver3::positioning::get_position_type`, Absolute | Fixed) skips it.
Floats still count (pinned in the same test).
RED: `dom_lint::autotest_generated::text_next_to_an_absolutely_positioned_sibling_is_not_reported`.
Verify: that test + `every_widget_dom_is_warning_free`.
Note (not changed, outside the brief): the flex / grid branch still counts an absolutely positioned child
as a competing flex item (`child_count`), which CSS does not; same root cause, a one-line follow-up.

**W3 DEDUP class lists.** gauge.rs `class_list` (6 callers) and date_range_picker.rs `one_class` (5) are
gone; the callers use `themes::decl::classes(&[..])`. No RED (same class lists).

**W4 DEDUP VirtualKeyCode -> character.** terminal_view.rs `us_char` is `pub(crate)`; icon_grid.rs
`typed_letter(key) = us_char(key, false).filter(u8::is_ascii_alphanumeric).map(char::from)` (the same
'0'..'9' / 'a'..'z'). No RED (the type-ahead and terminal tests).

**W5 DEDUP cell_grid `typed()`.** data_table.rs `insert_at` is `pub(crate)`; cell_grid's `typed` calls it.
No RED.

**W6 IconGrid items carry no DOM id.**
Root cause: `build` put the grid's id on the grid node only. Fix: when `grid.id` is not empty, every item's
id list gets `<grid id>-<index>` (the item's index, not its place in view). No api change.
RED: `icon_grid_tests::an_icon_grid_item_carries_its_grids_id_and_its_index_as_its_dom_id` (scrolled one row
down; a grid with an empty id names no item). Note: the DEFAULT grid id is "icon-grid", so items of a
grid built without `with_id` are now `#icon-grid-0..`.

state showed its reason only to the pointer.
- button.rs (`mark_disabled`): also FocusReceived -> `show_disabled_reason_on_focus` (the tooltip under the

- dialog_kit.rs: `row_button(label, kind, RowAction, theme, box_class, base, skin)`;

RED: `button::disabled_and_toggled_tests::a_disabled_button_shows_its_reason_on_keyboard_focus_too`;
