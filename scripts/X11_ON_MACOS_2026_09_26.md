## Build and run

```bash
open -a XQuartz            # DISPLAY exported by launchd; DISPLAY=:0 also works
cargo build --release -p azul-dll --features build-dll,x11-macos
AZ_LINK_PATH=... cargo build --release -p AzWidgets
AZ_BACKEND=x11 ./target/release/AzWidgets     # AZ_WINDOW=x11 is equivalent
./scripts/cgevent_input.py windows $(pgrep -x X11.bin)   # windows belong to XQuartz
echo "Xft.dpi: 96" | xrdb -merge                          # pin the scale
```
No auto-detection (XQuartz exports DISPLAY to every process). A build
without the feature prints a warning and opens AppKit windows.

## Check first when compiling

1. kqueue code in timer.rs (`libc::kevent` literal + constants; checked against libc 0.2.189 source only).
2. The whole shell2/linux tree (~15k lines) building on macOS for the first time, incl. `#![cfg_attr(not(target_os="linux"), allow(unreachable_patterns, irrefutable_let_patterns))]` in x11/mod.rs.
3. `#[cfg(az_x11)] { ... return run_linux_windows(...) }` inside a match arm in run.rs.
4. Linux build of the `Option<Rc<Egl>>` / `Option<Rc<Xkb>>` changes, compose sequencer construction, `GlFunctions::initialize(&gl_context.egl)`.
5. clipboard_xquartz.rs (rich-clipboard API).

## Will not work on XQuartz

CPU rendering only (no libEGL); PRIMARY selection stays in-app; no GNOME
global menu / portal theme switch / screensaver inhibit / tray / AT-SPI;
macOS system style detected once at startup; probably no touch/pen/smooth
scroll, per-seat keymaps, Finder drag-and-drop, macOS input methods;
eyedropper likely captures black (rootless root window); quartz-wm EWMH
partial; scale may round to 1.25x without Xft.dpi; `cgevent_input.py type`
only reaches XQuartz for characters mapped to a physical key (use `key`).
Unverified: libX11 input method opens, RandR 1.3, 32-bit visuals.
